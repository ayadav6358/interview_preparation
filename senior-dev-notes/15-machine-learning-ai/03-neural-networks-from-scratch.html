    Neural Networks from Scratch

    ⏱ ~3.5 hrs📍 Chapter 3 of 14

    One-line summary: A neural network is a stack of matrix multiplies and nonlinearities trained by backpropagation — a mechanical, fully-derivable application of the chain rule — and once you've implemented one from scratch in raw numpy, PyTorch's autograd (chapter 4) stops looking like magic and starts looking like exactly the thing it automates.

    On this page

      Why It Matters for a Senior Developer

      This is the chapter that separates "I've used PyTorch" from "I understand what PyTorch is doing for me." Interviewers love asking you to derive backprop for a tiny network on a whiteboard precisely because it's impossible to fake — either you understand the chain rule mechanics or you don't, and no amount of framework familiarity substitutes for it. Beyond interviews, this understanding is what lets you debug a model that won't train (vanishing gradients, dead ReLUs, exploding loss), choose activation functions and optimizers with actual reasoning instead of cargo-culting defaults, and read research papers without getting lost at the first equation.

      Why

      Every neural network, no matter how large or sophisticated (a transformer is, underneath, still matrix multiplies, nonlinearities, and backprop), reduces to the same forward-pass/loss/backward-pass/update loop. If you can derive and implement that loop for a 2-layer network by hand, you have, in a real sense, already understood the mechanical core of every deep learning system you'll ever work with — everything else is architecture and scale on top of this exact loop.

      Prerequisites

      Requires ML Math & Foundations (chapter 1) — specifically dot products, the chain rule, and softmax/cross-entropy. Directly sets up PyTorch & Tensors (chapter 4), where autograd automates exactly the backward pass derived here by hand.

      Core Concepts

      The perceptron and activation functions

      A single artificial neuron (perceptron) computes z = w · x + b (a weighted sum plus bias, chapter 1's dot product) and then applies a nonlinear activation function to z. Without a nonlinearity, stacking layers would be pointless — a composition of purely linear functions is still just one linear function, so a "deep" network with no nonlinearities couldn't learn anything a single linear layer couldn't. Activation functions are what let networks approximate arbitrarily complex, non-linear decision boundaries.

      • Sigmoid (1/(1+e^-z)) squashes to (0,1), historically popular for its probability-like interpretation, but suffers badly from vanishing gradients: its derivative is near-zero for large positive or negative z, so in deep networks the gradient signal shrinks to near-nothing by the time it backprops through many sigmoid layers.
      • ReLU (max(0, z)) — the modern default — has a constant gradient of 1 for any positive input (no vanishing gradient in the active region), is trivially cheap to compute, and empirically trains deep networks far more reliably. Its downside ("dead ReLU": a neuron stuck outputting 0 forever if its weights land in the always-negative region, since the gradient there is exactly 0) is why ReLU "won" the activation function debate despite being, mathematically, a much cruder function than sigmoid.
      • Softmax (chapter 1) is used only at a classification network's output layer, to convert raw logits into a probability distribution across classes.

      Forward pass mechanics and loss functions

      The forward pass is simply: input → (matmul + bias + activation) per layer → final output. For a 2-layer network: h = ReLU(W1 · x + b1), then ŷ = softmax(W2 · h + b2). Every intermediate value (z1, h, z2, ŷ) must be cached during the forward pass, because backprop needs them to compute gradients — this is the single most important implementation detail and the source of most from-scratch bugs.

      The loss function quantifies how wrong ŷ is relative to the true label y. Mean squared error (MSE = mean((ŷ-y)²)) is standard for regression. Cross-entropy (chapter 1) is standard for classification, and crucially, when paired with a softmax output layer, its gradient with respect to the pre-softmax logits simplifies beautifully to ŷ - y (predicted probabilities minus one-hot true label) — this simplification is why softmax+cross-entropy is the near-universal default pairing for classifiers, not an arbitrary convention.

      Backpropagation, derived step by step

      Backprop computes ∂Loss/∂w for every weight by applying the chain rule backward through the cached forward-pass values. For the 2-layer network above, worked through explicitly:

      1. dz2 = ŷ - y (the softmax+cross-entropy simplification above — this is the gradient of loss w.r.t. the output layer's pre-activation logits).
      2. dW2 = h.T @ dz2 and db2 = sum(dz2) (gradient of loss w.r.t. layer 2's weights/bias — this is just the chain rule: how layer 2's pre-activation changes with its own weights, times how much the loss changes with that pre-activation).
      3. dh = dz2 @ W2.T (propagate the gradient signal backward through layer 2's weights to find how the loss depends on the hidden activation h).
      4. dz1 = dh * ReLU'(z1) (apply the chain rule through the ReLU: its derivative is 1 where z1 > 0 and 0 otherwise — this is literally a mask multiply, which is why ReLU's backward pass is so cheap).
      5. dW1 = x.T @ dz1 and db1 = sum(dz1) (gradient w.r.t. layer 1's weights/bias, same pattern as step 2).

      Notice the pattern: every step reuses a value computed in the step before it (dz2 feeds into dh, which feeds into dz1) — this reuse, flowing backward, is precisely what makes backprop cost roughly one extra forward-pass-equivalent of computation, rather than scaling with the number of weights.

      Gradient descent variants: SGD, momentum, Adam

      Plain SGD updates each weight by its current gradient scaled by the learning rate, per batch. Momentum adds a running "velocity" (an exponential moving average of past gradients) to the update, so the optimizer keeps moving through small bumps/noise in the loss surface instead of reacting only to the instantaneous gradient — intuitively, like a ball rolling downhill that keeps some of its speed rather than stopping and re-aiming at every step. Adam (the modern default for most deep learning) combines momentum with a per-parameter adaptive learning rate, dividing each parameter's update by a running estimate of that parameter's gradient magnitude — parameters that have historically had large, volatile gradients get smaller effective steps, and parameters with small, stable gradients get relatively larger steps. This adaptivity is why Adam typically converges faster and more robustly than plain SGD with little tuning, at the cost of slightly more memory (it tracks two moving averages per parameter) and, in some cases, worse final generalization than well-tuned SGD+momentum on certain tasks.

      How It Works Under the Hood

      One full training step on a batch, tying every concept above together:

      1. Forward pass: compute and cache z1, h, z2, ŷ.
      2. Compute scalar loss from ŷ and true labels y.
      3. Backward pass: compute dz2, dW2, db2, dh, dz1, dW1, db1 in that exact order, each reusing the previous step's result (the chain rule in action).
      4. Optimizer step: update every weight/bias using its gradient and the chosen rule (plain SGD, momentum, or Adam).
      5. Zero out gradients (conceptually — in a from-scratch implementation this is implicit since you recompute fresh each step; in PyTorch, chapter 4, this is an explicit .zero_grad() call and forgetting it is a classic bug).

      Diagrams

      flowchart RL LOSS[Loss] --> DZ2[dz2 = y_hat - y] DZ2 --> DW2[dW2 = h^T @ dz2] DZ2 --> DH[dh = dz2 @ W2^T] DH --> DZ1[dz1 = dh * ReLU'z1] DZ1 --> DW1[dW1 = x^T @ dz1] DW2 --> UPDATE[Optimizer step] DW1 --> UPDATE

      Code Examples

      import numpy as np

np.random.seed(0)

# --- Toy dataset: XOR-like pattern, not linearly separable (requires a hidden layer) ---
X = np.array([[0,0],[0,1],[1,0],[1,1]], dtype=float)
Y_labels = np.array([0, 1, 1, 0])  # XOR
Y = np.eye(2)[Y_labels]             # one-hot: shape [4, 2]

# --- Initialize a tiny 2-layer network: 2 inputs -> 4 hidden -> 2 outputs ---
input_dim, hidden_dim, output_dim = 2, 4, 2
W1 = np.random.randn(input_dim, hidden_dim) * 0.5
b1 = np.zeros(hidden_dim)
W2 = np.random.randn(hidden_dim, output_dim) * 0.5
b2 = np.zeros(output_dim)

def relu(z): return np.maximum(0, z)
def relu_deriv(z): return (z > 0).astype(float)

def softmax(z):
    e = np.exp(z - z.max(axis=1, keepdims=True))
    return e / e.sum(axis=1, keepdims=True)

def cross_entropy(y_hat, y_true):
    return -np.mean(np.sum(y_true * np.log(y_hat + 1e-12), axis=1))

lr = 0.5
for epoch in range(2000):
    # --- Forward pass (cache everything backprop will need) ---
    z1 = X @ W1 + b1          # [4, 4]
    h = relu(z1)               # [4, 4]
    z2 = h @ W2 + b2           # [4, 2]
    y_hat = softmax(z2)        # [4, 2]

    loss = cross_entropy(y_hat, Y)

    # --- Backward pass: chain rule, step by step, exactly as derived above ---
    dz2 = (y_hat - Y) / X.shape[0]      # softmax+cross-entropy simplification
    dW2 = h.T @ dz2
    db2 = dz2.sum(axis=0)

    dh = dz2 @ W2.T
    dz1 = dh * relu_deriv(z1)
    dW1 = X.T @ dz1
    db1 = dz1.sum(axis=0)

    # --- Plain SGD update ---
    W1 -= lr * dW1; b1 -= lr * db1
    W2 -= lr * dW2; b2 -= lr * db2

    if epoch % 400 == 0:
        print(f"epoch {epoch:4d}  loss {loss:.4f}")

# --- Check it actually learned XOR ---
final_preds = softmax(relu(X @ W1 + b1) @ W2 + b2)
print("\nFinal predictions (rows = [0,0],[0,1],[1,0],[1,1]):")
print(np.round(final_preds, 2))
print("Predicted classes:", final_preds.argmax(axis=1), "  True:", Y_labels)

# --- BAD: no activation function between layers ---
# Stacking two linear layers with no nonlinearity collapses to one linear layer —
# this network could never learn XOR, no matter how long you train it.
def bad_forward_no_activation(X, W1, b1, W2, b2):
    z1 = X @ W1 + b1   # no relu() here
    z2 = z1 @ W2 + b2  # mathematically equivalent to X @ (W1@W2) + (b1@W2+b2) — still linear!
    return z2

      Real-World Production Scenario at Scale

      At scale

      A team training a mid-sized image classifier notices training loss plateauing almost immediately, with most hidden-layer activations reporting exactly zero when inspected. Debugging traces to a learning-rate-too-high issue early in training: a few large gradient updates pushed a large fraction of ReLU neurons' weights into the always-negative input region, where their gradient is permanently zero — "dead ReLUs" that can never recover via gradient descent, because a neuron that outputs 0 produces 0 gradient regardless of what the rest of the network does. The fix combined a lower initial learning rate, switching to a leaky-ReLU variant (small nonzero slope for negative inputs, so dead neurons can still receive gradient signal to recover) for the affected layers, and adding learning-rate warmup. This is a textbook case where understanding the backward-pass mechanics (specifically, that ReLU's gradient is exactly zero for negative inputs) was the only way to correctly diagnose a training failure that looked, from the loss curve alone, indistinguishable from several other possible causes.

      Common Mistakes, Gotchas and Best Practices

      Gotcha

      Forgetting to cache forward-pass intermediate values (z1, h, z2) needed by the backward pass — a surprisingly common from-scratch bug where someone tries to recompute them during backprop using already-updated weights, silently producing wrong gradients that don't throw an error but make training converge to a worse solution or not converge at all.

      Gotcha

      Initializing all weights to zero (instead of small random values) — with zero initialization, every neuron in a layer computes an identical output and receives an identical gradient, so they update identically forever and the network effectively behaves as if it had only one neuron per layer, no matter how many you actually have. This is called the symmetry problem and is why proper random initialization (and modern schemes like Xavier/He initialization) matters.

      • Sigmoid/tanh in deep (many-layer) networks reliably causes vanishing gradients — prefer ReLU or its variants for hidden layers unless there's a specific reason (e.g. a gated recurrent unit's internal gates, chapter 5) to use sigmoid/tanh.
      • Always verify a from-scratch backward pass with numerical gradient checking (chapter 1's numerical derivative) on a small example before trusting it on real training — an off-by-one transpose error in matrix shapes is the single most common from-scratch bug and often fails silently.

      Interview Questions

      Basic

      Why does a neural network need a nonlinear activation function between layers?

      Without a nonlinearity, stacking multiple linear layers mathematically collapses into a single equivalent linear layer, so the network couldn't learn any function beyond what one linear layer could represent, regardless of depth.

      Follow-up: what specific toy problem demonstrates that a linear model can't solve, but a nonlinear hidden layer can?
      Why did ReLU largely replace sigmoid as the default hidden-layer activation function?

      Sigmoid's derivative is near-zero for large positive or negative inputs, causing vanishing gradients in deep networks. ReLU has a constant gradient of 1 for positive inputs, propagating gradient signal much more reliably through many layers, and is also cheaper to compute.

      Follow-up: what is the "dead ReLU" problem, and why is it ReLU's main downside?
      What is the forward pass, and what must be cached during it?

      The forward pass computes the network's prediction by passing input through each layer's matrix multiply, bias add, and activation function in order. The pre-activation and post-activation values at every layer must be cached because the backward pass needs them to compute gradients via the chain rule.

      Follow-up: what happens to your gradients if you forget to cache these and try to recompute them after updating weights?
      What does backpropagation actually compute?

      It computes the gradient of the loss with respect to every weight and bias in the network, by applying the chain rule backward through the network starting from the loss, reusing intermediate gradient computations layer by layer.

      Follow-up: why is this more efficient than computing each weight's gradient independently from scratch?
      What does the optimizer do with the gradients computed by backpropagation?

      It uses the gradients to update each weight, moving it in the direction that reduces the loss, scaled by the learning rate (and, for momentum/Adam, combined with a running history of past gradients).

      Follow-up: what's the practical difference between plain SGD and Adam in terms of what each weight's update depends on?
      Why must weights be initialized randomly rather than all to zero?

      With all-zero initialization, every neuron in a layer computes identical outputs and receives identical gradients, so they all update identically forever — the layer effectively behaves as a single neuron no matter how many it actually has. Random initialization breaks this symmetry so different neurons can learn different things.

      Follow-up: why do modern initialization schemes (Xavier/He) scale the random values based on layer size rather than using a fixed small constant?

      Medium

      Derive why dz2 = y_hat - y for a softmax output layer with cross-entropy loss.

      Taking the derivative of cross-entropy loss (-Σ y·log(y_hat)) with respect to the pre-softmax logits z2, and applying the chain rule through the softmax function's own derivative, the two expressions combine and simplify algebraically to exactly y_hat - y — the softmax Jacobian terms cancel against the loss gradient terms in a way that's specific to this particular loss/activation pairing, which is exactly why it's used almost universally for classification.

      Follow-up: does this same simplification hold if you used MSE loss instead of cross-entropy with a softmax output? Why or why not?
      Explain the dead ReLU problem mechanically: why can't a dead neuron recover through further training?

      If a ReLU neuron's pre-activation is negative for essentially all training inputs, its output is always 0, and ReLU's derivative for negative inputs is exactly 0. During backprop, the gradient flowing back through that neuron gets multiplied by this zero derivative, becoming zero regardless of the upstream gradient — so that neuron's weights never receive any update signal and it stays dead permanently, unless something external (a different learning rate, re-initialization, or a leaky variant) changes its input distribution.

      Follow-up: how does leaky ReLU specifically fix this, and what's the tradeoff of using it everywhere by default?
      Why does momentum help gradient descent traverse a loss surface with small local bumps or noisy gradients more effectively than plain SGD?

      Momentum maintains a running exponential moving average of past gradients (a "velocity") and uses that, rather than only the instantaneous gradient, for the update. This smooths out noise (bumps that push the gradient in inconsistent directions across steps tend to cancel out in the average) while amplifying a consistent directional trend across many steps, letting the optimizer maintain progress through regions where the instantaneous gradient alone would cause oscillation or stalling.

      Follow-up: what hyperparameter controls how much past gradients influence the current update, and what happens at its extremes?
      Why does Adam use per-parameter adaptive learning rates instead of one global learning rate?

      Different parameters in a network can have very different gradient magnitudes and volatility — some weights consistently receive small, stable gradients while others receive large, noisy ones. Adam tracks a running estimate of each parameter's gradient magnitude (second moment) and divides that parameter's update by it, effectively giving small/stable-gradient parameters relatively larger steps and large/volatile-gradient parameters relatively smaller steps, which tends to make training more robust without needing per-layer manual learning rate tuning.

      Follow-up: what's a scenario where this adaptivity could hurt final generalization compared to well-tuned plain SGD?
      Walk through what would go wrong, numerically, if you implemented backprop but accidentally swapped a transpose (used W2 instead of W2.T when computing dh).

      The matrix shapes would likely mismatch and throw a runtime error in many cases (since W2 is [hidden, output] and dz2 is [batch, output], the multiply dz2 @ W2 would fail dimensionally) — but in cases where dimensions happen to coincidentally align (e.g. a square weight matrix), it would silently compute a mathematically wrong gradient that doesn't correspond to the true chain-rule derivative, producing training that may still reduce loss somewhat (since it's still roughly following some gradient-like signal) but converges to a worse or incorrect solution, which is exactly why numerical gradient checking against a known-correct reference is essential before trusting a from-scratch implementation.

      Follow-up: how would you set up a numerical gradient check to catch this kind of bug?

      Advanced

      Derive the full backward pass for a 3-layer network (two hidden layers) and explain how the pattern generalizes to arbitrary depth.

      Starting from dz3 = y_hat - y at the output, each layer going backward follows the same two-step pattern: (1) compute that layer's weight/bias gradients as (previous layer's activation).T @ (current upstream gradient), and (2) propagate the gradient further back as (current upstream gradient) @ (current layer's weights).T, then multiply elementwise by that earlier layer's activation derivative to get the next dz. This recursive, two-step structure is identical at every layer regardless of depth — it's the chain rule applied once per layer, each time consuming the previous layer's result, which is exactly why backprop's total cost scales linearly with depth (one backward "layer pass" per forward "layer pass") rather than combinatorially.

      Follow-up: why does this linear-in-depth cost still not prevent vanishing/exploding gradients in very deep networks, if the cost itself is fine?
      Why do vanishing and exploding gradients both arise from the same underlying mechanism (repeated multiplication through many layers), and what architectural solutions address this beyond just choosing ReLU?

      Backprop's gradient at an early layer is a product of many per-layer Jacobian/derivative terms chained together (the chain rule, applied across many layers). If these per-layer factors are consistently less than 1 in magnitude, the product shrinks toward zero exponentially with depth (vanishing); if consistently greater than 1, it grows exponentially (exploding) — ReLU helps because its derivative is exactly 1 (not shrinking) in its active region, but doesn't fully solve the problem in very deep networks. Architectural solutions beyond activation choice include residual/skip connections (letting gradient flow through an identity path that bypasses the multiplicative chain entirely, chapter 5-6), careful weight initialization schemes (He/Xavier, chosen so per-layer variance stays stable), batch/layer normalization (keeping activation distributions stable layer to layer), and gradient clipping (capping gradient magnitude as a blunt safety net against exploding gradients specifically).

      Follow-up: why do residual connections specifically target the vanishing gradient problem better than just choosing a better activation function?
      Explain why Adam's adaptivity, which usually speeds up and stabilizes training, can sometimes lead to worse generalization than well-tuned SGD with momentum, despite converging faster on training loss.

      Adam's per-parameter adaptive scaling can cause it to converge to sharper minima in the loss landscape (minima that fit the training data very precisely but are more sensitive to small perturbations, correlating empirically with worse generalization to unseen data) more readily than plain SGD, which tends to find flatter minima due to its noisier, less individually-tailored update behavior acting as an implicit regularizer. This is an active area of ML research (the "generalization gap" between Adam and SGD), and is why some state-of-the-art training recipes (especially for very large models, or image classification benchmarks chasing the last percentage point of accuracy) still default to SGD+momentum with a carefully tuned learning rate schedule rather than Adam, despite Adam's convenience.

      Follow-up: what's a practical compromise technique that tries to get Adam's convergence speed with better generalization properties?
      How would you debug a from-scratch network whose loss decreases initially but then plateaus at a value noticeably worse than a reference implementation's, with everything else (data, architecture, hyperparameters) held identical?

      Systematically isolate suspects in order of likelihood: (1) verify the forward pass output matches the reference exactly on a fixed input (rules out architecture/shape bugs); (2) run numerical gradient checking on every weight gradient against your analytic backward pass on a small fixed batch (catches silent chain-rule/transpose bugs that don't throw shape errors but compute wrong values); (3) check weight initialization scale and random seed handling (a too-large or too-small initial variance can cause early dead neurons or saturated activations that look like normal training but silently cap achievable loss); (4) verify the loss function and its gradient simplification (e.g. the y_hat - y softmax+cross-entropy shortcut) are both implemented, not just one, since mixing a shortcut gradient with a different loss function silently computes the wrong thing. This systematic elimination, starting from "does the forward pass match" before ever questioning the training dynamics, is the single most time-saving debugging discipline for from-scratch implementations.

      Follow-up: why is comparing against a known-correct reference implementation (rather than just "does the loss go down") essential here?
      Why is "my loss is going down, so my implementation must be correct" an unreliable heuristic for validating a from-scratch backprop implementation?

      A sufficiently flexible network with even partially-wrong gradients can still often decrease loss somewhat, because a wrong-but-nonzero gradient can still happen to correlate loosely with the true gradient direction often enough to make some progress — especially on easy toy problems with few parameters, where almost any consistent update direction eventually reduces loss on a small dataset. This means "loss goes down" is a necessary but far from sufficient correctness check; a genuinely wrong implementation (e.g. a missing or extra transpose, a sign error in one term) can still show a plausible-looking loss curve while converging to a meaningfully worse solution than the mathematically correct gradient would reach, which is why numerical gradient checking against a known-correct independent computation is the only reliable verification.

      Follow-up: on what kind of problem would a subtly wrong gradient implementation be most likely to still "accidentally" show a plausible decreasing loss curve?

      Quick Revision Cheat Sheet

      • Nonlinear activations are mandatory — without them, stacked linear layers collapse to one linear layer.
      • ReLU won over sigmoid because its gradient is a constant 1 (vs. near-zero at extremes), avoiding vanishing gradients.
      • Forward pass must cache all intermediate values (z1, h, z2) — backprop needs them.
      • Softmax + cross-entropy's gradient simplifies to y_hat - y — the reason for their near-universal pairing.
      • Backprop = chain rule applied backward, layer by layer, reusing each prior step's result.
      • Dead ReLU: a neuron permanently outputting 0 with 0 gradient, unrecoverable without external intervention.
      • Random weight init breaks symmetry; all-zero init makes every neuron in a layer identical forever.
      • Momentum smooths noisy gradients via a running average; Adam adds per-parameter adaptive learning rates.
      • Always validate a from-scratch backward pass with numerical gradient checking — "loss goes down" alone is not proof of correctness.
