    Attention & Transformers

    ⏱ ~4 hrs📍 Chapter 6 of 14

    One-line summary: Self-attention lets every token look directly at every other token and decide, via learned query/key/value projections, how much to borrow from each — this one mechanism, stacked and parallelized, is the entire architectural basis of every modern LLM, and it is the single most commonly asked deep-mechanism question in ML-adjacent senior interviews.

    On this page

      Why It Matters for a Senior Developer

      If an interviewer asks exactly one "explain the mechanism" ML question in a senior/staff-level interview touching AI, it is very likely to be some version of "explain self-attention" or "why do we scale by sqrt(d_k)?" This isn't trivia — it's a reliable proxy for whether you've actually studied how LLMs work versus only used them via an API. You've likely already covered the applied, API-calling side of LLMs in AI Integration: How LLMs Work; this chapter is the mechanism underneath that applied layer — the actual math and architecture that makes an LLM a specific, analyzable piece of engineering rather than a black box you prompt.

      Why

      Every architecture before attention (RNNs, CNNs applied to sequences) had to either process tokens strictly in order or only see a small local window at a time. Self-attention removes both constraints in one move: every token computes a direct, weighted relationship to every other token in the sequence, in a single parallelizable operation, with a path length between any two tokens that stays constant no matter how far apart they are. That combination — full parallelism during training, plus unlimited-range direct connections — is precisely why attention-based models scaled to internet-sized training corpora in a way recurrent models never could.

      Requires Neural Networks from Scratch, PyTorch & Tensors, and CNNs, RNNs & Sequence Models (specifically the vanishing gradient and parallelism discussion — this chapter is the direct answer to that chapter's final question). For the applied/production angle on using the resulting models, see AI Integration: How LLMs Work.

      Core Concepts

      Self-attention mechanics: Q, K, V and scaled dot-product attention

      Every input token starts as an embedding vector. From that single embedding, the model learns three separate linear projections (three separate weight matrices, W_Q, W_K, W_V) producing three different vectors per token:

      • Query (Q) — "what am I looking for?", derived from the current token.
      • Key (K) — "what do I offer?", derived from every token (including itself) that could be attended to.
      • Value (V) — "what information do I actually contribute if someone attends to me?", also derived from every token.

      The attention computation for one query token against all tokens: take the dot product of that token's Query vector with every token's Key vector (a similarity score — how relevant is this other token to what I'm looking for?), scale, apply softmax to turn those scores into a probability distribution summing to 1, then compute a weighted sum of all the Value vectors using those softmax weights. The result is a new vector for that token: a blend of other tokens' information, weighted by relevance. In matrix form, for the whole sequence at once:

      Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) V

      Why the scaling factor sqrt(d_k) exists: the dot product of two vectors grows in magnitude roughly proportional to their dimensionality d_k (summing more terms produces a larger-magnitude result, assuming roughly independent, unit-variance components). Without scaling, as d_k grows (e.g. 64 or 128 per head), the raw dot-product scores can become large in magnitude, pushing softmax into a near-one-hot regime where the gradient with respect to most inputs is close to zero (softmax saturates at extreme input magnitudes). Dividing by sqrt(d_k) keeps the variance of the scores roughly constant regardless of dimensionality, keeping softmax in a well-behaved range with usable gradients — this is purely a numerical-stability fix for training, not a change in what the mechanism conceptually computes.

      Multi-head attention

      Rather than computing one attention pattern per layer, the model splits Q, K, V into h independent "heads" (e.g. 12 heads of dimension 64 each, from a 768-dimensional embedding), runs scaled dot-product attention separately within each head's smaller subspace, then concatenates all heads' outputs and projects back to the full embedding dimension with one more learned matrix. Each head can learn to specialize in a different kind of relationship — one head might learn to track subject-verb agreement, another might track coreference (which pronoun refers to which noun), another might attend mostly to the immediately preceding token. A single attention head computing one softmax distribution per token can only represent one "shape" of relationship at a time; multiple heads let the model represent several different relevance patterns for the same token simultaneously, then combine them.

      Positional encoding: why transformers need it, and sinusoidal vs. learned

      Self-attention as described is permutation-invariant — nothing in the Q/K/V dot-product computation itself encodes token order; shuffling the input tokens would produce the same set of pairwise relationships, just relabeled. But order obviously matters for language ("dog bites man" ≠ "man bites dog"). Positional encoding injects order information directly into the input before attention ever runs, typically by adding a position-dependent vector to each token's embedding.

      • Sinusoidal (original Transformer paper) — a fixed, non-learned function of position using sine and cosine waves at different frequencies per embedding dimension. It generalizes to sequence lengths longer than anything seen during training (it's just a mathematical function, not a learned table), and nearby positions produce similar vectors while the relative-offset relationship between any two positions is consistent and computable, which theoretically helps the model learn relative-position reasoning.
      • Learned positional embeddings — a trainable embedding table, one vector per position, learned jointly with everything else (used by GPT-2 and many earlier models). Simpler, but fixed to a maximum sequence length baked in at training time and doesn't naturally extrapolate beyond it.
      • Modern alternatives (RoPE, ALiBi) — most current LLMs (Llama, GPT-4-class models, most open models in 2025-26) use Rotary Positional Embeddings (RoPE), which rotates Q and K vectors by an angle proportional to position directly inside the attention computation rather than adding a separate positional vector to the input embedding. This bakes relative position directly into the dot-product score itself and generalizes to longer sequences noticeably better than either original scheme, which is why it's now the dominant choice.

      The full transformer block: attention + FFN + residual + layernorm

      One transformer block/layer is not just attention — it's a specific stack of sub-layers, each wrapped in a residual connection and normalization:

      1. Multi-head self-attention over the block's input.
      2. Residual connection: add the attention output back to the original input (x + Attention(x)) — this gives gradients a direct, short path backward through every layer (echoing the same "additive path helps gradient flow" idea from LSTMs in the previous chapter), and lets a layer learn to only adjust the representation incrementally rather than having to reconstruct it entirely.
      3. Layer normalization: normalize activations (zero mean, unit variance, per token, across the feature dimension) to keep training stable across many stacked layers. Most modern architectures use "pre-norm" (normalize before the sub-layer, not after) because it produces more stable gradients in very deep stacks than the original "post-norm" design.
      4. Position-wise feed-forward network (FFN): a two-layer MLP (typically expanding to 4x the embedding dimension and back down, with a nonlinearity like GELU in between) applied independently to each token's vector. Attention mixes information across tokens; the FFN processes each token's resulting vector further independently — the two sub-layers have complementary jobs.
      5. Another residual connection and layer norm around the FFN.

      A full transformer stacks many of these blocks (e.g. 12, 32, 96+ depending on model size), each one refining every token's representation using the growing context gathered from previous blocks.

      Encoder, decoder, and decoder-only (GPT-style) architectures

      • Encoder-only (e.g. BERT) — uses full, unmasked self-attention: every token can attend to every other token in both directions. Good for understanding tasks where the whole input is available at once (classification, embeddings, extraction) but not naturally suited to generation, since it assumes the full sequence already exists.
      • Encoder-decoder (e.g. the original Transformer for translation, T5) — an encoder processes the full input with bidirectional attention; a decoder generates output tokens one at a time, using causal self-attention over its own previously generated tokens plus "cross-attention" into the encoder's output (Q from the decoder, K/V from the encoder) to stay grounded in the source. Good for sequence-to-sequence tasks with a clearly distinct input and output (translation, summarization with a fixed source document).
      • Decoder-only (GPT-style — the architecture behind essentially all modern general- purpose LLMs) — a single stack using causal (masked) self-attention: each token can only attend to itself and earlier tokens, enforced by masking out (setting to -infinity before softmax) any attention score pointing to a future position. This matches exactly how autoregressive generation works (predict the next token given only what's been generated so far) and turned out to scale better and generalize to more tasks via prompting than the encoder-decoder split, which is why it became the dominant architecture for general-purpose LLMs.

      KV-caching for inference

      During autoregressive generation, computing token N's output requires attending over all tokens 1 through N — but tokens 1 through N-1's Key and Value vectors were already computed in the previous generation step and haven't changed (causal masking means earlier tokens never attend to later ones, so their K/V vectors are fixed once computed). KV-caching stores these Key and Value vectors from previous steps and reuses them, so generating each new token only requires computing Q/K/V for the one new token and attending it against the cached K/V from all previous tokens, instead of recomputing everything from scratch. This turns what would be O(n²) redundant work across a full generation into roughly O(n) incremental work per new token — it's the single most important inference-time optimization for autoregressive LLMs, and it's the direct reason generation memory usage grows with context length (the KV cache itself consumes GPU memory proportional to sequence length × number of layers × number of heads).

      How It Works Under the Hood

      End to end, for a decoder-only LLM generating one new token:

      1. Input tokens are embedded, and positional information (RoPE, applied inside attention, or an added positional vector) is incorporated.
      2. For each transformer block: compute Q, K, V for the current token(s); for cached generation, reuse stored K/V for all previous tokens and only compute Q/K/V for the new token.
      3. Compute causal scaled dot-product attention per head (new token's Q against all K up to and including itself), softmax, weighted sum of V, concatenate heads, project.
      4. Add the residual connection, apply layer norm, pass through the FFN, add another residual, apply layer norm again.
      5. Repeat through every block; the final block's output for the last position is projected through a final linear layer (often tied to the input embedding matrix) to produce logits over the vocabulary.
      6. A sampling strategy (greedy, temperature + top-k/top-p) picks the next token from those logits; it's appended to the sequence, its K/V is cached, and the process repeats.

      Code Examples

      import torch
import torch.nn as nn
import math

class ScaledDotProductAttention(nn.Module):
    """Single-head attention, implemented explicitly to show every step."""
    def forward(self, Q, K, V, causal_mask=None):
        d_k = Q.size(-1)
        scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)   # (batch, seq, seq)
        if causal_mask is not None:
            scores = scores.masked_fill(causal_mask == 0, float("-inf"))
        weights = torch.softmax(scores, dim=-1)             # rows sum to 1
        return weights @ V, weights                          # (batch, seq, d_v)

class MultiHeadAttention(nn.Module):
    def __init__(self, embed_dim, num_heads):
        super().__init__()
        assert embed_dim % num_heads == 0
        self.num_heads = num_heads
        self.head_dim = embed_dim // num_heads
        self.W_q = nn.Linear(embed_dim, embed_dim)
        self.W_k = nn.Linear(embed_dim, embed_dim)
        self.W_v = nn.Linear(embed_dim, embed_dim)
        self.W_o = nn.Linear(embed_dim, embed_dim)
        self.attn = ScaledDotProductAttention()

    def split_heads(self, x):
        batch, seq_len, embed_dim = x.shape
        x = x.view(batch, seq_len, self.num_heads, self.head_dim)
        return x.transpose(1, 2)   # (batch, heads, seq, head_dim)

    def forward(self, x, causal_mask=None):
        batch, seq_len, _ = x.shape
        Q, K, V = self.split_heads(self.W_q(x)), self.split_heads(self.W_k(x)), self.split_heads(self.W_v(x))
        out, _ = self.attn(Q, K, V, causal_mask)
        out = out.transpose(1, 2).contiguous().view(batch, seq_len, -1)
        return self.W_o(out)

class TransformerBlock(nn.Module):
    def __init__(self, embed_dim, num_heads, ffn_dim):
        super().__init__()
        self.attn = MultiHeadAttention(embed_dim, num_heads)
        self.ln1 = nn.LayerNorm(embed_dim)
        self.ffn = nn.Sequential(
            nn.Linear(embed_dim, ffn_dim), nn.GELU(), nn.Linear(ffn_dim, embed_dim)
        )
        self.ln2 = nn.LayerNorm(embed_dim)

    def forward(self, x, causal_mask=None):
        x = x + self.attn(self.ln1(x), causal_mask)   # pre-norm + residual
        x = x + self.ffn(self.ln2(x))                  # pre-norm + residual
        return x

def causal_mask(seq_len, device="cpu"):
    # Lower-triangular mask: position i can attend to positions <= i only.
    return torch.tril(torch.ones(seq_len, seq_len, device=device)).unsqueeze(0).unsqueeze(0)

# Using HuggingFace for the real-world equivalent instead of reimplementing from scratch:
from transformers import AutoModel, AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
model = AutoModel.from_pretrained("bert-base-uncased")
inputs = tokenizer("Attention lets every token look at every other token.", return_tensors="pt")
outputs = model(**inputs, output_attentions=True)
# outputs.attentions is a tuple of per-layer attention weight tensors:
# (batch, num_heads, seq_len, seq_len) — exactly the "weights" matrix computed above,
# inspectable directly to see which tokens each head actually attended to.
print(outputs.attentions[0].shape)

      Real-World Production Scenario at Scale

      At scale

      A team serving a customer-support LLM notices that per-token generation latency grows noticeably as conversations get longer, and GPU memory usage on their inference servers climbs steadily during long sessions until requests start failing with out-of-memory errors. The root cause traces directly to KV-cache growth: every additional token in the growing conversation history adds its Key and Value vectors to the cache for every layer and every head, and that memory is held for the entire generation. The fix isn't a bug fix in the traditional sense — it's an architectural accommodation: the team adds a sliding-window cache eviction policy (dropping the oldest cached tokens beyond a budget, accepting some loss of very old context) and migrates to a model variant using grouped-query attention (fewer K/V heads shared across multiple Q heads), which cuts KV-cache memory per token substantially without a full multi-head-attention equivalent. Understanding that this was a KV-cache memory issue — not a "model is slow" issue — is exactly the kind of mechanism-level debugging that separates "knows how to call an LLM API" from "understands the system underneath it."

      Common Mistakes, Gotchas and Best Practices

      Gotcha

      Describing attention as "the model deciding which words are important" without being able to say how — in an interview, that's the line between a surface-level and a mechanistic answer. Be ready to say specifically: Q/K dot product produces relevance scores, softmax turns them into weights, weighted sum of V produces the mixed output — and why scaling by sqrt(d_k) exists (softmax saturation at high dot-product magnitude, not an arbitrary constant).

      Gotcha

      Forgetting that self-attention alone is permutation-invariant and has no sense of order — a surprising number of people can describe attention correctly but then can't explain why positional encoding is necessary at all, which is a dead giveaway of memorized-but-not- understood knowledge.

      • Causal masking must be applied before softmax (setting masked positions to -infinity), not after — masking the softmax output directly would leave the remaining weights not summing to 1.
      • Pre-norm (normalize before each sub-layer) is now standard over the original paper's post-norm, because it trains far more stably at the depths (dozens to 100+ layers) modern LLMs use.
      • KV-cache memory, not raw compute, is frequently the actual bottleneck for long-context inference — profile memory, don't just assume latency issues are purely FLOPs-bound.
      • RoPE/ALiBi generalize to longer sequences than they were trained on noticeably better than learned absolute positional embeddings — relevant when discussing why a given open model handles long context well or poorly.

      Interview Questions

      Basic

      What are Query, Key, and Value vectors, in plain terms?

      They're three separate learned linear projections of the same token embedding. Query represents what the current token is "looking for"; Key represents what each token (including itself) "offers" to be matched against; Value represents what information that token actually contributes if it's attended to.

      Follow-up: are Q, K, and V computed with the same weight matrix or different ones?
      Write out the scaled dot-product attention formula and explain each part.

      Attention(Q,K,V) = softmax(QK^T / sqrt(d_k)) V. QK^T computes similarity scores between every query and every key; dividing by sqrt(d_k) scales those scores to keep softmax well-behaved; softmax turns the scores into a probability distribution (weights summing to 1); multiplying by V produces a weighted blend of value vectors as the output.

      Follow-up: what shape is the QK^T matrix for a sequence of length n?
      Why is self-attention described as "permutation-invariant," and why is that a problem?

      Nothing in the Q/K/V dot-product computation itself depends on token position — shuffling the input tokens produces the same pairwise relationships, just relabeled. This is a problem because order matters in language, so without additional information the model literally cannot distinguish "dog bites man" from "man bites dog."

      Follow-up: what's the fix, at a high level?
      What is multi-head attention, and why not just use one larger head?

      Multi-head attention splits Q/K/V into several smaller independent subspaces (heads) and runs attention separately in each, then concatenates and projects the results. Multiple heads let the model represent several different kinds of relevance/relationship simultaneously (e.g. one head tracking syntax, another tracking coreference); a single softmax distribution per token can only express one such pattern at a time.

      Follow-up: if embed_dim is 768 and there are 12 heads, what's the dimension of each head?
      What's the difference between an encoder and a decoder in transformer terminology?

      An encoder uses full, bidirectional self-attention — every token can attend to every other token in both directions, suited to understanding the whole input at once. A decoder uses causal/masked self-attention — each token can only attend to itself and earlier tokens, matching how autoregressive generation works.

      Follow-up: which category does GPT-style architecture fall into?
      What does a residual connection do in a transformer block, in plain terms?

      It adds the sub-layer's input directly to its output (x + SubLayer(x)), giving gradients a short, direct path backward through every layer and letting each layer learn an incremental adjustment rather than having to reconstruct the full representation from scratch.

      Follow-up: what's the analogous problem this solves, that we saw with a different architecture in the previous chapter?
      What is KV-caching, in one sentence?

      It's reusing the already-computed Key and Value vectors of previous tokens during autoregressive generation instead of recomputing them at every new generation step, since causal masking guarantees they never change once computed.

      Follow-up: what resource does the KV cache consume, and how does it scale with context length?

      Medium

      Derive why the scaling factor in scaled dot-product attention is specifically sqrt(d_k), not some other constant.

      Assuming Q and K components are roughly independent with unit variance, the dot product of two d_k-dimensional vectors has variance that grows linearly with d_k (sum of d_k independent products). Dividing by sqrt(d_k) normalizes the variance of the dot product back to approximately 1 regardless of dimensionality, preventing scores from growing large in magnitude as d_k increases — large-magnitude scores push softmax into a near-one-hot, low-gradient regime, which would hurt training.

      Follow-up: what would you observe in practice (e.g. in training loss or attention weight patterns) if this scaling were omitted on a large model?
      Explain causal masking mechanically: where in the computation does it apply, and why there specifically?

      It's applied to the raw QK^T score matrix, before softmax: positions corresponding to "attending to a future token" are set to negative infinity. This must happen before softmax because softmax normalizes a row to sum to 1 — masking after softmax (e.g. zeroing out those weights post-hoc) would leave the remaining weights not summing to 1, breaking the probability-distribution interpretation and the weighted-average semantics of the output.

      Follow-up: how is the causal mask typically represented/constructed as a tensor?
      Why does the FFN sub-layer apply independently per token, and what complementary role does it play relative to attention?

      Attention is the only sub-layer that mixes information across token positions; the FFN takes each token's post-attention vector and transforms it independently of every other token's vector (same weights applied per-position, no cross-token interaction). The division of labor is: attention decides what to gather from other tokens, FFN further processes/transforms what each token now individually "knows." Both are necessary — attention alone with no per-token nonlinear transformation would be a comparatively weak model.

      Follow-up: why is the FFN typically expanded to 4x the embedding dimension internally rather than kept the same size?
      Compare sinusoidal, learned, and rotary (RoPE) positional encodings on generalization to longer sequences than seen in training.

      Learned absolute positional embeddings are a fixed-size lookup table trained only up to the maximum training sequence length, so they have no defined behavior (or very poor extrapolation) beyond it. Sinusoidal encodings are a fixed mathematical function of position, so they're technically defined for any length, but empirically still extrapolate only moderately well. RoPE encodes relative position directly into the attention dot-product via rotation, and empirically generalizes to longer contexts noticeably better than either, which is the main reason it's become the dominant choice in modern open LLMs.

      Follow-up: why does encoding "relative" rather than "absolute" position tend to generalize better?
      Why does KV-caching turn generation from O(n²) into roughly O(n) work across a full sequence, and what's the memory cost of that tradeoff?

      Without caching, generating token n requires recomputing K/V for all n tokens and reattending, and doing this for every one of n generation steps is O(n²) total work. With caching, each step only computes Q/K/V for the one new token and reuses cached K/V for the rest, making each step O(n) and the full generation O(n²) → effectively O(n) amortized per token (still O(n²) total across the full generation due to attention itself scaling with context length, but avoiding the redundant recomputation). The cost is memory: the cache holds K and V vectors for every token, every layer, every head, for the duration of generation — memory usage grows linearly with context length.

      Follow-up: what's one technique (besides shortening context) teams use to reduce KV-cache memory footprint?
      Why did decoder-only architectures become the dominant choice for general-purpose LLMs over the original encoder-decoder design?

      Decoder-only models unify understanding and generation into a single causal-attention stack: any task can be framed as "predict the next token" via prompting, without needing a separate encoder pass and cross-attention mechanism tailored to a fixed input/output split. This turned out to scale better empirically and generalizes far more flexibly to arbitrary tasks via prompting/few-shot examples than the encoder-decoder split, which is more naturally suited to tasks with a rigid, clearly distinct input and output (like translation).

      Follow-up: in what scenario would an encoder-decoder (or encoder-only) architecture still be the better choice today?

      Advanced

      Walk through, step by step, computing self-attention output for a 3-token sequence by hand (symbolically) — what are the shapes at each stage, and where would numerical instability most likely show up without the scaling factor?

      For 3 tokens with embedding dim d and head dim d_k: Q, K, V are each (3, d_k) after projection. QK^T is (3,3) — a full pairwise similarity matrix. Without scaling, if d_k is large (e.g. 64+) and projections aren't tightly controlled, individual entries of QK^T can have large magnitude; softmax applied to rows with widely-spread large values saturates (near one-hot), and the gradient of softmax with respect to its input becomes very small wherever the output is near 0 or 1 for most entries — this is where training signal would vanish, concretely inside the softmax(QK^T) step, which is exactly what sqrt(d_k) scaling is designed to prevent by keeping the pre-softmax scores in a moderate range.

      Follow-up: does this instability risk scale with sequence length too, or only with d_k? Why?
      Explain grouped-query attention (GQA) and multi-query attention (MQA) and the specific problem they solve relative to standard multi-head attention.

      Standard multi-head attention computes a separate set of Key and Value projections per head, meaning the KV-cache during inference must store K/V for every head independently — memory scales linearly with number of heads. Multi-query attention shares a single K/V projection across all Q heads (only Q is per-head), cutting KV-cache memory by roughly the head count while keeping most of the representational benefit of multiple query heads. Grouped-query attention is a middle ground: heads are grouped, and each group shares one K/V projection, trading off some of MQA's memory savings for better representational capacity than full MQA, closer to full multi-head quality. Both exist specifically to shrink KV-cache memory for long-context, high-throughput inference serving — a production/serving concern, not a training-quality concern.

      Follow-up: would you expect GQA to hurt model quality noticeably compared to full multi-head attention? Under what circumstances might it not?
      Why is attention's compute cost quadratic in sequence length, and what does that mean concretely for scaling context windows?

      Computing QK^T requires comparing every query position against every key position, producing an n×n score matrix — the compute and memory for this step scale as O(n²) in sequence length n, independent of embedding dimension. Doubling the context window roughly quadruples the attention computation and memory for that step (though the FFN sub-layers remain linear in n), making very long contexts disproportionately expensive. This is the core motivation behind efficient-attention research (sparse attention, linear attention approximations, sliding-window attention, FlashAttention-style memory-efficient exact computation) — all attempts to avoid or mitigate the quadratic cost rather than simply accepting it.

      Follow-up: does FlashAttention change the asymptotic complexity, or just the constant/memory-access pattern? Why does that distinction matter in practice?
      Design an experiment to empirically verify that a specific attention head in a trained model has learned to track long-range coreference (e.g. pronoun-to-noun resolution) rather than just attending to nearby tokens.

      Construct a labeled probe dataset of sentences with known pronoun-antecedent pairs at varying distances apart, run them through the model with output_attentions=True, and extract that specific head's attention weight matrix for each example. For each pronoun token's query position, check whether the attention weight is concentrated on the correct antecedent token's key position specifically (not just on nearby tokens by default), and measure this across examples with the antecedent placed at increasing distances — a head doing real coreference tracking should maintain high weight on the correct (possibly distant) antecedent regardless of distance, whereas a head just doing "attend to recent context" would show attention decaying with distance regardless of which token is the grammatically correct antecedent.

      Follow-up: why is attention weight alone sometimes considered insufficient evidence for "what a head is doing," and what additional technique (e.g. from interpretability research) could corroborate the finding?
      A team is fine-tuning a decoder-only LLM and observes that performance degrades sharply on inputs longer than the model's training context length, despite using RoPE. What's going on, and what are the standard mitigations?

      RoPE improves extrapolation relative to learned absolute positional embeddings, but it is not unlimited — rotation angles at positions far beyond the trained range produce frequency patterns the model never saw during training, and attention score distributions can still degrade ("positional out-of-distribution" behavior), especially for the lowest-frequency rotation components. Standard mitigations: positional interpolation (rescaling position indices to compress a longer sequence into the model's originally trained positional range before applying RoPE), continued pretraining/fine-tuning at the target longer context length so the model actually sees those positions during training, or newer techniques (YaRN, dynamic NTK scaling) that adjust RoPE's frequency base specifically to extend effective context length with minimal degradation.

      Follow-up: why does simply fine-tuning at a longer context length without any positional adjustment often still underperform compared to techniques that explicitly adjust the positional scheme?

      Use a fixed random seed and identical Q/K/V tensors for both implementations, and don't forget the causal mask parameter if comparing against the causal variant of the built-in function.

      Bonus: remove the sqrt(d_k) scaling and show how the attention weight distribution becomes visibly more peaked/one-hot as d_k increases.

      Intermediate (2-4 hrs)

      Build and train a tiny decoder-only transformer on a character-level task

      Using the TransformerBlock and causal masking from the code examples, build a small (2-4 layer) decoder-only model and train it on a simple character-level next-token-prediction task (e.g. learning to continue a small, repetitive text corpus).

      • Implement the full training loop (loss, optimizer, backward pass).
      • After training, generate text autoregressively from a seed prompt, implementing KV-caching for generation (reuse cached K/V rather than recomputing the whole sequence at every step).
      • Benchmark generation speed with and without KV-caching for a reasonably long generated sequence.

      Acceptance criteria: the model visibly learns the training corpus's patterns (loss decreases, generated text resembles the training distribution), and KV-caching measurably speeds up generation versus the naive recompute-everything approach.

      Hints

      For the non-cached baseline, simply re-run the full forward pass on the entire sequence-so-far at every generation step; for the cached version, store each layer's K/V tensors in a list and concatenate the new token's K/V onto them each step instead of recomputing from token 0.

      Bonus: visualize the attention weights of one head at one layer across the generated sequence, and try to identify what pattern (if any) that head appears to have learned.

      Advanced (1-2 days)

      Implement and benchmark multi-query attention against standard multi-head attention

      Extend your transformer implementation with a multi-query attention (MQA) variant (single shared K/V projection across all Q heads) alongside your existing standard multi-head attention, and compare them.

      • Train small models with each attention variant on the same task/data and compare final loss/quality.
      • Measure and compare KV-cache memory footprint (in bytes, computed analytically from shapes) for a given context length under both variants.
      • Measure actual generation throughput (tokens/sec) for both variants at a long context length.

      Acceptance criteria: a clear report quantifying the memory savings of MQA versus the quality tradeoff observed, with actual measured numbers, not just theoretical ones.

      Hints

      KV-cache memory per token = 2 (K and V) × num_layers × num_kv_heads × head_dim × bytes_per_element — compute this directly from your model's config for both variants rather than only measuring empirically, so you can sanity-check empirical memory measurements against the theoretical formula.

      Bonus: implement grouped-query attention as a third variant and show where it lands between standard multi-head and MQA on both quality and memory.

      Quick Revision Cheat Sheet

      • Attention(Q,K,V) = softmax(QK^T / sqrt(d_k)) V — Q="what I want", K="what I offer", V="what I contribute if attended to".
      • sqrt(d_k) scaling exists because raw dot-product variance grows with dimension, which would otherwise saturate softmax and kill gradients.
      • Multi-head attention runs several smaller attention computations in parallel subspaces so different heads can specialize in different relationship types.
      • Self-attention is permutation-invariant by default — positional encoding (sinusoidal, learned, or RoPE) injects order information.
      • RoPE is the dominant modern choice — encodes relative position directly in the attention dot-product, generalizes to longer contexts better than alternatives.
      • Transformer block = multi-head attention + residual + layernorm, then FFN + residual + layernorm; attention mixes across tokens, FFN processes each token independently.
      • Encoder = bidirectional (understanding); decoder = causal/masked (generation); decoder-only (GPT-style) dominates general-purpose LLMs.
      • KV-caching reuses previously computed Key/Value vectors during generation, avoiding O(n²) redundant recomputation — but costs memory proportional to context length.
      • Attention compute is quadratic in sequence length — the core motivation for GQA/MQA, sparse attention, and FlashAttention-style optimizations.
