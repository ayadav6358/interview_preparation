    Web Fundamentals

    📚 6 chapters⏱ ~13–15 hrs total

    A fast, no-hand-holding refresher on the fundamentals every senior web developer is assumed to know cold in an interview: HTML/CSS mechanics, JavaScript semantics, the DOM and browser rendering pipeline, HTTP/networking, Git internals, and the shell. These are muscle-memory skills that get rusty precisely because they're "basic" — this topic exists to sharpen the precise vocabulary and edge cases (specificity math, hoisting/TDZ, rebase vs merge, CORS preflight) that interviewers probe to separate "has used it" from "can explain it." It's also the assumed foundation for React Fundamentals, React/Next.js Advanced, and Node.js Advanced.

    Learning Outcomes

    • Calculate CSS specificity precisely and explain the cascade, including layers and custom properties.
    • Explain JS hoisting, the temporal dead zone, type coercion rules, and closures without hand-waving.
    • Describe the browser's critical rendering path and how DOM/CSSOM changes trigger layout vs paint vs composite.
    • Walk through a full HTTP request/response lifecycle including CORS preflight and cookie attributes.
    • Explain what `git rebase` actually does to commit history and resolve a real merge conflict confidently.
    • Navigate and script a Unix-like shell fluently: piping, redirection, env vars, exit codes.

    🏆 Capstone Project: Build a Multi-Page Static Website From Scratch

    Problem statement: Using nothing but semantic HTML, hand-written CSS, and vanilla JavaScript (no framework, no CSS framework), build and ship a small multi-page website — e.g. a personal portfolio or a "local weather dashboard" — that is responsive, accessible, interactive, and version-controlled with a clean Git history.

    Required features:

    • At least 3 HTML pages sharing a consistent semantic layout (header/nav/main/footer, proper heading hierarchy).
    • Responsive CSS using Flexbox and/or Grid — must work cleanly from 320px to 1440px wide, no horizontal scroll.
    • A form with real client-side validation (required fields, pattern matching, inline error messages, no library).
    • Vanilla JS DOM manipulation: at least one feature that adds/removes/updates elements dynamically (e.g., a to-do list, filterable card grid, or tabbed interface) using event delegation.
    • A `fetch()` call to a public API (e.g., a weather or quotes API) rendering live data into the DOM, with loading and error states handled.
    • Served locally via a simple static server (no backend framework) and a README explaining setup and structure.

    Tech stack suggestion: Plain HTML5/CSS3/ES2024 JS, `npx serve` or VS Code Live Server for local hosting, Git for version control.

    Milestones:

    1. Init a Git repo, scaffold the 3 pages with semantic HTML only (no styling yet), commit.
    2. Write the CSS: box model, Flexbox/Grid layout, responsive breakpoints, commit in logical chunks.
    3. Add the validated form and the DOM-manipulation feature with event delegation, commit.
    4. Wire up the `fetch()` call with loading/error UI states, commit.
    5. Clean up commit history (interactive rebase to squash WIP commits into logical units), write the README.
    6. Test keyboard navigation and screen-reader landmarks; fix any specificity/cascade bugs found along the way.

    Evaluation checklist:

    • ☐ Zero `!important` hacks — every specificity conflict is resolved by understanding the cascade, not overriding it.
    • ☐ Layout holds with no horizontal scroll from 320px to 1440px.
    • ☐ Form validation gives inline, accessible error messages (not just browser default bubbles).
    • ☐ Can explain, commit by commit, what each one changed and why the history reads cleanly.
    • ☐ `fetch()` failure (e.g., offline) is handled gracefully, not a blank screen or console error.
