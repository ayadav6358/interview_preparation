    Observability & Security

    📚 6 chapters⏱ ~14–17 hrs total

    Senior and Tech Lead interviews increasingly probe whether you can run a system in production, not just design one. This topic covers the three pillars of observability (logs, metrics, traces), the OWASP Top 10 with real Node/React exploits and fixes, secure auth and secrets management, and how to run a blameless incident post-mortem. Expect whiteboard questions like "walk me through debugging a latency spike across five services" and "how would you have caught this SQL injection in code review."

    Learning Outcomes

    • Design a structured logging strategy with correlation IDs that survives a multi-service request.
    • Instrument an app with Prometheus metrics (RED/USE methods) and write alerting rules that don't page on noise.
    • Propagate OpenTelemetry trace context across HTTP, queues, and async boundaries, and read a trace waterfall to find the real bottleneck.
    • Identify and fix real OWASP Top 10 vulnerabilities in Node/Express and React code — not just name them.
    • Implement secure auth (sessions vs JWT, refresh rotation), secrets management, CORS, CSP, and defenses against XSS/CSRF/SQLi.
    • Run a blameless incident post-mortem with a clear timeline, root cause, and actionable follow-ups.

    🏆 Capstone Project: Instrument, Attack, and Harden a Full-Stack App

    Problem statement: Take a small Node/Express + React app (or build a minimal one: a notes/todo API with login) and take it through the full observability + security lifecycle: instrument it, deliberately break it, then fix and document it like a production incident would require.

    Required work:

    • Add structured JSON logging (Pino/Winston) with a request-scoped correlation ID propagated through every log line and downstream call.
    • Expose a /metrics endpoint with Prometheus client metrics following the RED method (rate, errors, duration) for every route, plus a Grafana dashboard JSON.
    • Instrument the app with OpenTelemetry: auto-instrument HTTP + DB calls, manually span one business operation, and propagate trace context to at least one downstream call (even a second local service or a mocked external call).
    • Deliberately introduce and then fix at least 5 real vulnerabilities: reflected/stored XSS, SQL injection (raw string query), broken auth (e.g., weak JWT secret or missing expiry check), CSRF (state-changing GET or missing token on a cookie-session form), and insecure secrets handling (hardcoded API key in source).
    • For each vulnerability: write the exploit (a real curl/script/payload that works against the vulnerable version), then the fix, then a short note on how you'd catch it next time (lint rule, test, code review checklist item).
    • Simulate one incident (e.g., trigger a slow DB query under load, or the auth bypass you just fixed) and write a full post-mortem: timeline with timestamps, detection method, root cause (5 Whys), blast radius, and 3+ blameless action items with owners.

    Tech stack suggestion: Node.js + Express + TypeScript, React (Vite), Postgres or SQLite, Pino, prom-client, @opentelemetry/sdk-node, Jaeger or Grafana Tempo for trace visualization, Docker Compose for Prometheus + Grafana + Jaeger locally.

    Evaluation checklist:

    • ☐ A single request's logs can be filtered end-to-end by one correlation ID.
    • ☐ Metrics dashboard shows p50/p95/p99 latency and error rate per route, with at least one alert rule defined.
    • ☐ A trace waterfall for the slow operation clearly shows which span dominates the latency.
    • ☐ Every exploit was actually run against the vulnerable code and actually fails against the fixed code (not just described).
    • ☐ The post-mortem has a real timeline, a root cause that isn't just "human error," and action items that are specific and assignable.
