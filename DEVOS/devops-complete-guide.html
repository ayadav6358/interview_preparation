HLD — High Level Design (Platform Architecture)

Ek typical production DevOps platform ka bird's-eye view: code se production tak, aur observability ke saath.

1. Requirements

  • Functional: code push par automatic build/test/deploy; multi-env (dev/stage/prod); rollback; secrets management; logs/metrics/alerts.
  • Non-functional: 99.9% availability, deploy in <15 min, zero-downtime releases, auditability, cost-controlled, secure by default.

4. Environments

  • Dev: auto-deploy on merge to main, small nodes, spot instances.
  • Staging: prod-like, smoke + load tests, auto-promote.
  • Prod: manual approval (or progressive canary with auto-rollback), multi-AZ, backups, DR.
  • Separate AWS accounts per env (AWS Organizations) — blast radius kam.

5. Reliability, Scaling, DR

  • HPA (pods) + Cluster autoscaler (nodes); PodDisruptionBudgets; multiple replicas across AZs.
  • RDS Multi-AZ + automated backups + cross-region snapshot; RPO 15 min, RTO 1 hr (example targets).
  • Velero for cluster backup; Terraform to rebuild infra; runbooks tested via game days.

6. Security model

  • Least privilege IAM, IRSA (pod-level IAM roles), no long-lived credentials.
  • Network policies (default deny), private subnets, security groups tight.
  • Image scanning + signing, admission policies, secrets never in Git (External Secrets / SOPS).
  • Audit: CloudTrail, K8s audit logs, Git history.

7. Cost

  • Spot for non-prod, right-sizing, S3 lifecycle, tagging + AWS Budgets, scale-to-zero dev at night.

LLD — Low Level Design (Implementation)

HLD ke har block ka concrete implementation: repo layout, pipeline, Dockerfile, Terraform, K8s, alerts.

1. Repository structure

├── app/                      # application repo (separate in real life)
│   ├── src/
│   ├── Dockerfile
│   └── .github/workflows/ci.yml

2. Dockerfile (multi-stage, non-root)

FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:20-alpine
WORKDIR /app
ENV NODE_ENV=production
COPY --from=build /app/dist ./dist
COPY --from=build /app/node_modules ./node_modules
RUN addgroup -S app && adduser -S app -G app
USER app
EXPOSE 3000
HEALTHCHECK CMD wget -qO- http://localhost:3000/health || exit 1
CMD ["node","dist/server.js"]

3. CI pipeline (GitHub Actions + OIDC to AWS)

name: ci
on:
  push: { branches: [main] }
  pull_request:
permissions: { id-token: write, contents: read }
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci && npm test
      - name: Trivy fs scan
        uses: aquasecurity/trivy-action@master
        with: { scan-type: fs, severity: 'HIGH,CRITICAL', exit-code: '1' }
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::123456789012:role/gha-ecr-push
          aws-region: ap-south-1
      - id: ecr
        uses: aws-actions/amazon-ecr-login@v2
      - name: Build & push
        run: |
          IMG=${{ steps.ecr.outputs.registry }}/myapp:${{ github.sha }}
          docker build -t $IMG .
          trivy image --exit-code 1 --severity CRITICAL $IMG
          docker push $IMG
      - name: Bump image tag in gitops repo
        if: github.ref == 'refs/heads/main'
        run: |
          # yq edit values-dev.yaml image.tag, commit, push to gitops repo
          echo "update tag to ${{ github.sha }}"

7. Alerting rule (SLO style)

groups:
- name: myapp
  rules:
  - alert: HighErrorRate
    expr: sum(rate(http_requests_total{job="myapp",code=~"5.."}[5m]))
          / sum(rate(http_requests_total{job="myapp"}[5m])) > 0.02
    for: 5m
    labels: { severity: page }
    annotations:
      summary: "5xx error rate above 2% for 5 minutes"
      runbook: "https://wiki/runbooks/myapp-5xx"
  - alert: PodCrashLooping
    expr: increase(kube_pod_container_status_restarts_total[15m]) > 3
    for: 5m
    labels: { severity: ticket }

9. Rollback & incident runbook (short)

  1. Alert fires → acknowledge in PagerDuty, open incident channel.
  2. Check Grafana dashboard: recent deploy? → argocd app rollback myapp-prod or revert Git commit.
  3. kubectl get pods -n prod, kubectl describe pod, kubectl logs --previous.
  4. Mitigate first, root-cause later. Write blameless postmortem within 48 hrs with action items.

Interview Prep — Common Questions

  • Linux: process vs thread? What happens when you type a command? How to debug high CPU / disk full / OOM?
  • Networking: What happens when you open google.com? TCP 3-way handshake, DNS resolution, L4 vs L7 LB.
  • Git: merge vs rebase, revert vs reset, resolving conflicts, branching strategies.
  • Docker: image vs container, layers, CMD vs ENTRYPOINT, reduce image size, multi-stage builds.
  • K8s: pod lifecycle, CrashLoopBackOff debugging, Deployment vs StatefulSet, Services types, HPA, taints/tolerations, RBAC.
  • Terraform: state, locking, drift, count vs for_each, modules, import, workspaces.
  • CI/CD: design a pipeline for microservices; blue-green vs canary; how to handle secrets in pipelines.
  • AWS: Security group vs NACL, IAM role vs user, S3 consistency/storage classes, high availability design.
  • SRE: SLI/SLO/error budget, incident handling, toil, postmortems.
  • Scenario: "Production is down after a deploy" — walk through detection, mitigation, rollback, RCA.
