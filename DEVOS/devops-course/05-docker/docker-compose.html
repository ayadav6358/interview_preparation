Docker Compose (Multi-container Apps)

Intermediate Docker & Containers

Concept (What & Why)

Ek YAML mein pura stack: web + api + db + redis. Local development aur small deployments ke liye best.

Definition Deep-Dive

QuestionAnswer
Simple definitionOne YAML file that starts your whole app stack with one command.
Technical definitionDocker Compose (v2 plugin, Compose Specification) declares services, networks and volumes in YAML and creates/updates them via the Docker Engine API on a single host.
Why does it exist?Repeatable multi-container environments.
What happens without it?Long docker run commands typed by hand and easy to forget.
When to useLocal development, testing, small single-host deployments.
When NOT to useMulti-node production needing self-healing/autoscaling: use Kubernetes/ECS.
Real-world analogyA conductor's score for the whole orchestra.

Diagram & Internal Working

docker-compose.yml
   ├── web (nginx)  :80 ──> api
   ├── api (node)   :3000 ──> db, redis
   ├── db (postgres) volume pgdata
   └── redis

How it works internally (diagram explained)

docker compose up reads the YAML, creates the project network, volumes, then builds/pulls images and starts services in dependency order. Names are prefixed with the project (folder) name. Service names become DNS names on the network. On re-run Compose compares config and recreates only changed services.

Install / Setup

docker compose version   # bundled with modern Docker

Configuration Explained Line by Line

Line-by-line: key parts of the 3-tier stack

api:
    build: ./api
    environment:
      DB_URL: postgres://app:secret@db:5432/app
    depends_on:
      db: { condition: service_healthy }
db:
    image: postgres:16
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL","pg_isready -U app"]
LineMeaning / WHY it exists
build: ./apiBuild the image from the Dockerfile in ./api (use image: to pull instead).
environment:Injects config as env variables; port is the container port 5432, not a host port.
db:5432db is the service name resolved by Compose DNS.
depends_on ... service_healthyWaits until the DB healthcheck passes, avoiding startup race conditions.
volumes: pgdata:...Persistent named volume for database files.
healthcheck testpg_isready tells Compose the DB accepts connections.

Practical Examples

3-tier stack

services:
  web:
    image: nginx:1.27
    ports: ["80:80"]
    volumes: ["./nginx.conf:/etc/nginx/conf.d/default.conf:ro"]
    depends_on: [api]
  api:
    build: ./api
    environment:
      DB_URL: postgres://app:secret@db:5432/app
      REDIS: redis:6379
    depends_on:
      db: { condition: service_healthy }
  db:
    image: postgres:16
    environment: { POSTGRES_USER: app, POSTGRES_PASSWORD: secret, POSTGRES_DB: app }
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL","pg_isready -U app"]
      interval: 5s
  redis:
    image: redis:7
volumes:
  pgdata:

Commands

docker compose up -d --build
docker compose ps; docker compose logs -f api
docker compose exec db psql -U app
docker compose down -v      # -v removes volumes

Important Commands Explained

docker compose up -d --build
What does it do?
Builds images if needed and starts all services in the background.
Important options
--build, --force-recreate, --scale svc=N, -f file, --profile.
Expected output
Container xxx Started for each service.
Common mistake
Editing code but forgetting --build.
Troubleshooting
Use docker compose config to validate and view the merged file.

Hands-On Lab

Lab Goal

Run a web + Redis stack with Compose.

Prerequisites

  • Docker with Compose v2 (docker compose version)

Step 1

mkdir demo && cd demo && printf 'services:\n  web:\n    image: nginx:1.27\n    ports: ["8080:80"]\n  cache:\n    image: redis:7-alpine\n' > compose.yml

Creates a minimal compose file.

Step 2

docker compose up -d

Creates network demo_default, pulls images, starts both services.

Step 3

docker compose ps && docker compose exec cache redis-cli ping

Both services Up; Redis replies PONG.

Step 4

docker compose down

Stops and removes containers and network. Add -v only if you also want to delete volumes.

Real-World Problems & Fixes (Troubleshooting)

Problem: API starts before DB is ready and crashes
Cause: depends_on only orders start
Fix: Use healthcheck + condition: service_healthy and retries in app.
Problem: Secrets in compose file committed
Cause: Hard-coded passwords
Fix: Use .env (gitignored) or Docker secrets.

Best Practices

Production

  • Use -f compose.yml -f compose.prod.yml overrides.
  • Do not commit .env with secrets.

Reliability

  • Set restart: unless-stopped and healthchecks.

Common Mistakes

DevOps mistakes

  • Using Compose for multi-node production.
  • Using down -v on a shared/persistent environment.

Hinglish Explanation

Compose se ek command mein poora stack start hota hai. depends_on sirf start order deta hai; DB ready hone ka wait chahiye to healthcheck + service_healthy lagao.

Memory Tricks

ConceptMemory trick

Version / Environment Notes

  • Use docker compose (v2). docker-compose v1 is end-of-life and the top-level version: key is obsolete.
  • Compose file name: compose.yaml is preferred; docker-compose.yml still works.

Interview Questions

Q1. Compose vs Kubernetes?

Compose: single host, simple. K8s: multi-node orchestration, self-healing, scaling.

Q2. depends_on guarantees readiness?

No, only start order unless healthcheck condition used.

Q3. How to override for prod?

Multiple files: -f compose.yml -f compose.prod.yml.

Q4. How to scale a service?

docker compose up -d --scale api=3 (needs no fixed host port).

Q5. Where are env variables loaded from?

environment:, env_file:, and .env for variable substitution.

Q6. How do you run different configs for dev and prod with Compose?

Base compose.yml plus override files (compose.prod.yml), env files and profiles.

Why: Environment management.

Real-world example: Dev mounts source; prod uses built image and no bind mounts.
