Secrets Management (Vault, Secrets Manager)

Intermediate DevSecOps & Security

Concept (What & Why)

Passwords, tokens, keys ko Git ya env files mein mat rakho. Secret manager use karo: rotation, audit, dynamic short-lived credentials.

Definition Deep-Dive

QuestionAnswer
Simple definitionKeeping passwords, tokens and keys out of code and giving them to apps safely at runtime.
Technical definitionSecrets managers (Vault, AWS Secrets Manager, Parameter Store) store encrypted secrets with access policies, audit logs, versioning and rotation; apps authenticate with machine identity (IAM role/K8s SA) to fetch them.
Why does it exist?Leaked secrets are a top breach cause.
What happens without it?Passwords in Git and env files.
When to useAll credentials.
When NOT to useLong-lived shared secrets.
Real-world analogyA bank vault with a logbook: you sign to borrow and it records everything.

Diagram & Internal Working

App --auth (K8s SA / IAM role)--> Vault / AWS Secrets Manager --> secret (or dynamic DB creds, TTL 1h)
K8s: External Secrets Operator syncs store -> K8s Secret ; audit log of every read

How it works internally (diagram explained)

App identity (IAM role or Kubernetes ServiceAccount token) > authenticates to Vault/Secrets Manager > policy checks > returns secret (or generates a dynamic credential with TTL) > audit log entry. Rotation replaces the secret and updates consumers; short TTL limits blast radius.

Install / Setup

# Vault dev server (learning only)
docker run -d --name vault -p 8200:8200 -e VAULT_DEV_ROOT_TOKEN_ID=root hashicorp/vault
export VAULT_ADDR=http://127.0.0.1:8200 VAULT_TOKEN=root
# External Secrets
helm repo add external-secrets https://charts.external-secrets.io && helm install eso external-secrets/external-secrets -n eso --create-namespace

Configuration Explained Line by Line

Vault policy and read explained

path "secret/data/app/prod/*" {
  capabilities = ["read"]
}
# CLI
vault kv put secret/app/prod/db username=app password=S3cr3t
vault kv get -field=password secret/app/prod/db
LineMeaning / WHY it exists
path secret/data/...KV v2 paths include data/ in policies.
capabilities readLeast privilege: read only.
vault kv put/getWrite and fetch a secret; never put real secrets in shell history in real environments.

Practical Examples

Vault KV + policy

vault kv put secret/myapp db_password=S3cret
vault kv get -field=db_password secret/myapp
cat > app.hcl <<EOF
path "secret/data/myapp" { capabilities = ["read"] }
EOF
vault policy write myapp app.hcl

External Secret (AWS Secrets Manager -> K8s)

apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata: { name: db }
spec:
  refreshInterval: 1h
  secretStoreRef: { name: aws, kind: ClusterSecretStore }
  target: { name: db-secret }
  data:
  - { secretKey: password, remoteRef: { key: prod/db, property: password } }

AWS CLI

aws secretsmanager create-secret --name prod/db --secret-string '{"password":"S3cret"}'
aws secretsmanager get-secret-value --secret-id prod/db --query SecretString --output text

Step 3

vault kv get secret/demo

Reads it back; versions and metadata are kept.

Real-World Problems & Fixes (Troubleshooting)

Problem: Secret rotation causes outage
Cause: Apps cache old password
Fix: Use dynamic secrets / reload on change / dual-credential rotation.
Problem: K8s Secrets visible to many
Cause: Broad RBAC, no encryption
Fix: Restrict RBAC, enable KMS encryption, use CSI/ESO.

Best Practices

Security

  • Rotation, dynamic secrets, audit logs, least-privilege policies.

Common Mistakes

Security mistakes

  • Secrets in env files in Git.
  • Root token usage.

Hinglish Explanation

Secret Git mein nahi, vault mein. App ko identity (role) se secret milna chahiye, aur secret short-lived ho toh behtar.

Interview Questions

Q1. Why not env vars for secrets?

They leak in logs/process listings/crash dumps; prefer mounted files or fetch at runtime.

Q2. Dynamic secrets?

Generated on demand with TTL (e.g. DB user per app instance), auto-revoked.

Q3. SOPS/Sealed Secrets use?

Encrypt secrets so they can live in Git safely (GitOps).

Q4. Vault auth methods?

Kubernetes, AWS IAM, AppRole, OIDC.

Q5. Envelope encryption?

Data key encrypts data; master key (KMS) encrypts data key.

Q6. How does an app running on EKS get DB credentials safely?

Use IRSA to assume a role that reads Secrets Manager (or Vault Kubernetes auth), inject via External Secrets/CSI at runtime, rotate automatically.

Why: Cloud-native secrets.

Real-world example: No static credentials in manifests.
