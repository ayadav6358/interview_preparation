S3, EBS, RDS & DynamoDB

Intermediate Cloud (AWS)

Concept (What & Why)

S3 object storage (static sites, backups, logs). RDS managed relational DB. DynamoDB serverless NoSQL.

Definition Deep-Dive

QuestionAnswer
Simple definitionS3 stores files, EBS is a server disk, RDS is a managed relational database, DynamoDB is a managed NoSQL database.
Technical definitionS3 is regional object storage (11 nines durability design); EBS is AZ-bound block storage; RDS runs managed engines with backups, patching and Multi-AZ; DynamoDB is a serverless key-value/document store.
Why does it exist?Use the right storage for each data type with managed reliability.
What happens without it?Self-managed backups and failover.
When to useAll data workloads.
When NOT to useUsing EBS as shared storage across AZs.
Real-world analogyS3 = warehouse, EBS = your laptop's SSD, RDS = a database run by a DBA service.

Diagram & Internal Working

S3: bucket -> objects (versioning, lifecycle: Standard -> IA -> Glacier), SSE-KMS, block public access
RDS: Primary (AZ a) <-sync-> Standby (AZ b)  [Multi-AZ failover]; Read replicas for scale

How it works internally (diagram explained)

RDS Multi-AZ writes synchronously to a standby in another AZ; on failure DNS flips to the standby. Read replicas replicate asynchronously. EBS snapshots are incremental and stored in S3. S3 stores objects redundantly across AZs and offers versioning and lifecycle rules.

Install / Setup

aws s3 ls; aws rds describe-db-instances

Configuration Explained Line by Line

S3 lifecycle rule explained

{
  "Rules": [{
    "ID": "logs",
    "Status": "Enabled",
    "Filter": {"Prefix": "logs/"},
    "Transitions": [{"Days": 30, "StorageClass": "STANDARD_IA"}, {"Days": 90, "StorageClass": "GLACIER"}],
    "Expiration": {"Days": 365}
  }]
}
LineMeaning / WHY it exists
Filter PrefixApplies only to logs/.
TransitionsCheaper storage classes over time.
ExpirationDelete after a year to control cost.

Practical Examples

S3 essentials

aws s3 mb s3://my-unique-bucket-123
aws s3 sync ./dist s3://my-unique-bucket-123 --delete
aws s3api put-bucket-versioning --bucket my-unique-bucket-123 --versioning-configuration Status=Enabled
aws s3 presign s3://my-unique-bucket-123/file.pdf --expires-in 600

Lifecycle rule

{"Rules":[{"ID":"archive","Status":"Enabled","Filter":{"Prefix":"logs/"},
 "Transitions":[{"Days":30,"StorageClass":"STANDARD_IA"},{"Days":90,"StorageClass":"GLACIER"}],
 "Expiration":{"Days":365}}]}

RDS backup and restore

aws rds create-db-snapshot --db-instance-identifier prod --db-snapshot-identifier prod-2025-01-01
aws rds restore-db-instance-to-point-in-time --source-db-instance-identifier prod --target-db-instance-identifier prod-restore --restore-time 2025-01-01T10:00:00Z

Hands-On Lab

Lab Goal

Use S3 and create a snapshot.

Prerequisites

  • AWS CLI configured

Step 1

aws s3 mb s3://my-unique-bucket-12345 && echo hi > a.txt && aws s3 cp a.txt s3://my-unique-bucket-12345/

Creates a bucket (Block Public Access is on by default) and uploads.

Step 2

aws s3api put-bucket-versioning --bucket my-unique-bucket-12345 --versioning-configuration Status=Enabled

Protects against accidental deletes.

Step 3

aws s3 rb s3://my-unique-bucket-12345 --force

Cleanup to avoid charges.

Real-World Problems & Fixes (Troubleshooting)

Problem: Company data exposed via public S3 bucket
Cause: Public ACL/policy
Fix: Enable account-level Block Public Access, use CloudFront OAC, Access Analyzer/Config rules.
Problem: RDS CPU 100%
Cause: Missing indexes / connection storm
Fix: Performance Insights, slow query log, RDS Proxy, read replicas.

Best Practices

Security

  • Encryption at rest/in transit, private access, Block Public Access.

Backup & Disaster Recovery

  • Automated backups, snapshots, versioning, cross-region copy.

Common Mistakes

Production mistakes

  • No restore test.
  • Public bucket or DB.

Hinglish Explanation

Database ko RDS Multi-AZ mein chalao, backups on rakho aur restore test karo. S3 bucket kabhi public mat rakho.

ConceptMemory trick
Choose storageObject=S3, Block=EBS, File=EFS, SQL=RDS, Key-value=DynamoDB

Interview Questions

Q1. S3 storage classes?

Standard, IA, One Zone-IA, Glacier tiers, Intelligent-Tiering.

Q2. Multi-AZ vs read replica?

Multi-AZ for HA/failover (sync); read replica for read scaling (async).

Q3. How to secure S3?

Block public access, bucket policy, encryption, versioning, MFA delete, logging.

Q4. DynamoDB partition key importance?

Even distribution avoids hot partitions.

Q5. EBS snapshots?

Incremental backups stored in S3; used for backup/AMI.

Q6. How to restore an accidentally deleted S3 object?

If versioning was on, remove the delete marker or restore a previous version; otherwise restore from backup/replication.

Why: Data protection.

Real-world example: Enable versioning up front.
