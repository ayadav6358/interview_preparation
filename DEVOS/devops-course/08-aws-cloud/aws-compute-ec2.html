EC2, Auto Scaling & Load Balancing

Intermediate Cloud (AWS)

Concept (What & Why)

EC2 virtual servers hain. ASG instances ko scale/replace karta hai, ALB traffic distribute karta hai. Classic 3-tier HA pattern.

Definition Deep-Dive

QuestionAnswer
Simple definitionEC2 gives you virtual servers; Auto Scaling adds/removes them; a load balancer spreads traffic.
Technical definitionEC2 instances launch from AMIs using launch templates; ASGs maintain capacity across AZs using scaling policies; ELB distributes traffic and performs health checks.
Why does it exist?Elastic, resilient compute.
What happens without it?Fixed servers that fail or over-provision.
When to useLong-running or custom OS workloads.
When NOT to useSimple event tasks better on Lambda.
Real-world analogyA taxi fleet that grows during rush hour.

Diagram & Internal Working

Route53 -> ALB (public subnets, 2 AZ) -> Target Group -> ASG (private subnets)
                                              |         EC2 (launch template: AMI, user-data, IAM role)
                                            health checks -> replace unhealthy
Scaling policy: target tracking CPU 50%

How it works internally (diagram explained)

ASG desired capacity > launches instances from the launch template in chosen subnets > registers them with the target group > ALB health checks mark them healthy > traffic flows. If an instance fails checks, ASG terminates and replaces it. Scaling policies (target tracking) adjust desired capacity based on CloudWatch metrics.

Install / Setup

aws ec2 describe-instance-types --filters Name=free-tier-eligible,Values=true --query 'InstanceTypes[].InstanceType'

Practical Examples

Launch instance with user-data

aws ec2 run-instances --image-id ami-xxxx --instance-type t3.micro \
  --subnet-id subnet-123 --security-group-ids sg-123 --iam-instance-profile Name=app-role \
  --user-data file://userdata.sh --tag-specifications 'ResourceType=instance,Tags=[{Key=Env,Value=dev}]'

# userdata.sh
#!/bin/bash
apt update && apt install -y nginx
systemctl enable --now nginx

Target tracking policy

aws autoscaling put-scaling-policy --auto-scaling-group-name web-asg --policy-name cpu50 \
  --policy-type TargetTrackingScaling \
  --target-tracking-configuration '{"PredefinedMetricSpecification":{"PredefinedMetricType":"ASGAverageCPUUtilization"},"TargetValue":50}'

Hands-On Lab

Lab Goal

Launch a web server with an ALB.

Prerequisites

  • VPC with 2 public subnets
  • Budget alert

Step 1

Create launch template with the user data above (t3.micro, AL2023, SG allowing 80 from ALB SG)

Repeatable instance definition.

Step 2

Create target group (HTTP 80, health check /) and ALB in public subnets

ALB DNS becomes the entry point.

Step 3

Create ASG min 2/max 4 across two AZs attached to the target group; then terminate one instance

ASG replaces it automatically: self-healing.

Real-World Problems & Fixes (Troubleshooting)

Problem: New instance passes health check but app fails
Cause: Health check on wrong path / too early
Fix: Use app-level /health, grace period, warm-up.
Problem: Can't SSH to instance
Cause: SG closed / wrong key / no public IP
Fix: Use SSM Session Manager (no SSH keys/ports needed).

Best Practices

Security

  • IMDSv2, SSM instead of SSH, instance roles.

Cost Optimization

  • Savings Plans, Spot, Graviton, right-sizing.

Common Mistakes

Production mistakes

  • Single instance without ASG.
  • Manual config drift.

Hinglish Explanation

Instance ko manually mat banao; Launch template + Auto Scaling group use karo, taaki fail hone par khud replace ho jaye.

Interview Questions

Q1. On-demand vs reserved vs spot?

On-demand pay as you go; Reserved/Savings Plans commit for discount; Spot cheap but can be reclaimed.

Q2. ALB vs NLB?

ALB L7 HTTP routing; NLB L4 ultra-low latency, static IP.

Q3. What is an AMI?

Machine image template used to launch instances.

Q4. Instance store vs EBS?

Instance store ephemeral, EBS persistent network disk.

Q5. How to make app highly available?

Multi-AZ ASG behind ALB, multi-AZ DB, stateless app.

Q6. Zero-downtime deployment on ASG?

Use instance refresh or blue/green with new launch template versions, ALB health checks and minimum healthy percentage.

Why: Release strategy.

Real-world example: Rolling instance refresh 90%.
