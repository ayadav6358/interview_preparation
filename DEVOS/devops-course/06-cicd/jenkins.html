Jenkins

Intermediate CI/CD

Concept (What & Why)

Sabse popular self-hosted CI server. Jenkinsfile (pipeline as code), agents, plugins. Enterprises mein abhi bhi bahut use hota hai.

Definition Deep-Dive

QuestionAnswer
Simple definitionJenkins is a server you host that runs your build and deploy jobs.
Technical definitionJenkins is a Java-based automation server: a controller manages jobs, credentials and plugins; agents execute builds. Pipelines are defined in a Jenkinsfile (Declarative or Scripted Groovy).
Why does it exist?Flexible, self-hosted CI/CD with a huge plugin ecosystem.
What happens without it?Custom scripts and cron jobs.
When to useComplex/legacy or on-premises environments.
When NOT to useIf you want zero maintenance: use a managed CI.
Real-world analogyA factory manager (controller) assigning work to workers (agents).

Diagram & Internal Working

Git webhook -> Jenkins Controller -> schedules on Agents (VM/K8s pods)
                    |                      |
              Jenkinsfile stages     build, test, docker, deploy

How it works internally (diagram explained)

SCM webhook/poll > controller queues the build > allocates an executor on a matching agent (label) > agent checks out code and runs stages > results, artifacts and reports are sent to the controller > post actions (notify). Credentials are stored encrypted on the controller and injected into builds with masking. Kubernetes plugin can create a Pod per build as an ephemeral agent.

Install / Setup

# Docker (quick)
docker run -d --name jenkins -p 8080:8080 -p 50000:50000 -v jenkins_home:/var/jenkins_home jenkins/jenkins:lts
docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword

Configuration Explained Line by Line

Declarative Jenkinsfile explained

pipeline {
  agent { label 'docker' }
  environment { IMAGE = "registry.example.com/shop/api:${env.GIT_COMMIT}" }
  options { timeout(time: 30, unit: 'MINUTES'); disableConcurrentBuilds() }
  stages {
    stage('Test')  { steps { sh 'npm ci && npm test' } }
    stage('Sonar') { steps { withSonarQubeEnv('sonar') { sh 'sonar-scanner' } } }
    stage('Gate')  { steps { timeout(time: 5, unit: 'MINUTES') { waitForQualityGate abortPipeline: true } } }
    stage('Build') { steps { sh 'docker build -t $IMAGE .' } }
    stage('Scan')  { steps { sh 'trivy image --exit-code 1 --severity HIGH,CRITICAL $IMAGE' } }
    stage('Push')  { steps { withCredentials([usernamePassword(credentialsId: 'registry', usernameVariable: 'U', passwordVariable: 'P')]) {
      sh 'echo $P | docker login registry.example.com -u $U --password-stdin && docker push $IMAGE' } } }
  }
  post { failure { echo 'notify Slack' } always { cleanWs() } }
}
LineMeaning / WHY it exists
agent { label 'docker' }Run on an agent that has Docker; keeps builds off the controller.
environmentPipeline-wide variables; tagged with the commit SHA.
options timeout/disableConcurrentBuildsPrevents hung builds and overlapping deployments.
withSonarQubeEnv + waitForQualityGateRuns analysis and blocks the pipeline until the quality gate returns.
trivy --exit-code 1Fails the build on HIGH/CRITICAL vulnerabilities.
withCredentialsInjects registry credentials securely and masks them in logs.
postRuns after stages: notify on failure, always clean the workspace.

Practical Examples

Declarative Jenkinsfile

pipeline {
  agent any
  environment { IMAGE = "myrepo/app:${env.GIT_COMMIT[0..6]}" }
  options { timeout(time: 30, unit: 'MINUTES'); disableConcurrentBuilds() }
  stages {
    stage('Test')  { steps { sh 'npm ci && npm test' } }
    stage('Build') { steps { sh 'docker build -t $IMAGE .' } }
    stage('Push')  {
      steps { withCredentials([usernamePassword(credentialsId:'dockerhub', usernameVariable:'U', passwordVariable:'P')]) {
        sh 'echo $P | docker login -u $U --password-stdin && docker push $IMAGE' } }
    }
    stage('Deploy') {
      when { branch 'main' }
      steps { input 'Deploy to prod?'; sh './deploy.sh prod $IMAGE' }
    }
  }
  post { failure { echo 'Notify Slack' } always { cleanWs() } }
}

docker run -d --name jenkins -p 8080:8080 -p 50000:50000 -v jenkins_home:/var/jenkins_home jenkins/jenkins:lts

Real-World Problems & Fixes (Troubleshooting)

Problem: Jenkins slow / builds queue
Cause: Everything on controller, too few agents
Fix: Use ephemeral agents (K8s plugin), 0 executors on controller.
Problem: Plugin upgrade broke Jenkins
Cause: Uncontrolled plugin updates
Fix: Pin versions, test in staging, back up JENKINS_HOME, use JCasC.

Best Practices

Security

  • Keep Jenkins and plugins updated; disable script approvals abuse; use RBAC/SSO; zero executors on controller.

Reliability

  • Configuration as Code (JCasC), backup JENKINS_HOME, Pipeline as code.

Common Mistakes

DevOps mistakes

  • Manual UI config (snowflake)
  • Building on the controller
  • Never updating plugins

Hinglish Explanation

Jenkins mein controller sirf manage karta hai, build agent par chalta hai. Credentials withCredentials se use karo, kabhi Jenkinsfile mein password mat likho.

Interview Questions

Q1. Declarative vs scripted pipeline?

Declarative: structured, simpler; Scripted: full Groovy flexibility.

Q2. How to store credentials?

Jenkins Credentials store + withCredentials, or external Vault.

Q3. What is a Jenkins agent?

Node executing jobs, connected via SSH/JNLP or spawned dynamically.

Q4. How to trigger builds?

SCM webhooks, cron, upstream jobs, manual.

Q5. What is JCasC?

Jenkins Configuration as Code YAML to reproduce setup.

Q6. Jenkins build stuck 'waiting for next available executor'.

No agent with the required label/free executor; check node status, labels and agent connectivity or add dynamic agents.

Why: Capacity issue.

Real-world example: Label typo dokcer.
