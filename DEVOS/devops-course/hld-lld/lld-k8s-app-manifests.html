LLD 3: Kubernetes App Manifests (Production Grade)

Advanced HLD & LLD (Design + Diagrams + Real Examples)

Concept (What & Why)

Deployment + Service + Ingress + HPA + PDB + NetworkPolicy + ServiceAccount: production checklist wala YAML.

Definition Deep-Dive

QuestionAnswer
Simple definitionProduction-ready Kubernetes YAML for one application: deployment, service, ingress, autoscaling and protections.
Technical definitionA complete manifest set with resource requests/limits, probes, rolling update strategy, PDB, HPA, NetworkPolicy, dedicated ServiceAccount and securityContext.
Why does it exist?Predictable, safe, secure workloads.
What happens without it?Defaults that allow outages and privilege.
When to useEvery production service.
When NOT to useCopy without adjusting numbers.
Real-world analogyA pre-flight checklist for the application.

Diagram & Internal Working

Ingress(host) -> Service -> Deployment(3 pods, probes, limits, non-root, spread across zones)
HPA 3..15 (CPU 70%) | PDB minAvailable 2 | NetworkPolicy: only ingress-nginx -> app ; app -> db

How it works internally (diagram explained)

Deployment maintains replicas and rolls out safely (maxUnavailable 0). Readiness gates traffic, liveness restarts hung pods, startup protects slow starts. HPA scales pods on CPU; PDB keeps minimum pods during node drains; NetworkPolicy restricts traffic; ServiceAccount + securityContext limit privileges.

Install / Setup

kubectl apply -f app.yaml -n prod   # or via Helm chart / ArgoCD

Configuration Explained Line by Line

Production Deployment explained

apiVersion: apps/v1
kind: Deployment
metadata: { name: api, namespace: shop, labels: { app: api } }
spec:
  replicas: 3
  strategy: { type: RollingUpdate, rollingUpdate: { maxSurge: 1, maxUnavailable: 0 } }
  selector: { matchLabels: { app: api } }
  template:
    metadata: { labels: { app: api } }
    spec:
      serviceAccountName: api
      securityContext: { runAsNonRoot: true, seccompProfile: { type: RuntimeDefault } }
      topologySpreadConstraints:
      - { maxSkew: 1, topologyKey: topology.kubernetes.io/zone, whenUnsatisfiable: ScheduleAnyway, labelSelector: { matchLabels: { app: api } } }
      containers:
      - name: api
        image: registry.example.com/shop/api:3fa9c1d
        ports: [{ containerPort: 8080 }]
        resources: { requests: { cpu: 200m, memory: 256Mi }, limits: { memory: 512Mi } }
        readinessProbe: { httpGet: { path: /ready, port: 8080 }, periodSeconds: 5 }
        livenessProbe: { httpGet: { path: /live, port: 8080 }, initialDelaySeconds: 20, periodSeconds: 10 }
        startupProbe: { httpGet: { path: /live, port: 8080 }, failureThreshold: 30, periodSeconds: 2 }
        securityContext: { allowPrivilegeEscalation: false, readOnlyRootFilesystem: true, capabilities: { drop: [ALL] } }
        lifecycle: { preStop: { exec: { command: ["sleep","10"] } } }
LineMeaning / WHY it exists
maxUnavailable: 0Never reduce capacity during updates.
serviceAccountNameDedicated identity for least-privilege RBAC/IRSA.
runAsNonRoot / seccompPod-level hardening.
topologySpreadConstraintsSpread pods across zones for AZ failure tolerance.
image tag SHAImmutable version.
requests/limitsScheduling and protection; CPU limit omitted deliberately to avoid throttling (a design choice: adjust to policy).
readiness/liveness/startupTraffic gating, self-healing, slow-start protection.
readOnlyRootFilesystem/drop ALLContainer hardening.
preStop sleepLets the load balancer drain connections before shutdown.

Companion objects explained

apiVersion: policy/v1
kind: PodDisruptionBudget
metadata: { name: api, namespace: shop }
spec: { minAvailable: 2, selector: { matchLabels: { app: api } } }
---
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata: { name: api, namespace: shop }
spec:
  scaleTargetRef: { apiVersion: apps/v1, kind: Deployment, name: api }
  minReplicas: 3
  maxReplicas: 12
  metrics: [{ type: Resource, resource: { name: cpu, target: { type: Utilization, averageUtilization: 70 } } }]
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: api, namespace: shop }
spec:
  podSelector: { matchLabels: { app: api } }
  policyTypes: [Ingress]
  ingress: [{ from: [{ namespaceSelector: { matchLabels: { name: ingress-nginx } } }], ports: [{ port: 8080 }] }]
LineMeaning / WHY it exists
PDB minAvailable: 2Node drains cannot take the service below two pods.
HPA min 3 / max 12Baseline HA and burst capacity.
averageUtilization 70Scale before saturation (relative to requests).
NetworkPolicy ingressOnly the ingress controller namespace can reach the API pods (needs a policy-enforcing CNI).

Practical Examples

Production Deployment

apiVersion: apps/v1
kind: Deployment
metadata: { name: myapp, namespace: prod }
spec:
  replicas: 3
  strategy: { type: RollingUpdate, rollingUpdate: { maxSurge: 1, maxUnavailable: 0 } }
  selector: { matchLabels: { app: myapp } }
  template:
    metadata: { labels: { app: myapp } }
    spec:
      serviceAccountName: myapp
      securityContext: { runAsNonRoot: true, seccompProfile: { type: RuntimeDefault } }
      topologySpreadConstraints:
      - { maxSkew: 1, topologyKey: topology.kubernetes.io/zone, whenUnsatisfiable: ScheduleAnyway, labelSelector: { matchLabels: { app: myapp } } }
      terminationGracePeriodSeconds: 30
      containers:
      - name: myapp
        image: 123456789012.dkr.ecr.ap-south-1.amazonaws.com/myapp:abc123
        ports: [{ containerPort: 3000 }]
        envFrom: [{ secretRef: { name: myapp-secrets } }]
        resources: { requests: { cpu: 200m, memory: 256Mi }, limits: { memory: 512Mi } }
        readinessProbe: { httpGet: { path: /ready, port: 3000 }, periodSeconds: 5 }
        livenessProbe:  { httpGet: { path: /health, port: 3000 }, initialDelaySeconds: 15 }
        lifecycle: { preStop: { exec: { command: ["sleep","10"] } } }
        securityContext: { allowPrivilegeEscalation: false, readOnlyRootFilesystem: true, capabilities: { drop: [ALL] } }

NetworkPolicy allowing only ingress controller

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: myapp-allow-ingress, namespace: prod }
spec:
  podSelector: { matchLabels: { app: myapp } }
  policyTypes: [Ingress]
  ingress:
  - from: [{ namespaceSelector: { matchLabels: { kubernetes.io/metadata.name: ingress-nginx } } }]
    ports: [{ port: 3000 }]

Hands-On Lab

Lab Goal

Validate manifests without changing the cluster.

Prerequisites

  • kubectl
  • Cluster or kind

Step 1

kubectl apply --dry-run=server -f k8s/

Validates against the real API server schema/admission.

Step 2

kubectl apply -f k8s/ && kubectl -n shop rollout status deploy/api

Apply and watch rollout.

Step 3

kubectl -n shop get pdb,hpa,networkpolicy

Verify companion objects exist.

Real-World Problems & Fixes (Troubleshooting)

Problem: 502 errors during rollout
Cause: Traffic sent to terminating pods
Fix: preStop sleep + readiness + grace period so LB deregisters first.

Best Practices

Production

  • Zone spread, PDB, HPA, graceful shutdown.

Security

  • Non-root, drop caps, read-only FS, NetworkPolicy.

Common Mistakes

Production mistakes

  • No readiness probe.
  • Single replica.

Interview Questions

Q1. Why memory limit but no CPU limit?

CPU limits cause throttling; memory is incompressible so limit prevents node OOM.

Q2. Why readOnlyRootFilesystem?

Stops attackers writing binaries; mount emptyDir for temp.

Q3. What does maxUnavailable: 0 ensure?

Old pods removed only after new are ready.

Q4. Why topology spread?

Survive AZ failure.

Q5. Why ServiceAccount per app?

Least-privilege RBAC and IRSA mapping.

Q6. Why is preStop: sleep used?

Endpoints and load balancers update asynchronously; sleeping keeps the pod serving briefly after termination starts so in-flight requests/new connections still succeed while it is removed from rotation.

Why: Graceful shutdown.

Real-world example: Eliminated 502s during rollouts.
