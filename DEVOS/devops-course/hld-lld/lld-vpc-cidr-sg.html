LLD 1: VPC Subnets, CIDR & Security Group Rules

Intermediate HLD & LLD (Design + Diagrams + Real Examples)

Concept (What & Why)

HLD ka network ab exact numbers ke saath.

Definition Deep-Dive

QuestionAnswer
Simple definitionThe exact IP ranges and firewall rules for the network design.
Technical definitionLLD network specification: VPC and subnet CIDRs per AZ/tier, route tables, gateways, security group rules using SG references, NACL policy, endpoints and flow logs.
Why does it exist?Implementable, reviewable network.
What happens without it?Ad-hoc addressing and open rules.
When to useEvery VPC.
When NOT to useOverlapping CIDRs and 0.0.0.0/0 on internal tiers.
Real-world analogyStreet map with exact house numbers and gate rules.

Diagram & Internal Working

VPC 10.0.0.0/16
 public-a  10.0.1.0/24  (ALB, NAT-a)      public-b  10.0.2.0/24 (ALB, NAT-b)
 private-a 10.0.11.0/24 (app/EKS nodes)   private-b 10.0.12.0/24
 db-a      10.0.21.0/24 (RDS)             db-b      10.0.22.0/24

RT public : 0.0.0.0/0 -> IGW
RT private: 0.0.0.0/0 -> NAT (same AZ)
RT db     : local only

How it works internally (diagram explained)

Route tables decide next hops per subnet: public to IGW, app to NAT (per AZ), DB local only. Security groups are stateful and evaluated at each ENI: ALB SG allows internet 443; app SG allows app port from ALB SG; DB SG allows DB port from app SG. NACLs are a coarse stateless second layer.

Install / Setup

# Terraform module vpc (Terraform topic)

Configuration Explained Line by Line

Terraform snippet for SG chaining explained

resource "aws_security_group" "app" {
  name   = "app-sg"
  vpc_id = aws_vpc.main.id
  ingress {
    from_port       = 8080
    to_port         = 8080
    protocol        = "tcp"
    security_groups = [aws_security_group.alb.id]
  }
  egress { from_port = 0 to_port = 0 protocol = "-1" cidr_blocks = ["0.0.0.0/0"] }
}
LineMeaning / WHY it exists
security_groups = [alb.id]Only traffic from the ALB's SG is allowed: no IP lists to maintain.
port 8080Application port only.
egress allAllows outbound (updates/APIs); tighten with endpoints/egress rules for strict environments.

Practical Examples

Security group matrix

sg-alb : in 443 from 0.0.0.0/0 ; out all
sg-app : in 3000 from sg-alb ; out 5432 to sg-db, 6379 to sg-redis, 443 to 0.0.0.0/0 (via NAT)
sg-db  : in 5432 from sg-app ; no outbound needed
sg-bastion/SSM: prefer SSM Session Manager, no inbound 22

Terraform SG snippet

resource "aws_security_group_rule" "db_from_app" {
  type = "ingress"  from_port = 5432  to_port = 5432  protocol = "tcp"
  security_group_id        = aws_security_group.db.id
  source_security_group_id = aws_security_group.app.id
}

Hands-On Lab

Lab Goal

Validate an address plan with Python.

Prerequisites

  • Python 3

Step 1

python3 -c "import ipaddress as i; v=i.ip_network('10.0.0.0/16'); subs=['10.0.0.0/24','10.0.1.0/24','10.0.10.0/24','10.0.11.0/24','10.0.20.0/24','10.0.21.0/24']; print(all(i.ip_network(s).subnet_of(v) for s in subs))"

All subnets fit inside the VPC: True.

Step 2

python3 -c "import ipaddress as i, itertools; s=[i.ip_network(x) for x in ['10.0.0.0/24','10.0.1.0/24','10.0.10.0/24']]; print(any(a.overlaps(b) for a,b in itertools.combinations(s,2)))"

Checks for overlaps: False is good.

Real-World Problems & Fixes (Troubleshooting)

Problem: App can't reach RDS
Cause: SG on DB missing rule from app SG
Fix: Check SG reference, route, DB endpoint DNS, nc -zv db 5432 from app.

Best Practices

Security

  • Chain SGs; endpoints; flow logs.

Security group mein IP nahi, SG ka reference do (ALB SG se app SG). DB ko internet route mat do. CIDR overlap check karo.

Interview Questions

Q1. Why reference SG instead of CIDR?

Follows instances as they scale; tighter.

Q2. Why NAT per AZ?

Avoid cross-AZ dependency and data charges; AZ failure isolation.

Q3. How many IPs does AWS reserve per subnet?

5.

Q4. How do private instances get patches?

NAT or VPC endpoints/mirror repo.

Q5. NACL use case?

Coarse subnet-level deny (e.g. block an IP range).

Q6. Why one NAT gateway per AZ?

A single NAT is an AZ dependency and cross-AZ data path; per-AZ NATs keep each AZ independent at a higher fixed cost.

Why: HA vs cost.

Real-world example: Prod uses 2 NATs, dev uses 1.
