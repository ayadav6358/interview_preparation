Real Use Cases: Hardening, Patching, Packer & AWX

Advanced Configuration Management: Ansible

Concept (What & Why)

Production mein Ansible: server hardening, patching, AMI baking (Packer), testing (Molecule), aur AWX UI.

Definition Deep-Dive

QuestionAnswer
Simple definitionReal uses: harden servers, patch fleets, build images with Packer, run everything centrally with AWX.
Technical definitionHardening roles enforce baseline settings (SSH, sysctl, auditd); patching playbooks use serial batches with health checks; Packer's Ansible provisioner builds golden images; AWX adds RBAC, scheduling and logging.
Why does it exist?Turn theory into operations.
What happens without it?Ad-hoc, risky changes.
When to useFleet operations.
When NOT to usePatching all hosts at once.
Real-world analogyA maintenance crew following a checklist bay by bay.

Diagram & Internal Working

Packer + Ansible -> Golden AMI -> Terraform launches ASG with AMI
Nightly: Ansible patch playbook (serial) -> verify -> report
Molecule: role -> docker instance -> converge -> verify (CI)

How it works internally (diagram explained)

Rolling patch: for each batch (serial) the play removes hosts from the load balancer (delegate to LB), updates packages, reboots if required, waits for health, re-adds hosts, and stops if failures exceed max_fail_percentage. Packer starts a temporary instance, runs the Ansible provisioner, creates an AMI and terminates the builder.

Install / Setup

pip install molecule molecule-plugins[docker] ansible-lint
winget/apt install packer

Configuration Explained Line by Line

Rolling patch play explained

- hosts: web
  serial: "20%"
  max_fail_percentage: 10
  become: true
  tasks:
    - name: Upgrade packages
      ansible.builtin.apt: { upgrade: dist, update_cache: true }
      register: up
    - name: Reboot if required
      ansible.builtin.reboot:
      when: up.changed
    - name: Health check
      ansible.builtin.uri: { url: "http://{{ inventory_hostname }}/health", status_code: 200 }
      delegate_to: localhost
      retries: 10
      delay: 5
LineMeaning / WHY it exists
serial: 20%Patch a fifth of the fleet at a time.
max_fail_percentageAbort if too many hosts fail.
register/whenReboot only when something changed.
uri health checkProves the host is healthy before the next batch.
delegate_to: localhostRun the check from the control node.

Practical Examples

Hardening tasks

- name: Disable root SSH and passwords
  lineinfile: { path: /etc/ssh/sshd_config, regexp: '^#?{{ item.k }}', line: '{{ item.k }} {{ item.v }}' }
  loop: [{ k: PermitRootLogin, v: 'no' }, { k: PasswordAuthentication, v: 'no' }]
  notify: reload ssh
- name: Enable UFW
  ufw: { state: enabled, policy: deny }
- ufw: { rule: allow, port: '22', proto: tcp }

Packer template using Ansible

source "amazon-ebs" "ubuntu" {
  region = "ap-south-1"; instance_type = "t3.micro"
  source_ami_filter { filters = { name = "ubuntu/images/*22.04-amd64-server-*" } owners = ["099720109477"] most_recent = true }
  ssh_username = "ubuntu"; ami_name = "app-{{timestamp}}"
}
build {
  sources = ["source.amazon-ebs.ubuntu"]
  provisioner "ansible" { playbook_file = "site.yml" }
}

ansible-lint site.yml

Real-World Problems & Fixes (Troubleshooting)

Problem: Patching reboots all servers together
Cause: No serial/ordering
Fix: serial: 20%, reboot with reboot module and health check.
Problem: Playbook takes hours on 500 hosts
Cause: Default forks=5, gather_facts
Fix: Raise forks, gather_facts: false, pipelining, mitogen.

Best Practices

Reliability

  • serial, health checks, max_fail_percentage.

Security

  • Use maintained hardening roles; document exceptions.

Common Mistakes

Production mistakes

  • No serial: outage risk.

Hinglish Explanation

Patching batch mein karo (serial) aur har batch ke baad health check. Sab servers ek saath patch mat karo.

Version / Environment Notes

  • ansible.builtin.reboot requires Ansible 2.7+. Packer's Ansible provisioner and AMI builder options change by version; consult the docs.

Interview Questions

Q1. Mutable vs immutable infra?

Mutable: patch in place (Ansible). Immutable: bake new image and replace (Packer+ASG).

Q2. What is AWX?

Open-source web UI/API/RBAC for Ansible (upstream of Automation Controller).

Q3. How to test roles?

Molecule with Docker/Vagrant, ansible-lint, CI.

Q4. Pull mode?

ansible-pull runs from Git on the node itself via cron.

Q5. Performance tips?

forks, pipelining, fact caching, async tasks, strategy free.

Q6. How would you keep Ansible-built servers from drifting?

Prefer immutable golden images built with Packer and replaced on change; otherwise schedule check-mode runs/AWX jobs to detect and correct drift and restrict manual SSH.

Why: Long-term ops.

Real-world example: Nightly drift report.
