Roles, Templates, Variables & Vault

Intermediate Configuration Management: Ansible

Concept (What & Why)

Playbook bada ho jaye to roles mein todo. Jinja2 templates se config files generate karo. Vault se secrets encrypt karo.

Definition Deep-Dive

QuestionAnswer
Simple definitionRoles package reusable automation; templates make config files from variables; Vault encrypts secrets.
Technical definitionRoles follow a standard layout loaded automatically by Ansible; Jinja2 templates are rendered on the control node; Vault uses AES256 to encrypt vars/files.
Why does it exist?Reusability and clean structure.
What happens without it?Copy-pasted, unmaintainable playbooks.
When to useAll non-trivial automation.
When NOT to useOver-nesting roles.
Real-world analogyRoles are reusable recipe cards; templates are recipe cards with blanks to fill.

Diagram & Internal Working

roles/nginx/
  ├── tasks/main.yml
  ├── handlers/main.yml
  ├── templates/nginx.conf.j2
  ├── defaults/main.yml   (lowest precedence vars)
  └── vars/ , files/ , meta/

How it works internally (diagram explained)

When a play includes a role, Ansible loads defaults/main.yml (lowest precedence vars), vars/main.yml, then runs tasks/main.yml; handlers are registered from handlers/main.yml; template: looks in templates/. Vault-encrypted files are decrypted in memory with the supplied password.

Install / Setup

ansible-galaxy init roles/nginx
ansible-galaxy install geerlingguy.docker

Configuration Explained Line by Line

Role layout explained

roles/nginx/
  defaults/main.yml   # default variables (easy to override)
  tasks/main.yml      # what to do
  handlers/main.yml   # restart/reload actions
  templates/*.j2      # config files with variables
  files/              # static files
  meta/main.yml       # dependencies
LineMeaning / WHY it exists
defaultsLowest precedence: safe defaults callers can override.
tasksEntry point.
handlersTriggered by notify.
templatesRendered with Jinja2.
metaRole dependencies and metadata.

Practical Examples

Template

# templates/app.conf.j2
server {
  listen {{ http_port }};
  server_name {{ domain }};
  location / { proxy_pass http://127.0.0.1:{{ app_port }}; }
}
# task
- template: { src: app.conf.j2, dest: /etc/nginx/conf.d/app.conf, validate: 'nginx -t -c /etc/nginx/nginx.conf' }
  notify: reload nginx

Loops, conditions, tags

- apt: { name: "{{ item }}", state: present }
  loop: [git, curl, htop]
  when: ansible_os_family == "Debian"
  tags: [packages]
# ansible-playbook site.yml --tags packages --limit web1

Vault

ansible-vault create group_vars/prod/vault.yml
ansible-playbook site.yml --ask-vault-pass    # or --vault-password-file

Rolling update

- hosts: web
  serial: 1          # one server at a time
  max_fail_percentage: 0
  tasks: [ ... ]

Hands-On Lab

Lab Goal

Create a role and encrypt a secret.

Prerequisites

  • Ansible

Step 1

ansible-galaxy init roles/nginx

Creates the standard structure.

Step 2

printf 'db_password: s3cret\n' > vault.yml && ansible-vault encrypt vault.yml

Encrypts; the file now looks like $ANSIBLE_VAULT;1.1;AES256...

Step 3

ansible-playbook site.yml -e @vault.yml --ask-vault-pass

Uses the secret at runtime without it being stored in plain text.

Real-World Problems & Fixes (Troubleshooting)

Problem: Variable precedence confusion
Cause: Same var defined in many places
Fix: Keep defaults in role, env values in group_vars; use ansible-inventory --host.
Problem: Config change broke nginx on all servers
Cause: No validation, no serial
Fix: Use validate:, serial, --check.

Interview Questions

Q1. What is a role?

Reusable structured unit of tasks, templates, vars.

Q2. Ansible Galaxy?

Repository of community roles/collections.

Q3. How do you keep secrets safe?

Ansible Vault or external secret lookup (Vault, AWS SSM).

Q4. Dynamic inventory?

Inventory generated from cloud API (aws_ec2 plugin).

Q5. How to do zero-downtime rolling update?

serial, drain from LB with delegate_to, health-check before next batch.

Q6. Where should default values live in a role?

defaults/main.yml, so users can override them easily; vars/ is high precedence and hard to override.

Why: Role design.

Real-world example: nginx_port default.
