Prometheus & PromQL

Intermediate Monitoring, Logging & Observability

Concept (What & Why)

Pull-based metrics system. Targets ko scrape karta hai, time-series DB mein store. PromQL query language. Kubernetes ka de-facto standard.

Definition Deep-Dive

QuestionAnswer
Simple definitionPrometheus collects numbers about your systems and lets you query and alert on them.
Technical definitionPrometheus scrapes HTTP endpoints (text exposition format) on an interval, stores samples in a local time-series database and evaluates PromQL alert/recording rules; service discovery finds targets dynamically.
Why does it exist?Reliable metric collection with a powerful query language.
What happens without it?No trend or alert data.
When to useInfrastructure and application metrics.
When NOT to useLong-term storage without remote write; log storage.
Real-world analogyA reporter who visits every service every 15 seconds and writes down its numbers.

Diagram & Internal Working

[node_exporter][app /metrics][kube-state-metrics] <--scrape-- Prometheus --rules--> Alertmanager -> Slack/PagerDuty
                                                      |
                                                   Grafana (dashboards)

How it works internally (diagram explained)

Scrape loop: discover targets (static or Kubernetes SD) > relabel > HTTP GET /metrics > parse > append to the TSDB head (memory + WAL) > compact to blocks on disk. Rule evaluation runs each interval; firing alerts are sent to Alertmanager.

Install / Setup

# Docker quick start
docker run -d -p 9090:9090 -v $PWD/prometheus.yml:/etc/prometheus/prometheus.yml prom/prometheus
docker run -d -p 9100:9100 prom/node-exporter
# Kubernetes (recommended)
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm install mon prometheus-community/kube-prometheus-stack -n monitoring --create-namespace

Configuration Explained Line by Line

prometheus.yml explained

global:
  scrape_interval: 15s
scrape_configs:
  - job_name: kubernetes-pods
    kubernetes_sd_configs: [{ role: pod }]
    relabel_configs:
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
        action: keep
        regex: "true"
LineMeaning / WHY it exists
scrape_intervalHow often to scrape; trade-off resolution vs load.
kubernetes_sd_configsDiscover pods automatically.
relabel_configs keepOnly scrape pods annotated prometheus.io/scrape: true.

Practical Examples

prometheus.yml

global: { scrape_interval: 15s }
scrape_configs:
- job_name: node
  static_configs: [{ targets: ['localhost:9100'] }]
- job_name: myapp
  metrics_path: /metrics
  static_configs: [{ targets: ['app:3000'] }]

Useful PromQL

# CPU usage %
100 - avg by(instance)(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100
# request rate and error ratio
sum(rate(http_requests_total[5m]))
sum(rate(http_requests_total{code=~"5.."}[5m])) / sum(rate(http_requests_total[5m]))
# p95 latency
histogram_quantile(0.95, sum by(le)(rate(http_request_duration_seconds_bucket[5m])))
# memory available %
node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes * 100

Instrument a Python app

from prometheus_client import Counter, Histogram, start_http_server
REQ = Counter("http_requests_total", "reqs", ["code"])
LAT = Histogram("http_request_duration_seconds", "latency")
start_http_server(8000)
@LAT.time()
def handle(): REQ.labels("200").inc()

Real-World Problems & Fixes (Troubleshooting)

Problem: Prometheus memory explodes
Cause: High cardinality labels (user_id, url with ids)
Fix: Drop/aggregate labels, relabeling, limits; check topk(10, count by(__name__)({__name__=~'.+'})).
Problem: Need long-term storage / HA
Cause: Single Prometheus local TSDB
Fix: Remote write to Thanos/Mimir/VictoriaMetrics.

Best Practices

Performance

  • Recording rules; keep labels low cardinality.

Common Mistakes

Developer mistakes

  • High-cardinality labels.

Hinglish Explanation

rate() counter ko per-second speed mein badalta hai. Labels mein user_id jaise unique values mat daalo (high cardinality).

Interview Questions

Q1. Pull vs push model?

Prometheus pulls (scrapes) targets; push via Pushgateway only for short-lived jobs.

Q2. Counter vs gauge vs histogram?

Counter only increases (use rate()); gauge goes up/down; histogram buckets for quantiles.

Q3. rate vs irate?

rate = average per-second over window; irate = instantaneous last two points.

Q4. What is cardinality?

Number of unique label combinations; high cardinality kills performance.

Q5. How does service discovery work in K8s?

ServiceMonitor/PodMonitor CRDs via Prometheus Operator.

Q6. Why does Prometheus pull instead of push?

Central control over targets and rates, easy detection of down targets (up), simpler client libraries; Pushgateway for batch jobs.
