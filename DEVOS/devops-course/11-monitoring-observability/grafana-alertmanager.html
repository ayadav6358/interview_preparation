Grafana Dashboards & Alertmanager

Intermediate Monitoring, Logging & Observability

Concept (What & Why)

Grafana visualization, Alertmanager routing/grouping/silencing of alerts. Actionable alerts with runbooks.

Definition Deep-Dive

QuestionAnswer
Simple definitionGrafana draws dashboards; Alertmanager decides who gets notified and how.
Technical definitionGrafana queries data sources and renders panels; Alertmanager receives alerts from Prometheus, groups by labels, inhibits/silences, and routes to receivers with repeat intervals.
Why does it exist?Humans need clear views and actionable notifications.
What happens without it?Raw numbers and alert floods.
When to useAll production monitoring.
When NOT to useDashboards without a purpose.
Real-world analogyGrafana = instrument panel; Alertmanager = dispatcher of the right alarm to the right person.

Diagram & Internal Working

Prometheus rule fires -> Alertmanager: group -> dedupe -> route (severity/team)
   ├─ critical -> PagerDuty
   └─ warning  -> Slack #alerts
Inhibition: node down suppresses pod alerts on that node

How it works internally (diagram explained)

Prometheus sends alert instances (labels + annotations) to Alertmanager. Alertmanager waits group_wait, groups alerts with the same group_by labels into one notification, sends to the matched receiver, and repeats after repeat_interval if still firing. Inhibit rules suppress dependent alerts (e.g. disk warning when node is down).

Install / Setup

docker run -d -p 3000:3000 grafana/grafana    # admin/admin
# add Prometheus datasource http://prometheus:9090; import dashboard IDs 1860 (node), 15760 (k8s)

Configuration Explained Line by Line

alertmanager.yml explained

route:
  receiver: slack-default
  group_by: [alertname, service]
  group_wait: 30s
  group_interval: 5m
  repeat_interval: 4h
  routes:
    - matchers: [ severity = "page" ]
      receiver: pagerduty
receivers:
  - name: slack-default
    slack_configs: [{ channel: "#alerts", api_url_file: /etc/alertmanager/slack_url }]
  - name: pagerduty
    pagerduty_configs: [{ routing_key_file: /etc/alertmanager/pd_key }]
LineMeaning / WHY it exists
group_byAlerts with the same labels become one notification.
group_waitWait to collect related alerts before first send.
repeat_intervalRe-notify if still firing.
routes matchersSend severity=page to PagerDuty.
api_url_fileKeep secrets in files, not in the config.

Practical Examples

Alert rules

groups:
- name: app
  rules:
  - alert: HighErrorRate
    expr: sum(rate(http_requests_total{code=~"5.."}[5m])) / sum(rate(http_requests_total[5m])) > 0.02
    for: 5m
    labels: { severity: page }
    annotations: { summary: "5xx > 2%", runbook: "https://wiki/runbooks/5xx" }
  - alert: DiskFilling
    expr: predict_linear(node_filesystem_avail_bytes[6h], 24*3600) < 0
    for: 30m
    labels: { severity: ticket }

alertmanager.yml

route:
  receiver: slack
  group_by: [alertname, cluster]
  routes:
  - matchers: [severity="page"]
    receiver: pagerduty
receivers:
- name: slack
  slack_configs: [{ api_url_file: /etc/am/slack_url, channel: '#alerts', send_resolved: true }]
- name: pagerduty
  pagerduty_configs: [{ routing_key_file: /etc/am/pd_key }]

Real-World Problems & Fixes (Troubleshooting)

Problem: Alerts flap (fire/resolve repeatedly)
Cause: No for: duration / noisy metric
Fix: Add for: 5m, use averaging windows.
Problem: Dashboards nobody uses
Cause: Too many panels, no purpose
Fix: One overview dashboard per service: RED/USE, link runbooks and deployments annotations.

Best Practices

Reliability

  • Cluster Alertmanager; watchdog alert.

Security

  • Auth on Grafana; secrets in files.

DevOps mistakes

Interview Questions

Q1. What is for in alert rule?

Condition must hold this long before firing.

Q2. Grouping vs inhibition vs silence?

Group batches alerts; inhibition suppresses dependent alerts; silence mutes temporarily.

Q3. Grafana provisioning?

Datasources/dashboards as code (YAML/JSON) for reproducibility.

Q4. How to alert on missing data?

absent() or up == 0.

Q5. Predictive alert?

predict_linear to catch disk exhaustion early.

Q6. What are inhibition and silences?

Inhibition suppresses alerts when a related alert fires; silences mute alerts matching labels for a time (for maintenance).

Why: Alert hygiene.

Real-world example: Silence during planned upgrade.
