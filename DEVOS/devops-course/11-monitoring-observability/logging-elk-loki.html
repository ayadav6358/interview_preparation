Centralized Logging (ELK & Loki)

Intermediate Monitoring, Logging & Observability

Concept (What & Why)

Logs har server par mat dekho, ek jagah collect karo. Structured JSON logs best hain. Loki lightweight (labels index), ELK full-text search.

Definition Deep-Dive

QuestionAnswer
Simple definitionCentral logging collects logs from all servers and containers into one searchable place.
Technical definitionAgents (Promtail/Fluent Bit/Filebeat) tail logs, add labels/metadata, and ship them to Loki (label-indexed) or Elasticsearch (full-text indexed) where Grafana/Kibana query them.
Why does it exist?Logs are scattered across ephemeral containers.
What happens without it?SSH into pods that no longer exist.
When to useAll production systems.
When NOT to useLogging secrets/PII or debug spam.
Real-world analogyA central library for all applications' diaries.

Diagram & Internal Working

Pods/VMs -> agent (Promtail / Fluent Bit / Filebeat) -> Loki | Logstash -> Elasticsearch -> Grafana | Kibana
Structured log: {"ts":"..","level":"error","trace_id":"abc","msg":"db timeout"}

How it works internally (diagram explained)

Pod stdout > container runtime writes /var/log/containers/*.log > agent tails, enriches with Kubernetes labels > pushes to Loki (compresses chunks, indexes labels) > Grafana Explore runs LogQL: first select streams by labels, then filter lines.

Install / Setup

helm repo add grafana https://grafana.github.io/helm-charts
helm install loki grafana/loki-stack -n monitoring --set promtail.enabled=true,grafana.enabled=false

Configuration Explained Line by Line

LogQL examples explained

{namespace="prod", app="api"} |= "error"
{app="api"} | json | level="error" | line_format "{{.msg}}"
sum by (app)(rate({namespace="prod"} |= "error" [5m]))
LineMeaning / WHY it exists
{labels}Stream selector using indexed labels (fast).
|= "error"Line contains filter.
| jsonParse JSON fields.
rate(...)Turn logs into a metric for alerts.

Hands-On Lab

Lab Goal

Run Loki + Grafana and query logs.

Prerequisites

  • Docker Compose

Step 1

Use the official Loki docker-compose example (grafana/loki repo `production/docker-compose.yaml`)

Starts Loki, Promtail and Grafana (check the current file in the repo).

Step 2

Open Grafana > Explore > Loki > {job="varlogs"}

See system logs.

Step 3

Add |= "error"

Filter lines.

Real-World Problems & Fixes (Troubleshooting)

Problem: Can't correlate logs across services
Cause: No request/trace ID
Fix: Propagate trace_id header, include in every log line.
Problem: Log storage costs exploding
Cause: Debug logs, long retention
Fix: Retention policies, drop noisy logs, sample, hot/warm/cold tiers.

Best Practices

Security

  • Mask PII/secrets; restrict log access.

Cost Optimization

  • Retention tiers; drop noisy logs.

Common Mistakes

Security mistakes

  • Logging tokens and passwords.

Hinglish Explanation

Logs JSON format mein likho aur request_id rakho taaki metrics aur traces se jod sako. Passwords/PII kabhi log mat karo.

Interview Questions

Q1. ELK vs Loki?

ELK indexes full text (powerful, heavy); Loki indexes labels only (cheap, simple).

Q2. Why structured logging?

Machine-parseable, filterable fields.

Q3. Sidecar vs DaemonSet log agent?

DaemonSet one per node (efficient); sidecar per pod for special cases.

Q4. What to never log?

Passwords, tokens, PII.

Q5. Log rotation?

Prevent disk filling; logrotate or container runtime limits.

Q6. How to trace one user's failed request across services?

Use a correlation/request ID in every log and pass it in headers, then search by that ID; better use trace_id with OpenTelemetry.

Why: Debugging distributed systems.

Real-world example: Support ticket lookup.
