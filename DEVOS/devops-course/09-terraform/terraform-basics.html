Terraform Basics & Workflow

Basic Infrastructure as Code: Terraform

Concept (What & Why)

Declarative HCL likhte ho; Terraform current state (tfstate) se compare karke plan banata hai aur apply karta hai. Workflow: init -> plan -> apply -> destroy.

Definition Deep-Dive

QuestionAnswer
Simple definitionWrite what you want in a file; Terraform builds it.
Technical definitionTerraform parses HCL, builds a resource graph, compares to state, and calls provider APIs to converge infrastructure to the declared configuration.
Why does it exist?Repeatable, reviewable infrastructure.
What happens without it?Manual console work and drift.
When to useAny cloud/infra provisioning.
When NOT to useConfiguring software inside servers (use Ansible/images).
Real-world analogyA blueprint; Terraform is the builder that also remembers what it built.

Diagram & Internal Working

*.tf files --terraform init--> providers downloaded
        --terraform plan--> diff (desired vs state vs real)
        --terraform apply--> API calls -> resources created -> terraform.tfstate updated

How it works internally (diagram explained)

terraform plan refreshes state from the provider, compares desired configuration and produces an ordered action list. apply executes it using the dependency graph, running independent resources in parallel (default 10) and writing results to state after each change.

Install / Setup

winget install Hashicorp.Terraform    # or: sudo apt install terraform
terraform -version
# use an IAM role / SSO profile for AWS credentials

Configuration Explained Line by Line

Minimal EC2 example explained

terraform {
  required_providers { aws = { source = "hashicorp/aws", version = "~> 5.0" } }
}
provider "aws" { region = "ap-south-1" }

data "aws_ami" "al2023" {
  most_recent = true
  owners      = ["amazon"]
  filter { name = "name", values = ["al2023-ami-*-x86_64"] }
}

resource "aws_instance" "web" {
  ami           = data.aws_ami.al2023.id
  instance_type = "t3.micro"
  tags          = { Name = "demo-web" }
}
output "public_ip" { value = aws_instance.web.public_ip }
LineMeaning / WHY it exists
required_providersPins the provider source and version.
data aws_amiReads the latest Amazon Linux image instead of hard-coding an ID.
resource aws_instance.webCreates a VM; web is the local name.
ami = data...idReference = automatic dependency.
outputPrints the IP after apply.

Practical Examples

First config: S3 bucket + EC2

terraform {
  required_providers { aws = { source = "hashicorp/aws", version = "~> 5.0" } }
}
provider "aws" { region = "ap-south-1" }

variable "env" { default = "dev" }

resource "aws_s3_bucket" "logs" {
  bucket = "acme-logs-${var.env}-12345"
  tags   = { Env = var.env }
}

data "aws_ami" "ubuntu" {
  most_recent = true
  owners      = ["099720109477"]
  filter { name = "name", values = ["ubuntu/images/hvm-ssd/ubuntu-jammy-22.04-amd64-server-*"] }
}

resource "aws_instance" "web" {
  ami           = data.aws_ami.ubuntu.id
  instance_type = "t3.micro"
  tags          = { Name = "web-${var.env}" }
}

output "web_ip" { value = aws_instance.web.public_ip }

Hands-On Lab

Lab Goal

Create and destroy an EC2 instance.

Prerequisites

  • AWS credentials
  • Terraform installed
  • Budget alert

Step 1

terraform init

Downloads the AWS provider into .terraform/.

Step 2

terraform plan

Shows Plan: 1 to add.

Step 3

terraform apply

Type yes; instance is created; state written to terraform.tfstate.

Step 4

terraform destroy

Removes it. Always clean up.

Real-World Problems & Fixes (Troubleshooting)

Problem: Plan wants to destroy and recreate a resource
Cause: Changed an immutable attribute or renamed resource
Fix: Read plan carefully (-/+); use moved block / terraform state mv for renames; lifecycle { prevent_destroy = true } for critical.
Problem: Accidentally committed tfstate with secrets
Cause: Local state in Git
Fix: Use remote encrypted state; .gitignore state files.

Interview Questions

Q1. What is terraform state?

Mapping between config and real resources; needed to plan changes.

Q2. terraform plan vs apply?

plan shows changes without doing; apply executes.

Q3. What are providers?

Plugins that talk to APIs (AWS, Azure, K8s).

Q4. data source vs resource?

Data reads existing info; resource creates/manages.

Q5. Declarative vs imperative?

Terraform declares end state; scripts declare steps.

Q6. What does terraform plan -out give?

A saved plan that apply executes exactly, ensuring reviewed changes are the applied changes.

Why: Safety.
