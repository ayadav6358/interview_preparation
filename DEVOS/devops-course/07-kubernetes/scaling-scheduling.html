Scaling, Scheduling & Resource Management

Advanced Kubernetes

Concept (What & Why)

HPA pods scale karta hai, cluster autoscaler/Karpenter nodes. Scheduling controls: affinity, taints, topology spread, PDB.

Definition Deep-Dive

QuestionAnswer
Simple definitionScaling = more or fewer Pods/nodes as load changes; scheduling = deciding which node runs each Pod.
Technical definitionHPA/VPA/Cluster Autoscaler/Karpenter adjust capacity; the scheduler filters and scores nodes using requests, taints/tolerations, affinity, topology spread and priorities.
Why does it exist?Handle traffic changes and control placement and cost.
What happens without it?Over-provisioning or outages in spikes.
When to useAny production workload.
When NOT to useHPA on memory for apps that do not release memory.
Real-world analogyScheduler = seating manager placing guests by preference; HPA = adding tables when the restaurant fills.

Diagram & Internal Working

Load up -> HPA adds pods -> pods Pending -> Cluster Autoscaler/Karpenter adds node
Scheduling controls: nodeSelector | affinity/anti-affinity | taints+tolerations | topologySpread | priorityClass

How it works internally (diagram explained)

metrics-server collects CPU/memory. HPA compares average usage with the target percentage of requests and changes replicas. If new Pods are Pending, the Cluster Autoscaler/Karpenter adds nodes. The scheduler filters nodes (enough resources? taints tolerated? selectors?) then scores them and binds the Pod.

Install / Setup

kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml

Practical Examples

HPA

kubectl autoscale deploy web --cpu-percent=70 --min=2 --max=10
kubectl get hpa -w

Spread across zones + PDB

topologySpreadConstraints:
- maxSkew: 1
  topologyKey: topology.kubernetes.io/zone
  whenUnsatisfiable: DoNotSchedule
  labelSelector: { matchLabels: { app: web } }
---
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata: { name: web }
spec: { minAvailable: 2, selector: { matchLabels: { app: web } } }

Taint dedicated GPU nodes

kubectl taint nodes gpu1 dedicated=gpu:NoSchedule
# pod toleration: key dedicated, value gpu, effect NoSchedule

Hands-On Lab

Lab Goal

Autoscale a CPU-bound deployment.

Prerequisites

  • metrics-server installed
  • Deployment with CPU requests

Step 1

kubectl autoscale deploy web --cpu-percent=50 --min=2 --max=8

Creates an HPA.

Step 2

kubectl run load --rm -it --image=busybox -- sh -c 'while true; do wget -q -O- http://web; done'

Generates load.

Step 3

kubectl get hpa -w

Watch TARGETS rise and REPLICAS increase. Stop the load and see it scale down after the stabilisation window.

Real-World Problems & Fixes (Troubleshooting)

Problem: HPA shows <unknown> targets
Cause: metrics-server missing or no resource requests
Fix: Install metrics-server; set CPU requests.
Problem: Node drain blocked
Cause: PDB too strict
Fix: Adjust PDB or scale up replicas before draining.
Problem: Pods evicted under memory pressure
Cause: No/low requests; BestEffort QoS
Fix: Set requests=limits for critical pods (Guaranteed QoS).

Best Practices

Production

  • Set requests; HPA min >= 2; topologySpreadConstraints across zones.

Cost Optimization

  • Spot nodes for stateless, Karpenter consolidation.

Common Mistakes

DevOps mistakes

  • HPA without requests.
  • Scaling Pods but not nodes.

Hinglish Explanation

HPA Pods badhata hai, Cluster Autoscaler/Karpenter nodes badhata hai. HPA ka percentage requests par based hota hai, isliye requests sahi set karo.

Memory Tricks

ConceptMemory trick
Scheduling knobsTaint = repel; Toleration = allowed; Affinity = attract; Spread = distribute

Interview Questions

Q1. HPA vs VPA vs Cluster Autoscaler?

HPA changes pod count, VPA changes pod resources, CA changes node count.

Q2. Taints vs affinity?

Taints repel pods from nodes (need toleration); affinity attracts pods to nodes/pods.

Q3. QoS classes?

Guaranteed, Burstable, BestEffort; eviction order reversed.

Q4. What is a PDB?

Limits voluntary disruptions to keep min availability.

Q5. Karpenter vs Cluster Autoscaler?

Karpenter provisions right-sized nodes directly from pending pods, faster and more flexible.

Q6. HPA shows <unknown> for targets.

metrics-server missing/unhealthy or no CPU requests set on the Pods.

Why: Common lab issue.

Real-world example: Install metrics-server, add requests.
