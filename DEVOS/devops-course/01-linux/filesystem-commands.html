Filesystem & Basic Commands

Basic Linux

Concept (What & Why)

Linux mein sab kuch file hai. Root / se tree shuru hota hai. Pehle directory structure aur daily commands aani chahiye.

Definition Deep-Dive

QuestionAnswer
Simple definitionThe filesystem is the tree of folders and files starting at /; these commands let you move around and manage it.
Technical definitionLinux uses a single hierarchical namespace rooted at / with mount points; files are inodes referenced by directory entries; standard streams and pipes connect commands.
Why does it exist?Everything in Linux (config, devices, logs) is reached through files.
What happens without it?You cannot inspect or change the system.
When to useAlways.
When NOT to useDestructive commands (rm -rf) without checking the path.
Real-world analogyA building directory: floors (directories) and rooms (files).

Diagram & Internal Working

/
├── etc     -> config files (nginx.conf, ssh/sshd_config)
├── var     -> changing data (logs in /var/log, web in /var/www)
├── home    -> user directories (/home/anup)
├── usr     -> installed programs (/usr/bin, /usr/local)
├── opt     -> third-party software
├── tmp     -> temp files (cleared on reboot)
├── proc    -> virtual FS: process + kernel info
└── dev     -> devices (/dev/sda, /dev/null)

How it works internally (diagram explained)

When you run ls /etc, the shell forks a child and executes /bin/ls. ls uses system calls (openat, getdents) to read the directory inode's entries and stat for metadata, then writes text to stdout. Pipes connect one process's stdout to another's stdin through a kernel buffer.

Install / Setup

# Windows: WSL2 (PowerShell as admin)
wsl --install -d Ubuntu
# or use VirtualBox / multipass / AWS EC2 free tier
lsb_release -a     # verify distro

Practical Examples

Daily navigation and file ops

pwd; ls -lah
mkdir -p project/{src,logs,conf}
cd project && touch src/app.py
cp -r src src_backup
mv src_backup /tmp/
rm -rf /tmp/src_backup          # careful: no undo
cat /etc/os-release
head -n 5 /var/log/syslog; tail -f /var/log/syslog   # live follow
find /var/log -name "*.log" -mtime -1 -size +10M
du -sh * | sort -h              # what is eating space
ln -s /opt/app/current /var/www/app   # symlink (used in deployments)

Pipes and redirection

ls /etc | wc -l
ps aux | grep nginx | grep -v grep
echo "hello" > a.txt      # overwrite
echo "more"  >> a.txt     # append
command 2> err.log        # stderr
command > all.log 2>&1    # both
export APP_ENV=prod; echo $APP_ENV; echo $PATH

Important Commands Explained

ls -lah
What does it do?
Lists files with permissions, sizes (human readable) and hidden files.
Important options
-l long, -a all, -h human sizes, -t sort by time, -R recursive.
Expected output
drwxr-xr-x 2 user group 4.0K Sep 19 10:00 dir
Common mistake
Forgetting -a and missing dotfiles.
Troubleshooting
No such file: check pwd and spelling.
find /var/log -name '*.log' -mtime +7 -size +10M
What does it do?
Finds files by name/age/size.
Important options
-name, -type f|d, -mtime, -size, -exec cmd {} \;.
Expected output
List of matching paths.
Common mistake
Searching / as non-root (permission noise).
Troubleshooting
Use 2>/dev/null and narrow the path.
du -sh * | sort -h
What does it do?
Shows size of each item, sorted.
Important options
-s summary, -h human, --max-depth=N, -x one filesystem.
Expected output
Sizes with names.
Common mistake
Confusing du with df.
Troubleshooting
Disk full but du small: deleted-open files (lsof +L1).

Hands-On Lab

Lab Goal

Practise navigation and file operations safely.

Prerequisites

  • Linux/WSL terminal

Step 1

mkdir -p ~/lab/{logs,app} && cd ~/lab && pwd

Creates a tree and moves into it.

Step 2

echo 'hello' > app/a.txt && cp app/a.txt logs/ && ls -l logs app

Creates and copies a file; compare with ls.

Step 3

find ~/lab -type f -name '*.txt'

Locates files.

Step 4

rm -r ~/lab

Removes the lab. ALWAYS double-check the path before recursive delete.

Real-World Problems & Fixes (Troubleshooting)

Problem: rm -rf ne galat folder delete kar diya
Cause: Variable empty tha: rm -rf $DIR/* became rm -rf /*
Fix: Always set -u in scripts, quote variables, use ${DIR:?}; keep backups; use --preserve-root.
Problem: Command not found after installing tool
Cause: Binary not in $PATH
Fix: which tool, add to ~/.bashrc: export PATH=$PATH:/opt/tool/bin then source ~/.bashrc.

Best Practices

Production

  • Use absolute paths in scripts.
  • Test destructive commands with echo first.

Common Mistakes

Beginner mistakes

  • rm -rf $VAR/ with empty VAR.
  • Using cd without checking success in scripts.

Hinglish Explanation

Linux mein pura system ek tree hai jo / se shuru hota hai. rm -rf bina soche mat chalao: path do baar check karo.

Interview Questions

Q1. Difference between hard link and soft link?

Hard link points to the same inode (survives deletion of original, cannot cross filesystems, not for directories). Soft link is a separate file holding a path; breaks if target is removed.

Q2. What is /proc?

Virtual filesystem exposing kernel and process info in memory, e.g. /proc/cpuinfo, /proc/<pid>/status. No disk usage.

Q3. How to find a file bigger than 100MB modified in last 2 days?

find / -type f -size +100M -mtime -2 2>/dev/null

Q4. What does 2>&1 mean?

Redirect file descriptor 2 (stderr) to where fd 1 (stdout) currently points.

Q5. Difference between > and >>?

> truncates and writes, >> appends.

Q6. What is an inode?

Metadata structure storing file attributes (owner, perms, size, block pointers) but not the filename. 'No space left' can occur due to inode exhaustion (df -i).

Q7. Find and delete logs older than 30 days safely.

Preview with find /var/log/app -name '*.log' -mtime +30 -print, then add -delete, or use logrotate.

Why: Safe operations.

Real-world example: Never run delete first.
