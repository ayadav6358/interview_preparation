Bash Scripting for DevOps

Intermediate Linux

Concept (What & Why)

Repetitive kaam automate karne ke liye Bash script. Safe scripts likho: set -euo pipefail, quotes, functions, logging.

Definition Deep-Dive

QuestionAnswer
Simple definitionA file of shell commands with logic that automates repeated tasks.
Technical definitionBash is an interpreter supporting variables, conditionals, loops, functions, exit codes, traps and pipelines; scripts are executed via shebang with strict mode for safety.
Why does it exist?Automation is repeatable and reviewable.
What happens without it?Manual, error-prone steps.
When to useSmall automation and glue tasks.
When NOT to useComplex logic and data structures (use Python).
Real-world analogyA recipe the computer follows exactly.

Diagram & Internal Working

script.sh --> args/env --> checks --> do work --> log --> exit code (0 ok / non-zero fail)
                                  └─ trap cleanup on EXIT/ERR

How it works internally (diagram explained)

The kernel reads the shebang (#!/usr/bin/env bash) and runs bash with the script. Bash expands variables, runs commands, and each command returns an exit code (0 = success). set -e stops on failure, -u on unset variables, pipefail on failures inside pipelines. trap runs cleanup on exit.

Install / Setup

sudo apt install shellcheck -y   # lint your scripts

Configuration Explained Line by Line

Safe script template explained

#!/usr/bin/env bash
set -euo pipefail
trap 'echo "failed at line $LINENO" >&2' ERR
TARGET="${1:?usage: $0 <dir>}"
for f in "$TARGET"/*.log; do
  [ -e "$f" ] || continue
  gzip -f "$f"
done
LineMeaning / WHY it exists
#!/usr/bin/env bashFinds bash in PATH.
set -euo pipefailExit on error, unset variable or failed pipe.
trap ... ERRReports where it failed.
${1:?usage}Requires an argument and prints usage if missing.
"$TARGET"Quoting prevents word-splitting and globbing bugs.
[ -e "$f" ] || continueHandles the no-match case.

Practical Examples

Production-style script template

#!/usr/bin/env bash
set -euo pipefail
trap 'echo "failed at line $LINENO" >&2' ERR

log() { echo "[$(date +%F' '%T)] $*"; }
usage() { echo "Usage: $0 <env>"; exit 1; }
[[ $# -eq 1 ]] || usage
ENV="$1"

log "Deploying to $ENV"
for host in $(cat hosts_$ENV.txt); do
  ssh "$host" 'sudo systemctl restart myapp' && log "$host OK" || log "$host FAILED"
done

Backup with rotation

#!/usr/bin/env bash
set -euo pipefail
SRC=/var/www; DEST=/backup; KEEP=7
tar czf "$DEST/site-$(date +%F).tar.gz" "$SRC"
find "$DEST" -name 'site-*.tar.gz' -mtime +$KEEP -delete
# cron: 0 2 * * * /opt/scripts/backup.sh >> /var/log/backup.log 2>&1

Health check

code=$(curl -s -o /dev/null -w '%{http_code}' http://localhost:3000/health)
[[ "$code" == 200 ]] || { echo "unhealthy: $code"; exit 2; }

Hands-On Lab

Lab Goal

Write a backup script with logging.

Prerequisites

  • Linux terminal

Step 1

cat > backup.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
SRC="${1:?src}"; DEST="${2:?dest}"
mkdir -p "$DEST"
tar czf "$DEST/backup-$(date +%F).tgz" -C "$SRC" .
echo "$(date -Is) backup ok" >> "$DEST/backup.log"
EOF
chmod +x backup.sh

Creates an executable script.

Step 2

./backup.sh ~/lab /tmp/bk && ls -l /tmp/bk

Runs it; check the archive and log.

Step 3

./backup.sh

Prints the usage error thanks to ${1:?}.

Real-World Problems & Fixes (Troubleshooting)

Problem: Script continues after a failed command and corrupts data
Cause: No set -e
Fix: Use set -euo pipefail; check with shellcheck.
Problem: Cron job works manually but not from cron
Cause: Minimal PATH/env in cron
Fix: Use absolute paths, set PATH at top, redirect output to log.

Best Practices

Development

  • Use shellcheck; functions; logging; idempotent steps.

Security

  • Never echo secrets; validate inputs.

Common Mistakes

Developer mistakes

  • Unquoted variables.
  • Parsing ls output.
  • No error handling.

Hinglish Explanation

Script ke top par set -euo pipefail lagao aur variables ko quotes mein rakho. Cron mein script chalao to absolute paths use karo.

Interview Questions

Q1. What does set -euo pipefail do?

-e exit on error, -u error on unset var, -o pipefail pipeline fails if any command fails.

Q2. Difference between $@ and $*?

"$@" keeps each argument separate; "$*" joins into one string.

Q3. How to check if a file exists?

[[ -f file ]] (file), -d dir, -s non-empty.

Q4. What is exit code and how to read?

0 success; $? gives last command status.

Q5. What is a here-doc?

cat <<EOF ... EOF passes multi-line text to a command.

Q6. How do you make a script idempotent?

Check state before acting (e.g. mkdir -p, grep -q || append), so re-running gives same result.

Q7. What does $? and $@ mean?

$? is the last exit code; $@ is all arguments (quote it as "$@").
