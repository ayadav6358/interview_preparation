Performance & Troubleshooting

Advanced Linux

Concept (What & Why)

Production issue mein systematic approach chahiye: CPU, memory, disk IO, network. USE method (Utilization, Saturation, Errors) follow karo.

Definition Deep-Dive

QuestionAnswer
Simple definitionA method to find why a server is slow or failing.
Technical definitionUse the USE method (Utilization, Saturation, Errors) for CPU, memory, disk and network, correlating metrics with logs and recent changes.
Why does it exist?Fast, structured diagnosis reduces downtime.
What happens without it?Guessing and random restarts.
When to useIncidents and capacity reviews.
When NOT to useChanging many things at once.
Real-world analogyA doctor takes vitals before prescribing.

Diagram & Internal Working

Slow server?
 ├─ CPU?     top / mpstat        -> high %us (app) / %sy (kernel) / %wa (IO wait)
 ├─ Memory?  free -m / vmstat    -> swapping (si/so) / OOM in dmesg
 ├─ Disk?    iostat -xz 1        -> %util, await high
 ├─ Network? sar -n DEV / ss -s  -> retransmits, drops
 └─ App?     strace -p PID / logs / profiler

How it works internally (diagram explained)

Start with uptime (load) > top (who?) > free -h (memory/swap) > vmstat 1 (run queue, swap, iowait) > iostat -x 1 (disk latency/util) > ss -s (connections) > logs (journalctl, app logs). Each tool answers one question and narrows the suspect.

Install / Setup

sudo apt install sysstat htop iotop strace lsof -y

Practical Examples

60-second checklist

uptime; dmesg -T | tail
vmstat 1 5; mpstat -P ALL 1 3
free -m; iostat -xz 1 3
sar -n DEV 1 3; ss -s; top -bn1 | head -15

Find what a hung process is doing

strace -f -p <pid> -e trace=network,file
lsof -p <pid> | head
cat /proc/<pid>/status | grep -E 'VmRSS|Threads'

Tune kernel parameters

sysctl net.core.somaxconn
echo 'net.core.somaxconn=1024' | sudo tee /etc/sysctl.d/99-app.conf; sudo sysctl --system
ulimit -n; # 'too many open files' -> raise LimitNOFILE in systemd unit

Important Commands Explained

vmstat 1 5
What does it do?
CPU, memory, swap and IO snapshot every second.
Important options
-s memory stats, -d disk.
Expected output
Columns r b swpd free si so bi bo us sy id wa.
Common mistake
Reading only the first line (since boot).
Troubleshooting
High wa = disk waiting; high si/so = swapping.
iostat -x 1
What does it do?
Per-device IO utilisation and latency.
Important options
-x extended, -d device only.
Expected output
%util, await.
Common mistake
iostat package missing (sysstat).
Troubleshooting
%util near 100 and high await: disk saturated.

Hands-On Lab

Lab Goal

Create and diagnose CPU load.

Prerequisites

  • Linux terminal

Step 1

yes > /dev/null & yes > /dev/null &

Starts two CPU hogs.

Step 2

uptime; top -bn1 | head -15

Load rises; yes processes at the top.

Step 3

pkill yes; uptime

Load falls gradually (1-minute average).

Real-World Problems & Fixes (Troubleshooting)

Problem: High load but CPU idle
Cause: Processes stuck in IO wait (slow disk/NFS)
Fix: iostat, iotop; check %wa; move logs off slow disk.
Problem: 'Too many open files'
Cause: fd limit 1024
Fix: Set LimitNOFILE=65535 in unit or /etc/security/limits.conf; fix fd leak.
Problem: Memory keeps growing
Cause: Leak or page cache misunderstanding
Fix: free -m look at available not free; use smem/pmap; restart + profile.

Interview Questions

Q1. Explain load average.

1/5/15 min avg of tasks running or waiting (incl. IO on Linux). Compare with core count.

Q2. What is swap and when bad?

Disk space used as RAM overflow; heavy swapping (si/so) kills performance.

Q3. What is OOM killer?

Kernel kills a process (highest oom_score) when memory exhausted. See dmesg.

Q4. How to find which process is using most IO?

iotop -o or pidstat -d 1.

Q5. What is strace?

Traces system calls of a process; reveals file/network calls and blocking points.

Q6. What are cgroups and namespaces?

Kernel features: cgroups limit/account resources, namespaces isolate views (pid, net, mnt...). Together they make containers.

Q7. Load average is 20 but CPU idle is high. Why?

Load includes tasks in uninterruptible IO wait; likely disk or NFS problem. Check iowait, iostat, D-state processes.

Why: Understanding load.

Real-world example: Slow disk.
