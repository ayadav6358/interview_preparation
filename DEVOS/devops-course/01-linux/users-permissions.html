Users, Groups & Permissions

Basic Linux

Concept (What & Why)

Linux multi-user OS hai. Har file ke owner, group aur others ke permissions hote hain: read(4), write(2), execute(1). Security ka base yahi hai.

Definition Deep-Dive

QuestionAnswer
Simple definitionUsers and groups decide who can read, write or run a file.
Technical definitionEach file has an owner UID, group GID and mode bits (rwx for user/group/other) plus optional ACLs and special bits; the kernel checks the process's effective UID/GIDs against them.
Why does it exist?Multi-user security and least privilege.
What happens without it?Anyone could read secrets or change system files.
When to useAlways.
When NOT to usechmod 777.
Real-world analogyKeys and doors in an office: who holds which key.

Diagram & Internal Working

-rwxr-xr--  1  anup  devs  1200  app.sh
 |||||||||
 |||||||└─ others: r--  (4)
 ||||└┴── group : r-x  (5)
 |└┴┴──── owner : rwx  (7)   => chmod 754 app.sh
 └ file type (- file, d dir, l link)

How it works internally (diagram explained)

On each file access the kernel compares the process's UID/GID with the file's owner/group and mode: owner bits if UID matches, group bits if in group, otherwise other bits. Root (UID 0) bypasses checks (except some MAC systems). sudo runs a command as another user after checking /etc/sudoers.

Practical Examples

Create user, group, give sudo

sudo adduser deploy
sudo groupadd devs && sudo usermod -aG devs deploy
sudo usermod -aG sudo deploy         # sudo access
id deploy; groups deploy

chmod / chown

chmod 750 deploy.sh          # rwx r-x ---
chmod +x script.sh; chmod -R g+w /var/www
sudo chown -R www-data:www-data /var/www/app
umask 022                     # default: files 644, dirs 755
# special bits
chmod u+s /usr/bin/x   # setuid; chmod g+s dir (inherit group); chmod +t /tmp (sticky)

Fine-grained ACL

setfacl -m u:anup:rwx /data/reports
getfacl /data/reports

Important Commands Explained

chmod 640 secret.env && chown deploy:app secret.env
What does it do?
Sets mode and owner: owner rw, group r, others none.
Important options
-R recursive, symbolic u+x.
Expected output
No output on success.
Common mistake

Troubleshooting
Denied? Check ownership and parent directory execute bit (namei -l path).

Hands-On Lab

Lab Goal

Create a user and restrict a directory to a group.

Prerequisites

  • sudo access on a test machine

Step 1

sudo groupadd app && sudo useradd -m -G app alice && sudo useradd -m bob

alice is in group app, bob is not.

Step 2

sudo mkdir /srv/app && sudo chown root:app /srv/app && sudo chmod 770 /srv/app

Only root and group app can enter.

Step 3

sudo -u alice touch /srv/app/ok; sudo -u bob ls /srv/app

alice succeeds; bob gets Permission denied.

Real-World Problems & Fixes (Troubleshooting)

Problem: Nginx returns 403 for static files
Cause: www-data user cannot traverse parent directories (missing x bit)
Fix: namei -l /var/www/app/index.html to inspect every path component; fix with chmod o+x on dirs or correct owner.
Problem: Someone used chmod 777 to 'fix' an app
Cause: Real cause was ownership mismatch; 777 is a security hole
Fix: Set correct owner with chown, use 750/640, use groups.

Best Practices

Security

  • Least privilege; use groups not shared accounts; sudo for specific commands; keys 600; umask 027 for services.

Common Mistakes

Security mistakes

  • World-writable files.
  • Shared root password.

Hinglish Explanation

Permission teen logon ke liye hoti hai: owner, group, others. Directory par x ka matlab andar ja sakte ho. 777 kabhi mat lagao.

Interview Questions

Q1. What does chmod 644 mean?

Owner rw-, group r--, others r--.

Q2. What is sticky bit?

On directories, only file owner (or dir owner/root) can delete files - used in /tmp.

Q3. Difference between su and sudo?

su switches user with target's password; sudo runs a command as another user using your own credentials per /etc/sudoers policy, with audit log.

Q4. Where are users and passwords stored?

/etc/passwd (accounts), /etc/shadow (hashed passwords, root-only), /etc/group.

Q5. What is setuid?

Executable runs with the file owner's privileges (e.g. passwd). Risky if misused.

Q6. How to give a user access to only one command via sudo?

Edit with visudo: deploy ALL=(ALL) NOPASSWD: /bin/systemctl restart myapp.

Q7. What does umask do?

It subtracts permission bits from newly created files: umask 022 gives files 644 and directories 755.

Why: Default permissions.

Real-world example: umask 027 for private services.
