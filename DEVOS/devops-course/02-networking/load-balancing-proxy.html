Load Balancers, Reverse Proxy & Firewalls

Intermediate Networking

Concept (What & Why)

Traffic ko multiple servers mein baantna (LB), backend ko chhupana (reverse proxy), aur security rules (firewall/security groups).

Definition Deep-Dive

QuestionAnswer
Simple definitionA load balancer shares traffic among servers; a reverse proxy sits in front of servers; a firewall filters traffic.
Technical definitionL4 balancers forward TCP/UDP flows; L7 balancers/proxies parse HTTP to route by host/path/header, terminate TLS, cache and apply WAF rules; firewalls apply allow/deny rules by IP/port/protocol.
Why does it exist?Availability, scaling and security.
What happens without it?Single point of failure.
When to useAll production web apps.
When NOT to useSession state stored only on one server.
Real-world analogyRestaurant host seating guests at free tables.

Diagram & Internal Working

        Internet
           |
        [ WAF / CDN ]
           |
        [ ALB (L7) ]  -- health checks --
        /     |     \
     App1   App2   App3   (private subnets)
           |
        [ DB ]   SG: DB accepts 5432 only from App SG

Algorithms: round-robin | least-connections | ip-hash | weighted

How it works internally (diagram explained)

Client > LB (health checks mark targets healthy/unhealthy) > algorithm picks a healthy target > request forwarded > response returned. For HTTPS, LB terminates TLS with a certificate and may re-encrypt to backends. Unhealthy targets are removed until checks pass.

Install / Setup

sudo apt install nginx haproxy -y

Configuration Explained Line by Line

Nginx reverse proxy + load balancing explained

upstream api {
    least_conn;
    server 10.0.10.11:3000 max_fails=3 fail_timeout=10s;
    server 10.0.10.12:3000;
}
server {
    listen 443 ssl;
    server_name api.example.com;
    ssl_certificate     /etc/ssl/fullchain.pem;
    ssl_certificate_key /etc/ssl/privkey.pem;
    location / {
        proxy_pass http://api;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 60s;
    }
}
LineMeaning / WHY it exists
upstream apiNamed backend pool.
least_connSend to the server with fewest active connections.
max_fails/fail_timeoutPassive health check: skip a failing server for 10s.
ssl_certificateFull chain and key for TLS termination.
proxy_set_header HostPreserves the original host for the app.
X-Forwarded-ForPasses the client's real IP.
proxy_read_timeoutHow long to wait for the backend before returning 504.

Practical Examples

Nginx as load balancer

upstream backend {
    least_conn;
    server 10.0.11.10:3000 max_fails=3 fail_timeout=10s;
    server 10.0.11.11:3000;
}
server {
    listen 80;
    location / {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

Security group vs NACL

SG   : stateful, allow rules only, attached to ENI/instance
NACL : stateless, allow+deny, attached to subnet, evaluated in order

Hands-On Lab

Lab Goal

Load balance two backends with Nginx in Docker.

Prerequisites

  • Docker

Step 1

docker network create lb && for i in 1 2; do docker run -d --name web$i --network lb hashicorp/http-echo -text=server$i -listen=:5678; done

Two backends answering their names.

Step 2

Create nginx.conf with upstream {server web1:5678; server web2:5678;} and location / { proxy_pass http://app; } then run nginx with it mounted on port 8080

Nginx balances round robin.

Step 3

for i in 1 2 3 4; do curl -s localhost:8080; done

Alternates server1/server2. Stop one backend and see all requests go to the other.

Real-World Problems & Fixes (Troubleshooting)

Problem: Users get logged out randomly behind LB
Cause: Session stored in server memory; requests hit different servers
Fix: Sticky sessions (short-term) or external session store (Redis).
Problem: App sees LB IP not client IP
Cause: Missing forwarded headers
Fix: Use X-Forwarded-For / proxy protocol; configure app to trust proxy.

Best Practices

Reliability

  • Multi-AZ LB, connection draining, correct health-check path.

Security

  • WAF, TLS policy, restrict backend SG to LB only.

Common Mistakes

DevOps mistakes

  • Health check hits a heavy endpoint.
  • Backends open to the internet.

Hinglish Explanation

Load balancer healthy servers ko hi traffic deta hai. Health check aur timeouts sahi set karo warna 502/504 aayenge.

Interview Questions

Q1. L4 vs L7 load balancer?

L4 routes on IP/port (fast, protocol-agnostic - NLB); L7 routes on HTTP host/path/headers (ALB).

Q2. Forward vs reverse proxy?

Forward proxy acts for clients; reverse proxy acts for servers.

Q3. SG vs NACL?

SG stateful, instance level; NACL stateless, subnet level, ordered rules.

Q4. How do health checks work?

LB periodically probes an endpoint; unhealthy targets are removed from rotation.

Q5. What is a CDN?

Edge cache network serving content near users, reducing latency and origin load.

Q6. Users get logged out randomly behind a load balancer.

Session stored in server memory: use shared session store (Redis), JWT, or sticky sessions as a stopgap.

Why: Statelessness.

Real-world example: Move sessions to Redis.
