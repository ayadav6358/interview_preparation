HTTP, HTTPS & TLS/SSL

Intermediate Networking

Concept (What & Why)

Web ki language HTTP hai. HTTPS = HTTP + TLS encryption. Certificates, status codes aur headers debugging mein roz kaam aate hain.

Definition Deep-Dive

QuestionAnswer
Simple definitionHTTP is how browsers and servers talk; TLS makes it private and verified.
Technical definitionHTTP is a stateless request/response protocol (methods, headers, status codes); TLS provides confidentiality, integrity and server authentication via X.509 certificates issued by trusted CAs.
Why does it exist?Web communication needs a common protocol and protection from eavesdropping.
What happens without it?Plain-text passwords on the wire.
When to useAll web traffic.
When NOT to usePlain HTTP in production.
Real-world analogyHTTP is a postcard; HTTPS is a sealed, signed envelope.

Diagram & Internal Working

Client                                Server
  | ---- ClientHello (ciphers) ------> |
  | <--- ServerHello + Certificate ---- |
  | verify cert chain (CA)              |
  | ---- key exchange ----------------> |
  | <=== encrypted HTTP traffic =====> |

Status: 2xx ok | 3xx redirect | 4xx client error (401 auth, 403 forbidden, 404, 429) | 5xx server (500, 502 bad gw, 503, 504 timeout)

How it works internally (diagram explained)

After TCP connects, TLS: ClientHello (SNI, ciphers) > ServerHello + certificate > client validates chain against trusted CAs and hostname > key exchange (ECDHE) > symmetric session keys > encrypted HTTP.

Install / Setup

sudo apt install certbot python3-certbot-nginx openssl -y

Practical Examples

Inspect requests/certs

curl -I https://example.com
curl -X POST -H 'Content-Type: application/json' -d '{"a":1}' https://api/x -v
openssl s_client -connect example.com:443 -servername example.com </dev/null | openssl x509 -noout -dates -issuer
echo | openssl s_client -connect example.com:443 2>/dev/null | openssl x509 -noout -enddate

Free HTTPS with Let's Encrypt

sudo certbot --nginx -d example.com -d www.example.com
sudo certbot renew --dry-run

Important Commands Explained

curl -vI https://example.com
What does it do?
Shows TLS details, headers and status.
Important options
-k ignore cert errors (debug only), --http2, -w timing, --resolve.
Expected output
TLS handshake lines then HTTP/2 200.
Common mistake
Using -k and forgetting the real issue.
Troubleshooting
Cert errors: openssl s_client -connect host:443 -servername host -showcerts.
openssl x509 -noout -dates -subject -in cert.pem
What does it do?
Displays certificate validity and subject.
Important options
-issuer, -ext subjectAltName.
Expected output
notBefore/notAfter.
Common mistake
Checking only leaf, not the chain.
Troubleshooting
Verify chain with openssl verify.

Real-World Problems & Fixes (Troubleshooting)

Problem: 502 Bad Gateway from Nginx
Cause: Upstream app down or wrong port
Fix: systemctl status app; check proxy_pass; nginx error.log.
Problem: Browser shows 'certificate expired'
Cause: Renewal cron failed
Fix: certbot renew, monitor expiry with Prometheus blackbox probe_ssl_earliest_cert_expiry.
Problem: 504 Gateway Timeout
Cause: Upstream too slow
Fix: Increase proxy_read_timeout only after finding slow query; add caching.

Best Practices

Security

  • TLS 1.2+, HSTS, automated renewals, strong ciphers.

Common Mistakes

Production mistakes

  • Missing intermediate cert.
  • Expired certs.

Hinglish Explanation

HTTPS = HTTP + TLS. Certificate chain, expiry aur hostname teeno check karo. 401 = login nahi, 403 = permission nahi.

Memory Tricks

ConceptMemory trick
401 vs 403401 = who are you? (unauthenticated); 403 = I know you, not allowed

Version / Environment Notes

  • TLS 1.3 is preferred; SSL and TLS 1.0/1.1 are obsolete.
  • Let's Encrypt certs are valid for a short period: automation is required.

Interview Questions

Q1. Difference between 401 and 403?

401 not authenticated; 403 authenticated but not permitted.

Q2. 502 vs 503 vs 504?

502 invalid response from upstream, 503 service unavailable/overloaded, 504 upstream timeout.

Q3. How does HTTPS work?

Certificate verification, asymmetric key exchange to derive symmetric session keys, then symmetric encrypted traffic.

Q4. HTTP/1.1 vs HTTP/2 vs HTTP/3?

2 multiplexes over one TCP connection; 3 uses QUIC (UDP) avoiding head-of-line blocking.

Q5. What is HSTS?

Header forcing browsers to use HTTPS only for a domain.

Q6. What does HSTS do?

Header telling browsers to use HTTPS only for the domain for a period, preventing downgrade attacks.

Why: Web security.

Real-world example: Strict-Transport-Security: max-age=31536000.
