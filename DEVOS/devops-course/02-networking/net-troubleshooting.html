Network Troubleshooting Playbook

Advanced Networking

Concept (What & Why)

Systematic approach: kaha tak packet ja raha hai? Layer by layer test karo.

Definition Deep-Dive

QuestionAnswer
Simple definitionA step-by-step method to find where a network connection fails.
Technical definitionTest each layer in order with a specific tool and interpret the symptom (timeout, refused, reset, TLS error, HTTP code).
Why does it exist?Network incidents are common and time-critical.
What happens without it?Random guesses.
When to useAny connectivity problem.
When NOT to useChanging firewall rules blindly.
Real-world analogyChecking each link of a chain to find the break.

Diagram & Internal Working

1. Local:   ip a / ip route         (IP? gateway?)
2. DNS:     dig name               (resolves?)
3. Reach:   ping / traceroute / mtr (path OK?)
4. Port:    nc -zv host 443        (TCP open?)
5. App:     curl -v                (TLS/HTTP OK?)
6. Firewall: SG / NACL / iptables / route table
7. Packets: tcpdump / Wireshark    (final truth)

How it works internally (diagram explained)

Order: local config (ip a, ip r) > DNS (dig) > reachability (ping/mtr) > port (nc -zv) > TLS (openssl s_client) > HTTP (curl -v) > server side (ss -tulpn, logs). Compare from multiple vantage points (client, bastion, same subnet).

Install / Setup

sudo apt install netcat-openbsd mtr tcpdump nmap -y

Practical Examples

Debug script

HOST=example.com; PORT=443
dig +short $HOST
nc -zv -w3 $HOST $PORT
mtr -rwc 10 $HOST
sudo tcpdump -i any host $HOST and port $PORT -c 20 -nn

AWS reachability checklist

1 Route table has route (IGW/NAT)?
2 SG inbound/outbound allows port?
3 NACL allows both directions (ephemeral ports 1024-65535)?
4 Instance OS firewall/app listening on 0.0.0.0?
Use: VPC Reachability Analyzer

Important Commands Explained

nc -zv db.internal 5432
What does it do?
Tests if a TCP port accepts connections.
Important options
-z scan, -v verbose, -w 3 timeout.
Expected output
Connection to db.internal 5432 port [tcp] succeeded!
Common mistake
Testing from the wrong host.
Troubleshooting
Timeout: firewall/route. Refused: nothing listening.
mtr -rwc 50 host
What does it do?
Combines traceroute and ping to find loss per hop.
Important options
-r report, -c count, -T TCP mode.
Expected output
Per-hop loss and latency.
Common mistake
Reading loss at one hop that does not propagate.
Troubleshooting
Loss that continues to the last hop is real.

Hands-On Lab

Lab Goal

Diagnose a broken path on purpose.

Prerequisites

  • Docker

Step 1

docker run -d --name web -p 8081:80 nginx:1.27 && curl -sI localhost:8081 | head -1

Working baseline: HTTP 200.

Step 2

docker stop web && curl -sI localhost:8081

Connection refused: nothing listens.

Step 3

docker start web && sudo iptables -I INPUT -p tcp --dport 8081 -j DROP 2>/dev/null; curl -m 3 localhost:8081; sudo iptables -D INPUT -p tcp --dport 8081 -j DROP 2>/dev/null

Timeout when packets are dropped (needs Linux + sudo; skip on Docker Desktop). You have now seen refused vs timeout.

Real-World Problems & Fixes (Troubleshooting)

Problem: EC2 in private subnet can't reach internet
Cause: No NAT route
Fix: Add 0.0.0.0/0 -> nat-gw to private route table; NAT lives in public subnet.
Problem: Intermittent connection resets
Cause: Idle timeout on LB/NAT (350s) or conntrack table full
Fix: Enable TCP keepalive shorter than timeout; sysctl net.netfilter.nf_conntrack_max.

Hinglish Explanation

Timeout = drop, Refused = koi sun nahi raha. Har layer ek ek karke test karo aur client/server dono side se dekho.

Interview Questions

Q1. Connection timeout vs connection refused?

Timeout: packets dropped (firewall/route). Refused: reached host but nothing listening (RST).

Q2. How to test a port without telnet?

nc -zv host port or curl -v telnet://host:port, or bash </dev/tcp/host/port.

Q3. What is conntrack?

Kernel connection tracking table for stateful NAT/firewall; when full, new connections drop.

Q4. What does mtr show?

Combined traceroute + ping showing loss and latency per hop.

Q5. Why can pod-to-pod fail while node-to-node works?

CNI issues, NetworkPolicy, MTU/overlay problems, SG rules for pod ports.

Q6. curl works from bastion but not from app server. Why?

Difference in route/SG/NACL/DNS between the two hosts; compare rules and run mtr/nc from the app host.

Why: Vantage points.

Real-world example: SG allows only bastion CIDR.
