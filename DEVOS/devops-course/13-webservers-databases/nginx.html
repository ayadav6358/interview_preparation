Nginx: Web Server & Reverse Proxy

Basic Web Servers, Databases & Messaging

Concept (What & Why)

Nginx static files serve karta hai, reverse proxy/load balancer aur SSL terminator ka kaam karta hai. Event-driven, bahut fast.

Definition Deep-Dive

QuestionAnswer
Simple definitionNginx is a fast web server that also sits in front of your app to route, secure and balance traffic.
Technical definitionNginx is an event-driven, asynchronous HTTP/reverse-proxy server: a master process manages worker processes that multiplex connections; config is declarative (http > server > location).
Why does it exist?Efficient TLS termination, static serving and proxying.
What happens without it?App servers handle raw internet traffic directly.
When to useEdge/reverse proxy for almost every web app.
When NOT to useComplex app logic in Nginx.
Real-world analogyA receptionist who greets visitors, checks IDs and directs them to the right office.

Diagram & Internal Working

Client -> Nginx :443 (TLS, gzip, rate limit, cache)
            ├── /        -> static /var/www/html
            ├── /api     -> upstream node app :3000
            └── /ws      -> websocket upstream

How it works internally (diagram explained)

Master reads config and spawns workers (one per CPU). Each worker uses epoll to handle many connections in one loop. For each request Nginx matches a server (by listen/server_name), then a location, and either serves a file or proxies to an upstream with keep-alive connections. nginx -s reload starts new workers with new config and gracefully retires the old ones.

Install / Setup

sudo apt install nginx -y
sudo systemctl enable --now nginx
nginx -t && sudo systemctl reload nginx     # ALWAYS test before reload

Configuration Explained Line by Line

Production-style server block explained

server {
    listen 443 ssl http2;
    server_name app.example.com;
    ssl_certificate     /etc/ssl/fullchain.pem;
    ssl_certificate_key /etc/ssl/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    server_tokens off;
    add_header Strict-Transport-Security "max-age=31536000" always;
    limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;

    location /api/ {
        limit_req zone=api burst=20 nodelay;
        proxy_pass http://api;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
LineMeaning / WHY it exists
listen 443 ssl http2HTTPS with HTTP/2.
ssl_protocolsDisable old TLS versions.
server_tokens offHide version.
add_header HSTSForce HTTPS in browsers.
limit_req_zone/limit_reqRate limit per client IP (10 req/s, burst 20). Note: limit_req_zone must be in the http context in real config.
proxy_set_headerPass original host/protocol to the app.

Practical Examples

Reverse proxy + SSL + gzip + rate limit

limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;
server {
    listen 443 ssl http2;
    server_name app.example.com;
    ssl_certificate     /etc/letsencrypt/live/app.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.example.com/privkey.pem;
    gzip on; gzip_types text/css application/json application/javascript;

    location / { root /var/www/html; try_files $uri /index.html; }   # SPA
    location /api/ {
        limit_req zone=api burst=20 nodelay;
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    location /ws/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
server { listen 80; server_name app.example.com; return 301 https://$host$request_uri; }

Debug

sudo tail -f /var/log/nginx/error.log
curl -I localhost; nginx -T | less     # dump effective config

Important Commands Explained

nginx -t
What does it do?
Tests the configuration for syntax errors.
Important options
-T dumps full config, -c file.
Expected output
syntax is ok / test is successful
Common mistake
Reloading without testing.
Troubleshooting
Error shows file and line number.
nginx -s reload
What does it do?
Gracefully applies new config.
Important options
-s stop|quit|reopen.
Expected output
No output.
Common mistake
Using restart (drops connections).
Troubleshooting
If reload fails, old config keeps running; read error log.

Real-World Problems & Fixes (Troubleshooting)

Problem: 502 Bad Gateway
Cause: Upstream down/wrong port/socket permission
Fix: Check app status, proxy_pass, error.log.
Problem: 413 Request Entity Too Large
Cause: Default body limit 1MB
Fix: client_max_body_size 20m;
Problem: WebSocket disconnects
Cause: Missing Upgrade headers / proxy_read_timeout
Fix: Add upgrade headers, raise timeout.

Best Practices

Security

  • TLS 1.2+, HSTS, rate limits, hide version.

Performance

  • gzip, keepalive upstream, caching.

Common Mistakes

DevOps mistakes

Interview Questions

Q1. Nginx vs Apache?

Nginx event-driven, lower memory, great as proxy; Apache process/thread, .htaccess flexibility.

Q2. Forward vs reverse proxy?

Reverse proxy sits in front of servers.

Q3. What is try_files?

Try files in order then fallback (used for SPAs).

Q4. How does nginx handle load?

Master + worker processes with epoll event loop.

Q5. Nginx load-balancing methods?

round robin, least_conn, ip_hash, weighted.

Q6. Nginx returns 413 on uploads.

client_max_body_size too small (default 1m); raise it for the location/server.

Why: Common config issue.

Real-world example: Uploading images.
