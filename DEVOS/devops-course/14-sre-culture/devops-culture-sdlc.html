DevOps Culture, SDLC & Agile

Basic SRE, Reliability & DevOps Culture

Concept (What & Why)

DevOps = culture + practices + tools. Dev aur Ops ke beech ki deewar todna. CALMS: Culture, Automation, Lean, Measurement, Sharing.

Definition Deep-Dive

QuestionAnswer
Simple definitionDevOps culture means developers and operations share responsibility for the whole life of the software.
Technical definitionDevOps combines cultural philosophies (CALMS: culture, automation, lean, measurement, sharing), practices (CI/CD, IaC, monitoring) and Agile methods to shorten lead time and improve reliability across the SDLC.
Why does it exist?Break down silos and speed up safe delivery.
What happens without it?Handoff delays and blame.
When to useAny software organisation.
When NOT to useTool-only 'DevOps' without culture change.
Real-world analogyA relay team where everyone owns the finish line, not just their leg.

Diagram & Internal Working

Plan -> Code -> Build -> Test -> Release -> Deploy -> Operate -> Monitor -> (feedback) -> Plan
Waterfall (slow, big-bang)  vs  Agile/Scrum sprints  vs  DevOps continuous flow

How it works internally (diagram explained)

The value stream (idea to production) is mapped to find waiting and rework; small batches, automation, fast feedback and shared metrics reduce delays. Agile frameworks (Scrum sprints, Kanban flow) organise work; CI/CD and IaC make releases routine; monitoring and postmortems close the feedback loop.

Practical Examples

Scrum vs Kanban

Scrum: sprints (2 wk), roles PO/SM/team, ceremonies (planning, standup, review, retro)
Kanban: continuous flow, WIP limits, board columns

Hands-On Lab

Lab Goal

Map your delivery value stream and compute lead time.

Prerequisites

  • A team project or sample project
  • Whiteboard/spreadsheet

Step 1

Write each step from 'idea' to 'in production' with typical wait time and work time

Reveals bottlenecks such as manual approvals or slow test environments.

Step 2

Compute lead time = sum(work + wait) and flow efficiency = work / lead time

Low efficiency (often under 20%) shows where automation helps.

Step 3

Pick one bottleneck and define a small experiment (for example automate approval checks) with a measurable target

Continuous improvement in practice.

Real-World Problems & Fixes (Troubleshooting)

Problem: Dev throws code over the wall, Ops firefights
Cause: Silos, no shared ownership
Fix: You build it, you run it; shared on-call, shared dashboards.

Best Practices

Development

  • Small batches; definition of done includes monitoring and runbook.

Interview Questions

Q1. What is DevOps?

Culture and practices that unify development and operations to deliver software faster and more reliably.

Q2. What is CALMS?

Culture, Automation, Lean, Measurement, Sharing.

Q3. Agile vs DevOps?

Agile focuses on iterative development; DevOps extends to delivery and operations.

Q4. What is a retrospective?

Team meeting to improve process.

Q5. What is ChatOps?

Operating via chat tools with bots.

Q6. What does 'you build it, you run it' mean?

The team that develops a service is also responsible for operating it (on-call), which creates strong incentives for quality and observability.

Why: Ownership principle.

Real-world example: Amazon's model.
