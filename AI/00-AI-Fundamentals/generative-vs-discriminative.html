1. What is this?

A discriminative model learns the boundary between classes/outcomes: P(label | input). A generative model learns the underlying distribution of the data itself: P(input) or P(input | condition), and can be sampled to produce new, never-seen examples.

2. Why does it exist?

This distinction predates deep learning — it comes from classical statistics, where some models were built to directly separate classes (discriminative) and others to model how data is generated in the first place (generative), enabling sampling, density estimation, and Bayesian inference. Modern GenAI inherited the "generative" name because LLMs/diffusion models are, in this precise statistical sense, learning to model and sample from a data distribution.

3. Why is it important?

Choosing the wrong category for a task wastes resources: using a generative LLM for a bounded classification task is usually slower, costlier, and less consistent than a purpose-built discriminative classifier; conversely, a discriminative model fundamentally cannot create new content, so content-generation products require a generative model.

4. Where is it used?

  • Discriminative: fraud detection, spam filtering, ranking, toxicity classification, OCR label prediction.
  • Generative: chatbots, code generation, image/video synthesis, data augmentation, drafting content.

6. Core concepts

  • Discriminative: logistic regression, SVM, most classifiers, BERT-style encoders used for classification — model P(y|x) directly.
  • Generative (classic): Naive Bayes, Gaussian Mixture Models, HMMs — model P(x|y) and P(y), can generate samples.
  • Generative (modern/GenAI): GPT/Claude/Gemini (autoregressive text), diffusion models (images/video), GANs, VAEs — model the full data distribution well enough to sample realistic new content.
  • A generative model can, in principle, be used for classification via Bayes' rule, but this is rarely the efficient choice in practice.

8. Architecture

Discriminative:  Input x  →  Model  →  P(y | x)  →  Label

Generative:      Condition/prompt  →  Model (learns P(x))  →  Sample  →  New content x

9. How it works internally

A discriminative classifier is trained to minimize classification error (e.g., cross-entropy between predicted and true label) directly — it never needs to model what "spam text in general" looks like, only what separates spam from non-spam. A generative model is trained to maximize the likelihood of the observed data under its learned distribution (e.g., next-token prediction likelihood for LLMs) — it implicitly must capture much more about the structure of the data to do this well, which is also why generative models typically need far more data/compute to train well.

10. Step-by-step: classifying a model

  1. Ask: does the model's output define a decision/label/score given an input, or does it produce new data resembling the training distribution?
  2. If decision/label → discriminative.
  3. If new data/content → generative.
  4. Check if it could, in principle, be sampled to generate novel examples of its training domain (even if that's not its deployed use) — this confirms the generative/discriminative label.

11. Simple example

A spam classifier (discriminative) only decides spam/not-spam. A model that can write a realistic spam email (generative) has learned the distribution of spam text well enough to produce new instances.

12. Real-world example

A resume-screening model that scores "fit: 0.82" is discriminative. An LLM that drafts a tailored cover letter from a resume is generative.

13. Code example

# Discriminative: predicts a label
from sklearn.linear_model import LogisticRegression
clf = LogisticRegression().fit(X_train, y_train)
label = clf.predict(x_new)  # "spam" or "not spam"

# Generative: produces new content conditioned on input
from anthropic import Anthropic
client = Anthropic()
resp = client.messages.create(
    model="claude-sonnet-5",
    max_tokens=200,
    messages=[{"role": "user", "content": "Write a short spam-style email about a fake prize."}]
)
new_text = resp.content[0].text  # brand-new text, sampled from the model's learned distribution

14. Advanced example

Using a generative model's likelihood scores for discriminative-style out-of-distribution detection: compute the model's log-probability of an input and flag unusually low-likelihood inputs as anomalous — a case where a generative model's internal density estimate is repurposed for a discriminative-style decision without retraining.

logprob = generative_model.score(input_sample)  # log P(x) under the model
if logprob < THRESHOLD:
    flag_as_anomalous(input_sample)

15. Common mistakes

  • Using an LLM (generative) for high-volume real-time binary classification when a discriminative classifier would be far cheaper and faster.
  • Assuming a generative model's fluent output implies calibrated confidence the way a discriminative classifier's probability output does.
  • Believing "generative" means "creative/random" and "discriminative" means "simple" — the distinction is about what's being modeled, not sophistication.

16. Best practices

  • Use discriminative models for narrow, stable classification/scoring tasks at scale.
  • Use generative models when the deliverable is genuinely new content or when zero-shot generalization across unseen categories matters more than per-call cost.
  • Consider hybrid pipelines: generative model's embeddings/features feeding a lightweight discriminative head for the final decision.

17. Production considerations

Discriminative models are typically cheaper and lower-latency to serve at scale; generative models cost more per call and have higher, more variable latency due to autoregressive generation — factor this into SLA design when choosing between them for a given sub-task.

18. Security considerations

Generative models carry additional risks discriminative models don't: prompt injection, hallucinated/fabricated outputs presented as fact, and potential for misuse to generate harmful content at scale — discriminative classifiers mainly risk biased/adversarial-example-driven misclassification.

19. Performance considerations

Discriminative inference is typically a single forward pass (fast, parallelizable). Generative inference (autoregressive) requires one forward pass per output token (sequential, slower) — a fundamental latency difference to design around.

20. Cost considerations

Generative model API calls are priced per token (input+output) and are typically far more expensive per request than a discriminative model's single forward-pass inference — multiply by request volume before choosing.

21. Debugging/troubleshooting

  • "Classifier results are inconsistent run to run": check if you accidentally swapped in a generative model prompted to output a label, instead of a true discriminative classifier — generative sampling introduces variance a discriminative model wouldn't have.
  • "Generation is too slow": expected — generative inference is sequential; consider streaming for perceived latency or a smaller/faster model.

27. Interview Questions — Beginner

Q1. Is ChatGPT/Claude discriminative or generative?
A. Generative — it models the distribution of likely next tokens and samples from it to produce new text.
Q2. What does a discriminative model directly learn?
A. P(label | input) — the boundary between classes given the input.
Q3. What does a generative model directly learn?
A. The distribution of the data itself, P(input) or P(input | condition), so it can be sampled to produce new examples.
Q4. Name one classic discriminative algorithm.
A. Logistic regression (or SVM).
Q5. Name one classic generative algorithm (pre-deep-learning).
A. Naive Bayes (or Gaussian Mixture Models).
Q6. Can a generative model produce a classification label?
A. Yes, indirectly (e.g., an LLM can be prompted to output a label), though it's often less efficient than a dedicated discriminative classifier.
Q7. Which type of model is typically faster at inference, discriminative or generative?
A. Discriminative — typically one fast forward pass versus generative's sequential, multi-step token generation.
Q8. Does "generative" mean the model is more creative/intelligent than a discriminative one?
A. No — it refers to what's being modeled (the data distribution vs. a decision boundary), not a measure of sophistication.
Q9. Would you use a discriminative or generative model to detect spam at massive scale in real time?
A. Discriminative — faster, cheaper, more consistent for this high-volume, bounded classification task.
Q10. Would you use a discriminative or generative model to draft a personalized email reply?
A. Generative — the task requires producing new, coherent content, not classifying.

28. Interview Questions — Intermediate

Q1. How can Bayes' rule be used to turn a generative model into a classifier, and why is this rarely done in practice for modern tasks?
A. P(y|x) = P(x|y)P(y) / P(x) — if you've learned P(x|y) and P(y) generatively, you can derive the discriminative posterior. In practice, directly learning P(y|x) via a discriminative model is usually more data-efficient and accurate for the specific classification task, since the generative model solves a strictly harder problem (modeling all of x) to get there.
Q2. Why do generative models typically require more training data than discriminative models for a comparable task?
A. Generative models must capture the full structure/distribution of the data, a strictly harder objective than discriminative models, which only need to learn the (often much simpler) boundary that separates classes.
Q3. What's a practical reason to prefer a fine-tuned discriminative classifier over a zero-shot LLM prompt for a stable, high-volume classification task?
A. Lower per-request cost and latency, more consistent/deterministic outputs, and easier auditing/calibration of confidence scores — all of which matter more at scale than the LLM's flexibility advantage, which isn't needed once the taxonomy is fixed.
Q4. Can discriminative models be deep learning models? Give an example.
A. Yes — e.g., a BERT-based or CNN-based classifier is a deep, discriminative model; depth/architecture is orthogonal to the generative/discriminative distinction.
Q5. Why might a generative model's fluent, confident-sounding output be more dangerous in a classification-adjacent task than a discriminative model's explicit probability score?
A. A discriminative model's probability output is typically directly calibrated to its training objective and easy to threshold; a generative model's fluency can create false confidence in a free-text answer that has no calibrated uncertainty signal attached, making errors harder to detect automatically.

29. Interview Questions — Advanced

Q1. How would you use a generative language model's per-token log-probabilities for an out-of-distribution/anomaly-detection task, and what's the risk?
A. Low likelihood under the model for a given input can signal it's unusual/out-of-distribution relative to training data; risk: likelihood doesn't always correlate with "this is wrong/anomalous" in the way you want — some rare-but-valid inputs (e.g., unusual but legitimate language) also score low, requiring careful thresholding and validation against labeled anomalies.
Q2. Why is "discriminative vs generative" a different axis than "classic ML vs deep learning," and can you have all four combinations?
A. Yes — logistic regression (discriminative, classic ML), Naive Bayes (generative, classic ML), a BERT classifier (discriminative, DL), and an LLM (generative, DL) are all valid combinations; the two axes describe orthogonal properties (what is learned vs. how it's learned/architecture).

30. Interview Questions — Senior/Architect

Q1. You need to detect toxic content in real time at high volume. Would you use an LLM (generative) or a discriminative classifier, and why?
A. A discriminative classifier (e.g., a fine-tuned small encoder or classic ML model) — far lower latency and cost at high volume, more consistent/auditable decisions, and the task is a bounded classification problem. An LLM might be reserved for ambiguous edge cases escalated from the classifier, keeping the expensive generative path as a fallback, not the default.
Q2. How would you architect a hybrid system that uses a generative model's embeddings to improve a discriminative classifier, without incurring generative inference cost per request?
A. Precompute embeddings from the generative/foundation model offline (or cache them per unique input), then train and serve a lightweight discriminative head (e.g., logistic regression) on those embeddings at inference time — paying the expensive generative cost once (or rarely), not per production request.

31. Scenario-Based Questions

Scenario 1. Your team replaced a fast fraud classifier with an LLM prompt "is this transaction fraudulent?" and latency/cost exploded. What do you recommend?
A. Revert to a discriminative classifier for the core real-time decision; reserve the LLM (if needed at all) for generating human-readable explanations of flagged cases after the fast classifier has already made the call.
Scenario 2. Product wants a feature that both classifies support ticket urgency AND drafts a suggested reply. How do you architect this using the generative/discriminative distinction?
A. Use a discriminative classifier (cheap, fast, consistent) for the urgency label, and a generative LLM call only for drafting the reply text — two different models for two different sub-tasks, each matched to the right category.

32. Quick revision notes

  • Discriminative = draws the line between classes (P(y|x)).
  • Generative = learns the data itself and can sample new examples (P(x)).
  • All modern "GenAI" (LLMs, diffusion) is generative by definition.
  • Discriminative models are usually cheaper/faster for narrow, stable classification.

33. Cheat sheet

Discriminative = draws the line between classes (P(y|x)). Generative = learns the data itself and can sample new examples (P(x)). All modern "GenAI" (LLMs, diffusion) is generative by definition.
