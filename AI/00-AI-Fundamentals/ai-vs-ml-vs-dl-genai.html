1. What is this?

Artificial Intelligence (AI) is the umbrella field: building systems that perform tasks normally requiring human intelligence. Machine Learning (ML) is a subset of AI: systems that improve at a task by learning patterns from data instead of explicit rules. Deep Learning (DL) is a subset of ML using multi-layer neural networks that learn hierarchical representations directly from raw data. Generative AI (GenAI) is a subset of DL: models that produce new content (text, images, audio, code, video) rather than just classifying or scoring.

2. Why does it exist?

This hierarchy reflects the actual historical/technical evolution: early AI (1950s–80s) was rule-based/symbolic ("expert systems"), which proved brittle for messy real-world data. ML emerged to let systems learn statistical patterns from examples instead. DL emerged once compute/data allowed deep neural networks to outperform hand-engineered features. GenAI emerged once DL models (especially Transformers) got large enough to model full data distributions well enough to generate convincing new samples. Each layer exists to solve limitations of the layer above it being too rigid to scale.

3. Why is it important?

As a software engineer you'll constantly face "do we need an LLM for this, or is this a classifier?" Knowing the hierarchy stops you from over-engineering: a fraud flag might just need classic ML (cheap, fast, interpretable); a chatbot genuinely needs GenAI. Picking the wrong layer is the most common source of bloated, slow, expensive AI systems in production — and a classic interview differentiator between junior and senior engineers.

4. Where is it used?

  • AI (broad): any "smart" feature — rule engines, search ranking, recommendation, chatbots.
  • ML: fraud detection, credit scoring, demand forecasting, spam filtering.
  • DL: image recognition, speech recognition, embeddings, translation.
  • GenAI: chatbots, coding assistants, content generation, image/video synthesis, agentic systems.

5. Prerequisites

No formal prerequisites — this is the entry point of the whole knowledge base. Basic familiarity with "a model learns from data" is helpful before continuing to AI Lifecycle.

6. Core concepts

  • Each layer is a strict subset of the one above it (all GenAI is DL, all DL is ML, all ML is AI) — but not every AI system uses ML, not every ML model is DL, and not every DL model is generative.
  • Representation learning: DL's key innovation is learning useful features automatically instead of hand-crafting them.
  • Generative objective: GenAI models are trained/used to produce samples, not just scores/labels.

8. Architecture (how they nest)

AI (broadest)
 └── Machine Learning
      └── Deep Learning
           └── Generative AI
                └── LLMs, Diffusion Models, Multimodal GenAI

A production AI product typically spans multiple layers at once: a RAG chatbot combines classic ML (reranking), DL (embedding models), and GenAI (the LLM), glued together by ordinary software engineering.

9. How it works internally

At each layer, "working" means something different: classic ML fits parameters of a relatively simple function (e.g., a linear combination of features) by minimizing a loss via optimization like gradient descent. DL stacks many such transformations (layers) so the network itself discovers useful intermediate features. GenAI (e.g., an LLM) applies the DL machinery to a specific objective — predicting the next token/pixel/sample — at a scale where sampling from the learned distribution produces convincing novel content.

10. Step-by-step: classifying a real system

  1. Ask: does it learn from data, or is behavior hand-coded? If hand-coded → AI but not ML.
  2. If it learns: does it use a multi-layer neural network? If no (e.g., linear regression, decision tree) → ML but not DL.
  3. If yes, neural network: is its job to generate new content, or to score/classify/predict? If score/classify → DL but not GenAI.
  4. If it generates new, coherent content conditioned on input → GenAI.

11. Simple example

Spam filter using logistic regression on word-frequency features = ML, not DL, not GenAI.

12. Real-world example

Modern code autocomplete (GitHub Copilot, Claude Code) = GenAI (LLM-based). A credit-card fraud real-time flag = classic ML (gradient-boosted trees), chosen deliberately over GenAI for latency, cost, and auditability.

13. Code example

# Classic ML — no deep learning needed
from sklearn.linear_model import LogisticRegression
from sklearn.feature_extraction.text import TfidfVectorizer

X_train = ["win a free prize now", "meeting moved to 3pm"]
y_train = [1, 0]  # 1 = spam

vec = TfidfVectorizer()
X = vec.fit_transform(X_train)
clf = LogisticRegression().fit(X, y_train)
print(clf.predict(vec.transform(["free prize winner"])))  # [1]

# GenAI — generating new content via an LLM
from anthropic import Anthropic

client = Anthropic()
resp = client.messages.create(
    model="claude-sonnet-5",
    max_tokens=100,
    messages=[{"role": "user", "content": "Write a one-line spam-filter rule in plain English."}]
)
print(resp.content[0].text)

15. Common mistakes

  • Calling every ML model "AI-powered" in marketing — technically true but misleading about sophistication.
  • Reaching for an LLM when a regex or simple classifier would be cheaper, faster, more deterministic.
  • Assuming GenAI output is "retrieved facts" rather than probabilistic generation.
  • Confusing "narrow AI" (all current systems) with AGI in business conversations, leading to unrealistic expectations.

16. Best practices

  • Default to the cheapest layer of the stack that meets the requirement.
  • Reserve GenAI for tasks genuinely requiring language understanding/generation or open-ended reasoning.
  • Benchmark a classic ML baseline before assuming you need DL/GenAI for a new problem.

17. Production considerations

Cost and latency scale roughly with where you sit in this stack: classic ML inference is microseconds and nearly free; DL inference needs GPUs but is cheap at scale; GenAI inference is the most expensive and highest-latency per call. Architect multi-layer pipelines so expensive GenAI calls are the exception, not the default path.

18. Security considerations

Each layer carries different risks: ML models can be subject to adversarial examples/data poisoning; GenAI models additionally face prompt injection and hallucination-driven decisions. Classify your system correctly so you apply the right threat model (see 38-AI-Security).

19. Performance considerations

Classic ML: sub-millisecond inference, trivial to scale horizontally. DL: needs batched GPU inference for throughput. GenAI: autoregressive generation is inherently sequential and the slowest per-request — design UX (streaming) and architecture (caching, routing) around this reality.

20. Cost considerations

A classic ML call might cost a fraction of a cent in compute; an LLM call can cost orders of magnitude more per request. Multiply by request volume before committing to GenAI for a high-volume, simple task.

21. Debugging/troubleshooting

  • "Our AI feature is too slow/expensive": first check whether it's using GenAI where classic ML/DL would suffice.
  • "Results are inconsistent": check whether you're using a generative model where a deterministic discriminative model is actually what's needed.

27. Interview Questions — Beginner

Q1. Is every ML model a neural network?
A. No — ML includes linear/logistic regression, decision trees, SVMs, k-means, etc. Deep learning specifically means multi-layer neural networks.
Q2. What subset relationship exists between AI, ML, DL, and GenAI?
A. GenAI ⊂ DL ⊂ ML ⊂ AI — each is a strict subset of the one before it.
Q3. Give one example of AI that is not ML.
A. A rule-based expert system or a hand-coded chess-move search algorithm.
Q4. What makes deep learning "deep"?
A. It uses neural networks with many stacked layers that learn hierarchical features automatically.
Q5. Is a spam filter using logistic regression considered GenAI?
A. No — it's classic ML; it classifies, it doesn't generate new content.
Q6. What's the key difference between DL and GenAI?
A. DL is the architecture/technique (neural networks); GenAI is a category of DL models specifically trained to generate new content.
Q7. Is AGI the same as the AI we use today?
A. No — today's systems are all "narrow AI," good at specific tasks. AGI (general, human-level intelligence) hasn't been achieved.
Q8. Name one GenAI example.
A. An LLM like Claude, or an image diffusion model like Stable Diffusion.
Q9. Why might a company use classic ML instead of an LLM for fraud detection?
A. Classic ML is faster, cheaper, and more interpretable/auditable for a stable, structured, real-time classification task.
Q10. Can a discriminative model be deep learning?
A. Yes — e.g., a BERT-based classifier is DL but discriminative, not generative.

28. Interview Questions — Intermediate

Q1. Why is representation learning considered DL's key innovation over classic ML?
A. Classic ML requires hand-engineered features; DL's layered architecture learns useful features automatically from raw data, scaling better to complex, unstructured inputs like images and text.
Q2. Can you have an AI system with no ML component at all? Give an example.
A. Yes — a rules engine routing support tickets by keyword matching is AI (automates a task) but contains no learned model.
Q3. Why do production AI products often span multiple layers of this hierarchy simultaneously?
A. Different sub-tasks have different requirements (speed, interpretability, generative need); using the cheapest adequate layer per sub-task (e.g., classic ML for scoring, GenAI only for final text generation) optimizes cost/latency/quality holistically.
Q4. What's a concrete risk of defaulting to GenAI for every "smart feature" request from product?
A. Unnecessary latency and cost at scale, non-deterministic/hard-to-audit behavior for tasks that need consistency, and over-engineering a simple classification problem.
Q5. How would you explain to a non-technical stakeholder why "AI" doesn't mean "it understands like a human"?
A. Explain that all current systems are narrow AI — they're trained to perform specific statistical pattern-matching tasks extremely well, without general reasoning or true understanding; AGI (general intelligence) doesn't exist yet.
Q6. Why is "AI-powered" in marketing often technically true but misleading?
A. Because even a simple rule engine or basic ML model technically qualifies as "AI," the label doesn't convey sophistication — a logistic regression model and a frontier LLM are both "AI-powered" despite vastly different capability.
Q7. What's the difference between a DL model used for classification and one used for generation, architecturally?
A. Often similar backbone architectures (e.g., transformers), but the output head/objective differs: classification outputs a fixed label distribution; generation outputs a distribution over the next token/pixel/sample to be sampled iteratively.
Q8. How would you benchmark whether a problem truly needs DL versus classic ML?
A. Train a strong classic ML baseline first (e.g., gradient boosting on engineered features); only move to DL if the baseline's accuracy/ceiling is insufficient and the extra complexity's cost (data, compute, interpretability loss) is justified by the gain.
Q9. Why might embeddings (DL) be used even in a "classic ML" pipeline?
A. Embeddings convert unstructured data (text/images) into dense vectors that classic ML models (e.g., logistic regression, k-NN) can then operate on — combining DL's representation learning with ML's simpler decision layer.
Q10. What's a scenario where using GenAI for classification (vs. a discriminative model) might still make sense?
A. Zero-shot/few-shot settings with no labeled training data and frequently changing categories, where retraining a classifier per change is impractical — an LLM's generalization ability outweighs the cost/latency disadvantage.
Q11. How do you decide if a feature belongs in "AI" at all versus plain deterministic software?
A. If the behavior can be fully specified by explicit business rules without needing to generalize from examples or handle ambiguity, it's just software — reserve "AI" labeling and complexity for genuinely pattern-learning or generative needs.
Q12. What's an example of a DL model that is neither primarily discriminative nor generative in the usual sense?
A. An embedding model (e.g., a sentence-embedding encoder) — its job is representation, not classification or generation; it's used as an input to downstream ML/retrieval systems.
Q13. Why does interpretability tend to decrease as you move down this hierarchy (AI→GenAI)?
A. Simpler models (linear regression, decision trees) have directly inspectable parameters/logic; deep networks and especially large generative models are high-dimensional, non-linear, and effectively black boxes, making their decisions much harder to explain.
Q14. What role does data volume play in choosing between ML and DL?
A. DL models generally need much more data to outperform classic ML, since they have far more parameters to fit; with small datasets, classic ML often generalizes better and overfits less.
Q15. How would you position a "hybrid" architecture combining ML, DL, and GenAI to a hiring panel as a system design answer?
A. Describe a pipeline where DL embeddings feed a classic ML reranker/classifier for deterministic decisions, and GenAI is invoked only for the final natural-language generation step — demonstrating layer-appropriate design rather than "LLM for everything."

29. Interview Questions — Advanced

Q1. Why is "GenAI ⊂ DL" not strictly true for all historical generative models (e.g., Naive Bayes, GMMs)?
A. Classic statistical generative models predate deep learning and aren't neural-network-based; the strict nesting (GenAI ⊂ DL ⊂ ML ⊂ AI) specifically describes modern GenAI (LLMs, diffusion models), not the full historical category of "generative models" in statistics, which also includes non-DL techniques.
Q2. How would you architect a system where the "AI layer" used for a given request is decided dynamically rather than fixed at design time?
A. Implement a router that profiles request complexity/characteristics, dispatches to the cheapest layer expected to succeed (classic ML/rules first), and escalates to DL/GenAI only on low-confidence or explicitly complex cases, logging escalation rates to continuously tune thresholds.
Q3. What's the risk of letting "it's technically AI" justify skipping proper ML evaluation rigor (train/val/test splits, drift monitoring)?
A. Treating a system as "just AI/magic" rather than a measurable statistical system leads to unvalidated deployments, undetected drift, and silent accuracy degradation — every layer of this hierarchy still requires standard ML lifecycle discipline (see AI Lifecycle).
Q4. How does the cost-performance curve differ qualitatively between scaling a classic ML system and scaling a GenAI system to more requests?
A. Classic ML inference cost is near-constant and tiny per request, scaling nearly linearly with trivial marginal cost; GenAI inference cost per request is orders of magnitude higher and scales with token count, making volume-based cost control (caching, routing, batching) a first-class architectural concern that's largely irrelevant for classic ML.
Q5. Why might a senior engineer push back on "let's just fine-tune an LLM" as the default upgrade path from a classic ML baseline?
A. Fine-tuning introduces a training pipeline, versioning, evaluation overhead, and inference cost increase that may not be justified if the classic ML baseline already meets accuracy/latency/cost requirements — the upgrade should be driven by a measured capability gap, not by assuming "more AI layer = better."

30. Interview Questions — Senior/Architect

Q1. A product manager insists every new feature should "use AI" for marketing reasons, regardless of fit. How do you handle this as the technical lead?
A. Reframe the conversation around measurable outcomes (accuracy, cost, latency, risk) rather than the AI label itself; propose the cheapest adequate layer honestly described as "AI-powered" where true, and present data on cost/risk if GenAI is pushed for a task better served by classic ML.
Q2. How would you design an internal "AI layer selection" guideline/runbook for engineering teams at your company?
A. Document a decision tree: structured data + stable labels → classic ML; unstructured data needing automatic feature learning (images/audio/text embeddings) → DL; open-ended generation/language tasks/zero-shot needs → GenAI; include cost/latency benchmarks per layer and require a baseline-first evaluation policy before adopting a heavier layer.
Q3. How do you audit an existing system to determine if it's using an inappropriately heavy AI layer for its task?
A. Profile actual task requirements (latency SLA, required determinism, data structure), benchmark a lighter-layer baseline against production traffic/logs, and compare cost and quality — if the baseline meets requirements at a fraction of the cost, recommend migration with a rollout plan.

31. Scenario-Based Questions

Scenario 1. Your team built an LLM-based classifier for a fixed 5-category ticket taxonomy and it's slow and expensive at scale. What do you recommend?
A. Replace with a fine-tuned small classifier or even classic ML (embeddings + logistic regression) since the taxonomy is fixed and stable — reserve the LLM for genuinely open-ended sub-tasks, if any.
Scenario 2. A new feature needs to summarize arbitrary free-text customer feedback into categories that change monthly. Which layer fits best and why?
A. GenAI — the open-ended, frequently-changing taxonomy makes retraining a classic ML model impractical each month; an LLM with a well-crafted prompt generalizes without retraining.
Scenario 3. Leadership asks if your chatbot is "getting smarter" the more customers use it. How do you correct this misconception using the AI/ML/DL/GenAI framing?
A. Clarify that the deployed model's weights are frozen (inference only) — it doesn't learn from production usage unless you explicitly run a retraining/fine-tuning cycle on collected data, which is a separate, deliberate process.

32. Quick revision notes

  • AI = umbrella · ML = learns from data · DL = neural nets, many layers · GenAI = DL that creates new content.
  • Nesting: GenAI ⊂ DL ⊂ ML ⊂ AI (for modern systems).
  • Pick the smallest/cheapest layer that solves the problem.
  • Production systems often combine layers; don't default to GenAI for everything.

33. Cheat sheet

AI = umbrella · ML = learns from data · DL = neural nets, many layers · GenAI = DL that creates new content. Pick the smallest layer of this stack that solves your problem.
