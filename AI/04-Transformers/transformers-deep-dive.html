1. What is this?

The Transformer is the neural network architecture underlying virtually all modern LLMs. It processes sequences using self-attention (letting every token look at every other token) instead of recurrence, combined with feed-forward networks, positional encoding, layer normalization, and residual connections, stacked into many layers (encoder, decoder, or decoder-only).

2. Why does it exist?

Introduced to solve RNNs' two biggest problems: sequential processing preventing training parallelization, and difficulty modeling long-range dependencies. Self-attention lets any token directly relate to any other token in one step and lets the entire sequence be processed in parallel during training.

3. Why is it important?

Understanding tokenization, attention, and KV caching explains concrete LLM behaviors you interact with daily: why context windows exist, why output generation is slower than input processing, why "attention dilution" degrades long-context quality, and why serving infrastructure (vLLM, etc.) optimizes specifically around KV cache and batching.

4. Where is it used?

Every modern LLM (GPT, Claude, Gemini, Llama), most modern embedding models, vision transformers (ViT), and increasingly multimodal models combining text/image/audio via the same attention mechanism.

5. Prerequisites

Deep Learning Fundamentals (especially attention basics).

6. Core concepts

  • Tokenization: splitting text into sub-word units the model processes.
  • Embeddings: mapping tokens to dense vectors capturing learned meaning.
  • Positional encoding: injecting order/position information, since attention itself is order-agnostic.
  • Self-attention / Multi-head attention: computing weighted relevance between all token pairs, across multiple parallel "heads" capturing different relationship types.
  • Query, Key, Value (Q, K, V): learned projections of each token used to compute attention scores and weighted outputs.
  • Feed-forward network: a per-token MLP applied after attention in each block.
  • Layer normalization & residual connections: stabilize training and let gradients flow through very deep stacks.
  • Causal masking: prevents a token from attending to future tokens, enabling autoregressive generation.
  • KV cache: stores computed keys/values so generation doesn't recompute attention over the whole sequence at every step.

8. Architecture

Tokens → Embedding + Positional Encoding
 → [ Transformer Block × N ]:
       Multi-head Self-Attention (causal mask for decoders)
       → Add & LayerNorm (residual connection)
       → Feed-Forward Network
       → Add & LayerNorm (residual connection)
 → Final linear layer → vocabulary probability distribution

9. How it works internally

For each token, the model computes Query, Key, and Value vectors via learned linear projections. Attention scores are Query·Key (scaled by √d_k) between the current token and all previous tokens (for decoders), passed through softmax to get attention weights, which then weight a sum over the Value vectors — producing a context-aware representation of that token informed by relevant previous tokens. Multi-head attention runs several such computations in parallel with different learned projections, letting the model capture different types of relationships (e.g., syntactic vs semantic) simultaneously, then concatenates and projects the results.

10. Step-by-step: a token's journey through the model

  1. Token is converted to an embedding vector; positional encoding is added.
  2. In each transformer block: compute Q, K, V; compute attention scores against all previous tokens (causal mask); weighted-sum the Values using softmax(scores).
  3. Add the attention output to the original input (residual connection); apply layer normalization.
  4. Pass through a feed-forward network (per-token MLP); add residual connection; normalize again.
  5. Repeat through all N blocks.
  6. Final layer projects the last block's output to a probability distribution over the vocabulary.
  7. Sample the next token; append; repeat (reusing cached K/V for all previous tokens).

11. Simple example

In the sentence "The cat sat on the mat because it was tired," attention lets the model correctly connect "it" back to "cat" (not "mat") by learning that "it" should attend strongly to the semantically appropriate antecedent — a relationship RNNs struggle with over longer distances but attention handles directly regardless of distance.

12. Real-world example

Claude and GPT-family models are decoder-only Transformers: no encoder half, just a stack of causal self-attention + feed-forward blocks, trained end-to-end on next-token prediction — the architectural simplicity (one unified stack, one objective) is part of why decoder-only models scaled so effectively.

13. Code example (simplified attention)

import torch
import torch.nn.functional as F

def scaled_dot_product_attention(Q, K, V, causal_mask=None):
    d_k = Q.size(-1)
    scores = Q @ K.transpose(-2, -1) / d_k**0.5
    if causal_mask is not None:
        scores = scores.masked_fill(causal_mask == 0, float('-inf'))
    weights = F.softmax(scores, dim=-1)
    return weights @ V

# Multi-head: run this in parallel across multiple (Q,K,V) projections, then concatenate

14. Advanced example

A minimal illustration of KV caching's benefit during autoregressive generation — without caching, each new token recomputes attention over the full growing sequence; with caching, only the new token's Q/K/V need computing, reusing cached K/V for all prior tokens:

class KVCache:
    def __init__(self):
        self.keys, self.values = [], []

    def append_and_attend(self, new_k, new_v, query):
        self.keys.append(new_k)
        self.values.append(new_v)
        K = torch.cat(self.keys, dim=0)
        V = torch.cat(self.values, dim=0)
        return scaled_dot_product_attention(query, K, V)

15. Common mistakes

  • Assuming attention is inherently order-aware — it isn't; positional encoding is what injects order information.
  • Confusing encoder-only (BERT-style, bidirectional, good for classification/embeddings) with decoder-only (GPT/Claude-style, causal, good for generation).
  • Underestimating how much KV-cache memory grows with context length and batch size in serving infrastructure.

16. Best practices

  • Use encoder-style models for embeddings/classification tasks; decoder-style for generation.
  • When building custom Transformer components, leverage existing, well-tested implementations (Hugging Face Transformers, PyTorch) rather than reimplementing attention from scratch for production use.

17. Production considerations

Serving infrastructure (vLLM, TensorRT-LLM) exists specifically to optimize KV-cache memory management and batching across concurrent requests — understanding this architecture explains why these tools matter for cost/latency at scale (see LLM Inference).

18. Security considerations

Attention patterns can, in principle, be probed/analyzed to extract information about training data or model internals (model inversion research); production systems should not assume internal representations are fully opaque to a sufficiently motivated adversary with API access.

19. Performance considerations

Self-attention's cost grows quadratically with sequence length in its naive form — this directly explains why context window limits exist and why long-context inference is more expensive per token than short-context inference.

20. Cost considerations

Model depth (number of layers) and width (hidden dimension size) both directly drive compute cost per token — larger, deeper models cost more per token processed, which is reflected in provider pricing tiers across model sizes.

21. Debugging/troubleshooting

  • Custom Transformer training diverges: check layer normalization placement and residual connections — missing them is a common cause of unstable deep-network training.
  • Attention visualization looks uniform/unfocused: may indicate undertrained attention heads or a need for more training data/steps.

27. Interview Questions — Beginner

Q1. What is self-attention?
A. A mechanism letting each token compute a weighted relevance to every other token in the sequence, producing a context-aware representation.
Q2. What do Query, Key, and Value represent?
A. Learned projections of each token: Query asks "what am I looking for," Key advertises "what do I offer," Value carries the actual content to be aggregated.
Q3. Why is positional encoding needed?
A. Self-attention itself has no inherent sense of token order; positional encoding injects that information explicitly.
Q4. What is causal masking?
A. Preventing a token from attending to future tokens, so generation only depends on past context — required for autoregressive generation.
Q5. What is a KV cache?
A. Cached keys/values from previously processed tokens, avoiding recomputing attention over the whole sequence at every generation step.
Q6. What's the difference between an encoder and a decoder in the Transformer?
A. An encoder processes input bidirectionally (sees all tokens); a decoder uses causal (masked) attention, generating one token at a time.
Q7. What type of Transformer are modern LLMs like Claude/GPT?
A. Decoder-only Transformers.
Q8. What is multi-head attention?
A. Running several attention computations in parallel with different learned projections, capturing different types of relationships simultaneously.
Q9. What does a residual (skip) connection do?
A. Adds a layer's input directly to its output, helping gradients flow through deep stacks and stabilizing training.
Q10. Why did Transformers replace RNNs for most language tasks?
A. They process sequences in parallel (faster training) and handle long-range dependencies better via direct attention, rather than RNNs' sequential, distance-decaying hidden state.

28. Interview Questions — Intermediate

Q1. Walk through the computation of a single self-attention output for one token.
A. Compute Q for the current token and K, V for all tokens it can attend to; compute attention scores as Q·K (scaled by √d_k); apply softmax to get normalized weights; compute a weighted sum of V vectors using those weights as the final output.
Q2. Why is the attention score scaled by √d_k?
A. Without scaling, dot products grow large in magnitude as dimensionality increases, pushing softmax into regions with extremely small gradients; scaling keeps the scores in a numerically stable range for effective training.
Q3. Why does multi-head attention use multiple heads instead of one larger attention computation?
A. Multiple smaller attention computations (heads) with independently learned projections can specialize in capturing different types of relationships (e.g., syntactic dependency vs. coreference) in parallel, which a single attention computation of the same total parameter budget empirically captures less effectively.
Q4. Why would you choose an encoder-only model like BERT over a decoder-only LLM for a text-classification task?
A. Encoder-only models see the full input bidirectionally in one pass, which is well-suited to tasks needing a holistic understanding of fixed input (classification/embeddings), and they're typically smaller/cheaper to run than large decoder-only LLMs for narrow tasks.
Q5. What's the practical significance of KV cache memory growing with both sequence length and batch size?
A. It directly limits how many concurrent requests (batch size) a serving system can handle at a given context length within fixed GPU memory, which is why serving infrastructure (vLLM, etc.) invests heavily in memory-efficient KV-cache management (e.g., paged attention).
Q6. Why does layer normalization help stabilize training in deep Transformer stacks?
A. It normalizes activations within each layer to a consistent scale/distribution, preventing the internal covariate shift that would otherwise compound across many stacked layers and destabilize gradient-based training.
Q7. How does an encoder-decoder Transformer's decoder differ from a decoder-only LLM's decoder?
A. An encoder-decoder's decoder has an additional cross-attention step attending to the encoder's output (the source sequence), in addition to its own causal self-attention over already-generated tokens; a decoder-only LLM has no separate encoder or cross-attention — it's purely causal self-attention over its own growing sequence.
Q8. Why is "attention is all you need" (the original Transformer paper's title) a meaningful claim architecturally?
A. It demonstrated that a model built purely from attention and feed-forward layers — with no recurrence or convolution — could match or exceed RNN/CNN-based approaches on sequence tasks, while being far more parallelizable to train, fundamentally changing the field's default architecture choice.
Q9. Why would increasing the number of attention heads without increasing total model dimension potentially hurt performance?
A. Each head's dimension (d_k) shrinks as more heads share the same total dimension, reducing the representational capacity per head — there's a trade-off between the number of specialized "views" and the richness each view can capture.
Q10. What's the relationship between model depth (number of layers) and the kinds of patterns a Transformer can learn?
A. Earlier layers tend to capture more local/syntactic patterns, while later layers build increasingly abstract, context-integrated representations — depth lets the model compose simpler patterns into progressively more complex, task-relevant representations, similar to hierarchical feature learning in CNNs.

29. Interview Questions — Advanced

Q1. Explain how rotary positional embeddings (RoPE) differ from the original sinusoidal positional encoding, and why modern LLMs favor RoPE-style approaches.
A. Sinusoidal encoding adds a fixed positional signal to token embeddings before attention; RoPE instead rotates the Query/Key vectors as a function of position directly within the attention computation, which naturally encodes relative position information and empirically generalizes better to sequence lengths beyond those seen during training — a key enabler of modern long-context models.
Q2. Why does "lost in the middle" occur even though every token theoretically has direct attention access to every other token?
A. Direct access doesn't guarantee uniform effective attention weighting — learned attention patterns during training are shaped by the training data's typical structure (e.g., important information often near the start/end of training examples), and positional encoding schemes can introduce subtle biases, resulting in empirically weaker recall for mid-sequence content despite the architecture's theoretical capability.
Q3. How does speculative decoding exploit the Transformer's architecture to speed up inference, and what's the correctness guarantee?
A. A smaller draft model proposes several candidate tokens; the larger target model verifies them in a single parallel forward pass (since verifying is just computing probabilities for a fixed sequence, which parallelizes like a forward pass over input, not like sequential generation); accepted tokens match exactly what the target model would have generated with standard sampling, preserving output distribution correctness while reducing the number of expensive sequential forward passes needed.

30. Interview Questions — Senior/Architect

Q1. How would you explain the trade-offs between encoder-only, decoder-only, and encoder-decoder architectures to a team deciding on a model for a new embedding-based search feature versus a new generative chatbot feature?
A. For search/embeddings, recommend an encoder-only model (bidirectional context, optimized for producing fixed representations, typically smaller/cheaper); for the chatbot, a decoder-only LLM (built for open-ended autoregressive generation); explain encoder-decoder is mainly relevant for seq2seq-style tasks like translation, which is neither of these two use cases.
Q2. Your infra team wants to understand why serving longer-context requests is disproportionately more expensive than the token-count-based pricing alone suggests. How do you explain this using Transformer internals?
A. Explain that attention's quadratic cost with sequence length and the linearly growing KV-cache memory footprint both increase per-request GPU resource consumption (compute and memory) faster than linearly with context length, which is why providers' effective serving costs — and sometimes pricing tiers — reflect super-linear scaling for very long contexts even if the headline $/token rate looks flat.

31. Scenario-Based Questions

Scenario 1. Your team is building embeddings for a semantic search feature and is debating whether to use a decoder-only LLM or a dedicated encoder-only embedding model. What do you recommend?
A. Recommend a dedicated encoder-only embedding model — purpose-built for producing high-quality fixed-size representations bidirectionally, typically smaller, cheaper, and faster than extracting embeddings from a large decoder-only LLM, which wasn't primarily optimized for that task.
Scenario 2. Production latency for long-document summarization requests spikes disproportionately compared to short-document requests, even accounting for token-based pricing. How do you explain this to your team using what you know about Transformer internals?
A. Point to the quadratic attention cost and growing KV-cache memory footprint as sequence length increases — both compute and memory pressure increase faster than linearly with context length, explaining the disproportionate latency/resource impact beyond simple token-count scaling.

32. Quick revision notes

  • Tokenize → embed + positional encode → N× (self-attention → FFN, with residuals+norm) → output projection.
  • Q/K/V: Query asks, Key advertises, Value carries content.
  • Causal masking enables autoregressive generation; KV cache avoids recomputation.
  • Decoder-only = modern LLMs; encoder-only = classification/embeddings; encoder-decoder = seq2seq.

33. Cheat sheet

Self-attention: Q·K → softmax → weighted sum of V. Positional encoding injects order. Causal mask enables generation. KV cache avoids recomputation. Decoder-only = modern LLMs; encoder-only = embeddings/classification; encoder-decoder = seq2seq.
