1. What is this?

This is a complete, from-scratch implementation of a small, modern decoder-only transformer language model ("MiniLLM") trained character-by-character on Shakespeare's text. It is not a simplified toy transformer — it uses the exact four architectural upgrades that separate "GPT-2-style" transformers from the LLMs used in production today:

  • RMSNorm instead of LayerNorm (normalization)
  • RoPE (Rotary Positional Embeddings) instead of absolute/sinusoidal position encoding
  • GQA (Grouped Query Attention) instead of standard Multi-Head Attention
  • SwiGLU instead of a plain ReLU feed-forward network

The walkthrough covers tokenization, batching, each architectural component, assembling them into transformer blocks, the training loop, evaluation, and autoregressive text generation — i.e., the entire life cycle of training your first LLM.

2. Why does it exist?

Understanding an LLM only through its API (prompt in → text out) hides exactly how next-token prediction, attention, and position-awareness are implemented. This class exists to demystify that black box by building a working, trainable language model line-by-line, using a small enough dataset (Shakespeare, 65 unique characters) and model (4 layers, 256 dimensions) that it trains in ~15–20 minutes on a single T4 GPU, while still using real, modern production components rather than outdated simplifications.

3. Why is it important?

Every major open-weight LLM released since ~2023 (LLaMA, Mistral, Gemma, Qwen, Phi) uses this exact combination — RMSNorm, RoPE, GQA, SwiGLU, pre-norm residual blocks. If you understand this walkthrough, you understand the architectural backbone of essentially every modern open LLM, not just a historical/pedagogical version of a transformer. This is heavily tested in ML/AI engineering interviews, especially for roles touching model training, fine-tuning, or inference optimization.

4. Where is it used?

  • Pretraining and fine-tuning of modern open-source LLMs (LLaMA family, Mistral, Gemma, Qwen).
  • Any custom/from-scratch LLM training pipeline (startups training domain-specific small LLMs).
  • Efficient on-device/edge LLMs, where GQA's smaller KV cache and RMSNorm's cheaper compute matter most.
  • Research and educational contexts for understanding transformer internals before touching frameworks like Hugging Face Transformers or nanoGPT/litGPT.

5. Prerequisites

Transformers fundamentals (attention, embeddings, feed-forward networks), basic PyTorch (nn.Module, tensors, autograd), the standard 6-step training loop (forward → zero_grad → backward → clip → step), and basic linear algebra (dot products, matrix multiplication, rotation matrices).

6. Core concepts

RMSNormLayerNormNormalizes by root-mean-square only (no mean-subtraction, no learned bias) — fewer ops, fewer params, same effectiveness.

9. How it works internally

  1. Tokenize: text → list of integer character IDs via a simple lookup dictionary.
  2. Batch: randomly sample fixed-length windows from the training text; the target sequence is the input shifted right by one character, so a single sequence of length N yields N training examples (predict the next character at every position simultaneously).
  3. Embed: each token ID is looked up in a learned embedding table, producing a 256-dim vector per token.
  4. Transformer blocks (×4): each block first normalizes with RMSNorm, runs Grouped Query Attention (with RoPE applied inside to inject position information), adds the result back to the input (residual), then normalizes again and runs a SwiGLU feed-forward network, again with a residual add.
  5. Final norm + LM head: one last RMSNorm, then a linear projection back to vocabulary size (65) to produce logits — un-normalized scores for every possible next character.
  6. Loss: cross-entropy between predicted logits and the actual next character, averaged across the whole batch and sequence.
  7. Backprop + update: standard gradient descent (AdamW) adjusts every weight to reduce that loss.
  8. Generation: repeatedly feed the current sequence in, take the logits for only the last position, sample a next character (via temperature + softmax + multinomial sampling), append it, and repeat.

10. Step-by-step explanation

  1. Section 0 — Setup & Data: build a character tokenizer (encode/decode), and a get_batch() function that produces random (x, y) training pairs, where y is x shifted by one character.
  2. Section 1 — RMSNorm: replace LayerNorm with a simpler, cheaper normalization that only divides by root-mean-square and scales by a learned weight vector — plus dropout for regularization.
  3. Section 2 — RoPE: precompute rotation angles per dimension-pair and position, then rotate Query and Key vectors so their dot product encodes relative, not absolute, position.
  4. Section 3 — GQA: project input into 8 Query heads but only 2 Key/Value heads, expand (repeat) the KV heads to match Q head count, apply RoPE to Q and K, compute causally-masked scaled dot-product attention, then merge heads back and project out.
  5. Section 4 — SwiGLU: a gated feed-forward network with two parallel linear paths (gate with SiLU activation, and a raw "up" path) multiplied together before a final down-projection.
  6. Section 5 — Assembly: combine RMSNorm + GQA + RMSNorm + SwiGLU into one TransformerBlock using the pre-norm residual pattern, then stack 4 of these blocks plus an embedding layer and weight-tied output head into the full MiniLLM model.
  7. Section 6 — Training: run the standard 6-step training loop (get batch → forward → zero_grad → backward → clip gradients → optimizer step) for 3000 steps, periodically evaluating train/val loss with dropout disabled.
  8. Section 7 — Generation: implement autoregressive sampling with temperature control, feeding the model's own previous output back in as the next input.

12. Real-world example

LLaMA 2/3, Mistral 7B, and Gemma all use this identical stack: RMSNorm for normalization, RoPE for positions, GQA (or its extreme variant, Multi-Query Attention) to shrink the KV cache for faster inference, and SwiGLU feed-forward blocks. The only real differences from this Shakespeare walkthrough are scale (billions of parameters vs. ~a few million), a subword tokenizer (e.g., BPE/SentencePiece) instead of per-character tokens, many more layers/heads, and training on trillions of tokens of diverse text instead of one Shakespeare corpus.

13. Code example

class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))

    def forward(self, x):
        rms = torch.sqrt(x.pow(2).mean(dim=-1, keepdim=True) + self.eps)
        return (x / rms) * self.weight


class SwiGLU(nn.Module):
    def __init__(self, d_model, hidden_dim):
        super().__init__()
        self.w_gate = nn.Linear(d_model, hidden_dim)
        self.w_up   = nn.Linear(d_model, hidden_dim)
        self.w_down = nn.Linear(hidden_dim, d_model)

    def forward(self, x):
        gate = F.silu(self.w_gate(x))   # gated path
        up = self.w_up(x)               # raw value path
        return self.w_down(gate * up)


class TransformerBlock(nn.Module):
    def __init__(self, d_model, n_heads, n_kv_heads, ffn_hidden_dim):
        super().__init__()
        self.attn_norm = RMSNorm(d_model)
        self.attention = GroupedQueryAttention(d_model, n_heads, n_kv_heads)
        self.ffn_norm = RMSNorm(d_model)
        self.ffn = SwiGLU(d_model, ffn_hidden_dim)

    def forward(self, x, rope_cos, rope_sin):
        x = x + self.attention(self.attn_norm(x), rope_cos, rope_sin)
        x = x + self.ffn(self.ffn_norm(x))
        return x

14. Advanced example

Grouped Query Attention — the piece that actually shrinks the KV cache. 8 Query heads share only 2 Key/Value heads (a 4:1 ratio), and repeat_kv() expands the 2 KV heads back to 8 (memory-efficient, no data copy) before the attention computation:

def repeat_kv(x, n_rep):
    if n_rep == 1:
        return x
    b, n_kv, seq, hd = x.shape
    return (x[:, :, None, :, :]
            .expand(b, n_kv, n_rep, seq, hd)
            .reshape(b, n_kv * n_rep, seq, hd))

def apply_rope(x, cos, sin):
    seq_len = x.shape[2]
    cos = cos[:seq_len].unsqueeze(0).unsqueeze(0)
    sin = sin[:seq_len].unsqueeze(0).unsqueeze(0)
    x1, x2 = x[..., ::2], x[..., 1::2]       # even / odd dims
    out1 = x1 * cos - x2 * sin
    out2 = x1 * sin + x2 * cos
    return torch.stack([out1, out2], dim=-1).flatten(-2)

# forward pass (inside GroupedQueryAttention):
q = self.q_proj(x).view(b, seq, 8, 32).transpose(1, 2)   # [b,8,seq,32]
k = self.k_proj(x).view(b, seq, 2, 32).transpose(1, 2)   # [b,2,seq,32]
v = self.v_proj(x).view(b, seq, 2, 32).transpose(1, 2)   # [b,2,seq,32]

q = apply_rope(q, rope_cos, rope_sin)
k = apply_rope(k, rope_cos, rope_sin)
k = repeat_kv(k, n_rep=4)     # [b,2,seq,32] -> [b,8,seq,32]
v = repeat_kv(v, n_rep=4)

scale = 1.0 / math.sqrt(32)
scores = (q @ k.transpose(-2, -1)) * scale
mask = torch.triu(torch.ones(seq, seq), diagonal=1).bool()
scores = scores.masked_fill(mask, float("-inf"))        # causal mask
weights = F.softmax(scores, dim=-1)
out = weights @ v
out = out.transpose(1, 2).contiguous().view(b, seq, -1)
return self.o_proj(out)

15. Common mistakes

  • Forgetting .contiguous() before .view() after a .transpose() — PyTorch will raise a runtime error because the tensor's memory layout is no longer contiguous.
  • Applying RoPE to the Value vectors as well as Query/Key — RoPE must only be applied to Q and K, never V.
  • Forgetting to call model.eval() (disabling dropout) during evaluation/generation, which produces noisy, non-deterministic loss estimates and generation quality.
  • Mismatching n_heads and n_kv_heads such that n_heads % n_kv_heads != 0, which breaks the repeat_kv expansion.
  • Not scaling attention scores by 1/√head_dim, causing softmax saturation and vanishing gradients.
  • Skipping gradient clipping — transformer training is prone to occasional exploding gradients, especially early in training or with higher learning rates.
  • Not weight-tying the embedding and output head when parameter count matters — it's a free ~17% parameter reduction in this toy model and much more at scale.

16. Best practices

  • Always verify the model is "wired correctly" by checking the initial (untrained) loss roughly equals ln(vocab_size) — here ln(65) ≈ 4.17, matching random guessing.
  • Use pre-norm (normalize before each sub-layer) rather than post-norm — far more stable for deep transformer stacks.
  • Keep RoPE's rotation frequencies precomputed once and reused every forward pass rather than recomputed per call.
  • Always apply the causal mask during training, even though the model sees the whole sequence at once — it's what makes the model autoregressive-valid at inference time.
  • Monitor train vs. validation loss gap during training to catch overfitting early.
  • Use dropout during training but always disable it (model.eval()) for evaluation and generation.

17. Production considerations

At production scale, the same architecture is combined with mixed-precision training (bf16/fp16), distributed data/model parallelism, learning-rate warmup + cosine decay schedules, much larger and more diverse training corpora, and a proper subword tokenizer. GQA specifically exists as a production-driven optimization — it directly reduces the KV cache size that must be stored in GPU memory during serving, which is often the real bottleneck for serving long-context models to many concurrent users.

18. Security considerations

A model trained from scratch on your own data avoids third-party data/model supply-chain risk, but introduces training-data provenance and data-leakage concerns of your own — if any sensitive data is in the training corpus, the model can memorize and regurgitate it (verbatim completions of memorized sequences are a known risk, especially at small dataset sizes / many training epochs). Always audit training data for secrets/PII before training.

19. Performance considerations

  • GQA directly reduces the KV cache from 8 heads worth of K/V to 2 heads worth — a 4× memory/bandwidth reduction here, which speeds up inference significantly, especially for long contexts.
  • RMSNorm is cheaper than LayerNorm (fewer ops — no mean-subtraction, no bias term), a small but real per-layer speedup that compounds across many layers and training steps.
  • Gradient clipping prevents wasted training steps caused by exploding gradients derailing optimization.
  • @torch.no_grad() during evaluation/generation avoids building the autograd graph, significantly reducing memory and compute during inference.

20. Cost considerations

This specific model (4 layers, 256-dim, 3000 training steps) trains in ~15–20 minutes on a single T4 GPU — effectively free on most cloud free tiers or a local GPU. The cost lessons generalize directly to larger training runs: batch size and context length determine GPU memory usage, GQA's smaller KV cache reduces serving cost per request at scale, and weight tying reduces total parameter count (and thus storage/serving cost) for free.

21. Debugging/troubleshooting

  • Loss stuck near ln(vocab_size) and not decreasing: check the learning rate isn't too low, verify gradients are actually flowing (no accidental torch.no_grad() around the training forward pass), and confirm the optimizer is actually stepping on the model's parameters.
  • Loss becomes NaN: almost always exploding gradients — confirm gradient clipping is active and consider lowering the learning rate.
  • Generated text is complete gibberish after training: verify model.eval() is called before generation and that the tokenizer's encode/decode round-trip correctly matches training-time vocabulary.
  • Shape mismatch errors in attention: almost always a GQA head-count mismatch — confirm n_heads % n_kv_heads == 0 and that repeat_kv's n_rep equals n_heads / n_kv_heads.
  • Train loss keeps falling but val loss rises: classic overfitting — reduce model size, increase dropout, or add more/more-diverse training data.

27. Interview Questions — Beginner

Q1. What does RMSNorm do differently from LayerNorm?
A. RMSNorm only divides by the root-mean-square of the input and scales by a learned weight — it skips mean-subtraction and the learned bias/shift that LayerNorm uses, making it cheaper while performing just as well.
Q2. What problem does RoPE solve?
A. It injects positional information into attention by rotating Query and Key vectors by an angle based on position, so the attention dot product naturally reflects the relative distance between tokens rather than their absolute positions.
Q3. What is Grouped Query Attention (GQA)?
A. An attention variant where multiple Query heads share a smaller number of Key/Value heads (e.g., 8 Q heads sharing 2 KV heads), shrinking the KV cache and speeding up inference.
Q4. What does the causal mask do?
A. It prevents a token's attention from looking at future tokens (sets their scores to -inf before softmax), which is required for autoregressive, next-token prediction to be valid.
Q5. Why is the target sequence just the input shifted by one position?
A. Because the training objective is next-character/token prediction — at every position, the model should predict whatever character comes immediately after.
Q6. What does the temperature parameter control during generation?
A. It scales the logits before softmax — lower temperature makes the output more deterministic/conservative, higher temperature makes it more random/creative.
Q7. Why do we call model.eval() before generating text?
A. To disable dropout, so all neurons/values are active — training-time stochastic regularization would otherwise make generation noisier and worse.
Q8. What is weight tying?
A. Sharing the same weight matrix between the token embedding layer and the final output (LM head) projection, reducing total parameter count.
Q9. Why is the initial loss expected to be around ln(vocab_size)?
A. An untrained model effectively guesses randomly among all possible tokens, and the cross-entropy loss of uniform random guessing over V classes is ln(V) — seeing this value confirms the model is wired up correctly before training.
Q10. What does SwiGLU's "gate" path do?
A. It learns, per dimension, how much of the "up" (value) path should pass through, via an element-wise multiplication after a SiLU activation — this lets the network suppress irrelevant dimensions dynamically.

28. Interview Questions — Intermediate

Q1. Why does RoPE only need to be applied to Query and Key vectors, not Value vectors?
A. Position information needs to influence how much attention one token pays to another (which depends on the Q·K dot product), but the Value vectors just carry the content being aggregated — rotating them would scramble the content itself without providing any benefit, since the weighted sum over V doesn't need positional encoding.
Q2. Why does GQA's repeat_kv() use .expand() instead of .repeat()?
A. .expand() creates a view with stride tricks (no actual memory copy) while .repeat() would physically duplicate the underlying data — expand is far more memory-efficient when you just need the broadcasted shape for a matmul.
Q3. Why is pre-norm (normalize before sub-layer) preferred over post-norm (normalize after) in deep transformer stacks?
A. Pre-norm keeps the residual stream (the running sum of x across layers) unnormalized and directly connected end-to-end, giving gradients a clean, un-obstructed path back through the network — this makes very deep stacks (dozens to hundreds of layers) much easier to train without careful learning-rate warmup tuning, which post-norm often requires.
Q4. How does the choice of n_kv_heads trade off quality against inference efficiency?
A. Fewer KV heads mean a smaller KV cache and faster/cheaper inference, but force more Query heads to share the same Key/Value representations, which can reduce representational flexibility; n_kv_heads = n_heads is standard MHA (max quality, max cost), n_kv_heads = 1 is Multi-Query Attention (min cost, more quality risk), and GQA sits as a tunable middle ground.
Q5. Why does gradient clipping matter specifically for transformer training?
A. Transformers, especially early in training or with aggressive learning rates, are prone to occasional large gradient spikes (e.g., from attention score outliers) that can destabilize or diverge training; clipping the gradient norm (e.g., to 1.0) caps the size of any single update step without changing its direction, preventing these spikes from derailing optimization.
Q6. What's the purpose of dividing attention scores by 1/√head_dim?
A. Without scaling, the dot products of Q and K grow in magnitude with head dimension, pushing softmax into a saturated regime where gradients vanish; scaling by 1/√head_dim keeps the scores at a magnitude where softmax remains well-behaved and gradients flow properly.

29. Interview Questions — Advanced

Q1. Explain why RoPE's "low dimensions rotate fast, high dimensions rotate slow" design lets a single mechanism capture both short-range and long-range patterns.
A. Each dimension-pair is assigned a different rotation frequency (1/base^(2i/head_dim)): low-index pairs have high frequency, so their relative angle changes rapidly even for small position gaps, making them sensitive to fine-grained, short-range relationships; high-index pairs have low frequency, changing angle slowly even across large position gaps, so they encode coarser, long-range relationships. The combination across all dimension-pairs gives the model a multi-resolution view of relative position, somewhat like how different frequencies in a Fourier basis capture different scales of structure.
Q2. Why is weight tying (sharing the embedding matrix and LM head) mathematically sensible, not just a parameter-saving trick?
A. The embedding matrix maps token IDs to vectors, and the LM head maps the final hidden state back to a score per token — both matrices are fundamentally relating the same vocabulary to the same vector space. Tying them encourages the model to represent "the direction in embedding space associated with token X" consistently for both reading and writing tokens, which empirically improves perplexity for smaller models, since it halves the number of independent parameters that must be learned to represent that relationship, effectively regularizing it.

30. Interview Questions — Senior/Architect

Q1. You're designing a from-scratch LLM training pipeline that must serve long-context (32K+ tokens) requests cost-effectively at inference time. Walk through which architectural decisions from this walkthrough you'd prioritize and why.
A. GQA (or even more aggressive MQA) becomes critical at long context, since KV cache size scales linearly with both sequence length and number of KV heads — at 32K context, an 8:1 or higher GQA ratio dramatically reduces the memory bandwidth bottleneck that otherwise limits batch size and latency during serving. RoPE is preferred over absolute position embeddings because it generalizes more gracefully to context lengths at or somewhat beyond what was seen in training (with techniques like RoPE scaling/NTK-aware interpolation for further extension). RMSNorm's lower per-layer compute cost compounds meaningfully across the many layers in a production-scale model, both in training throughput and inference latency. I would also ensure gradient clipping and a proper learning-rate warmup/decay schedule are in place, since long-context training is more prone to instability. Overall: every component here is still the right choice at scale — the Shakespeare toy walkthrough isn't a simplified stand-in, it's literally the production recipe at smaller dimensions.

31. Scenario-Based Questions

Scenario 1. Your team's custom-trained model produces fluent but repetitive, low-diversity text even at temperature 1.0. What architectural or training factors would you investigate?
A. First check if this is a sampling issue (consider top-k/top-p/nucleus sampling in addition to temperature, since pure temperature scaling with multinomial sampling can still concentrate probability mass on a few tokens if the underlying distribution is already peaked) rather than an architectural one. If diversity issues persist, investigate whether the model is overfit (compare train vs. val loss — an overfit model memorizes high-frequency patterns from training data, producing repetitive completions), whether dropout was sufficiently applied during training, and whether the training corpus itself lacks diversity.
Scenario 2. After training, your model's loss plateaus well above ln(vocab_size)'s reasonable target and never meaningfully drops below it. What would you check first?
A. First verify the model is actually learning anything beyond random guessing by checking loss at step 0 ≈ ln(vocab_size) as a sanity check — if it's already near that value and never moves, suspect gradients aren't flowing (check for accidentally frozen parameters, a learning rate that's effectively zero, or an optimizer not actually attached to the model's parameters) rather than an architecture issue.
Scenario 3. You need to cut inference serving costs for your trained model by 50% without retraining from scratch. Which of RMSNorm/RoPE/GQA/SwiGLU gives you the most leverage, and how?
A. GQA gives the most direct leverage on serving cost, since it's specifically about reducing the KV cache footprint — if the model wasn't already trained with an aggressive KV-head ratio, options include: quantizing the KV cache itself, reducing max served context length, or (more involved) a conversion/fine-tuning procedure to convert an existing MHA-trained checkpoint into a GQA-equivalent one by averaging/grouping existing KV head weights, then briefly fine-tuning to recover quality — a known technique used by some production LLM teams when retrofitting GQA onto an already-trained MHA model.

32. Quick revision notes

  • RMSNorm = cheaper LayerNorm (no mean-subtract, no bias, scale only).
  • RoPE = rotates Q/K by position-dependent angle → captures relative position via dot product.
  • GQA = fewer KV heads shared across more Q heads → smaller KV cache, faster inference.
  • SwiGLU = gated dual-path FFN (SiLU(W_gate·x) * (W_up·x) then down-project).
  • Pre-norm residual blocks: x = x + sublayer(norm(x)) — stable deep training.
  • Weight tying: embedding matrix == LM head matrix, fewer params.
  • Shift-by-1 next-token prediction: one sequence of length N → N training examples.
  • Causal mask: token i can only attend to tokens ≤ i.
  • Initial loss ≈ ln(vocab_size) is the "model is wired correctly" sanity check.
  • Temperature controls generation randomness; same mechanism used in ChatGPT/Claude.

33. Cheat sheet

RMSNorm = RMS-divide + scale (no mean/bias). RoPE = rotate Q/K by angle(position) → relative position in Q·K. GQA = N_q heads share N_kv heads (N_kv < N_q) → KV cache ÷ (N_q/N_kv). SwiGLU = SiLU(gate) × up → down-project. Block = x + Attn(Norm(x)); x + FFN(Norm(x)). Loss@start ≈ ln(vocab_size). Generation = logits[-1]/temp → softmax → multinomial sample → append → repeat.
