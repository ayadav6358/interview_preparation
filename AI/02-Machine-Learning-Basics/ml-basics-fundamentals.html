1. What is this?

Machine Learning covers algorithms that learn patterns from data: supervised learning (learn from labeled examples), unsupervised learning (find structure in unlabeled data), semi-supervised learning (mix of both), and reinforcement learning (learn from reward signals via interaction). Within supervised learning, tasks split into classification (predict a category) and regression (predict a number); unsupervised learning commonly does clustering (group similar items).

2. Why does it exist?

ML exists because many real-world patterns are too complex or numerous to hand-code as rules, but can be inferred statistically from sufficient labeled or unlabeled examples — covered in depth in AI vs ML vs DL vs GenAI.

3. Why is it important?

Even in a 2026 GenAI-dominated world, classic ML remains the right tool for the majority of narrow, structured-data problems (fraud detection, churn prediction, ranking, forecasting) — an AI engineer who only knows LLMs will reach for an expensive, slow, non-deterministic tool where a cheap classic ML model would be objectively better.

4. Where is it used?

Fraud detection, credit scoring, demand forecasting, recommendation ranking, spam filtering, churn prediction, A/B test analysis, anomaly detection, reranking stages in RAG pipelines.

8. Architecture

Raw data → Feature engineering → Train/Val/Test split
 → Model training (supervised: minimize prediction error against labels)
 → Evaluation (precision/recall/F1/ROC-AUC for classification; MSE/MAE for regression)
 → Deployment → Inference on new data

9. How it works internally

Supervised models minimize a loss comparing predictions to true labels (cross-entropy for classification, squared error for regression) via optimization. Unsupervised models like k-means minimize within-cluster variance without any labels, discovering structure purely from feature similarity. Reinforcement learning maximizes expected cumulative reward through trial-and-error interaction, often using algorithms like policy gradients — the same family of techniques underlying RLHF alignment of LLMs.

10. Step-by-step: a typical ML workflow

  1. Define the task (classification/regression/clustering) and success metric.
  2. Collect and clean data; engineer relevant features.
  3. Split into train/validation/test.
  4. Train a baseline model (e.g., logistic regression) before anything complex.
  5. Evaluate with task-appropriate metrics (precision/recall/F1 for imbalanced classification, not just accuracy).
  6. Iterate on features/model choice using validation performance.
  7. Final unbiased evaluation on test set; deploy.

11. Simple example

Predicting whether an email is spam (classification) vs. predicting a house's sale price (regression) — same general ML workflow, different loss functions and evaluation metrics.

12. Real-world example

A credit card company uses a gradient-boosted classifier (precision/recall tuned to minimize both fraud losses and false-positive customer friction) to flag transactions in real time — a textbook supervised classification problem where accuracy alone would be misleading due to severe class imbalance (fraud is rare).

13. Code example

from sklearn.model_selection import train_test_split
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.metrics import precision_score, recall_score, f1_score, roc_auc_score

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, stratify=y)

model = GradientBoostingClassifier().fit(X_train, y_train)
preds = model.predict(X_test)
probs = model.predict_proba(X_test)[:, 1]

print("Precision:", precision_score(y_test, preds))
print("Recall:", recall_score(y_test, preds))
print("F1:", f1_score(y_test, preds))
print("ROC-AUC:", roc_auc_score(y_test, probs))

14. Advanced example

Handling severe class imbalance (e.g., 0.1% fraud rate) by tuning the decision threshold against business cost, instead of using the default 0.5:

from sklearn.metrics import precision_recall_curve
precisions, recalls, thresholds = precision_recall_curve(y_test, probs)

# Pick threshold maximizing F1, or matching a business-defined precision target
import numpy as np
f1_scores = 2 * precisions * recalls / (precisions + recalls + 1e-9)
best_threshold = thresholds[np.argmax(f1_scores)]
final_preds = (probs >= best_threshold).astype(int)

15. Common mistakes

  • Using accuracy as the metric for an imbalanced classification problem (a model predicting "not fraud" always can be 99.9% accurate and useless).
  • Not stratifying train/test splits for imbalanced classes, causing unstable evaluation.
  • Skipping a simple baseline model and jumping straight to complex approaches.
  • Leaking future information into features (e.g., using a value only known after the prediction target already happened).

16. Best practices

  • Always establish a simple baseline before adding complexity.
  • Choose metrics matching the business problem (precision/recall trade-off, not just accuracy).
  • Stratify splits for classification with imbalanced classes.
  • Validate that features don't leak information unavailable at prediction time.

17. Production considerations

Classic ML models are typically cheap and fast to serve (sub-millisecond), making them ideal for high-throughput, latency-sensitive decisions — monitor for drift since even simple models degrade as real-world distributions shift.

18. Security considerations

ML models can be vulnerable to adversarial examples (inputs crafted to fool the model) and data poisoning (corrupting training data) — validate data provenance and consider adversarial robustness testing for security-critical classifiers (e.g., fraud detection).

19. Performance considerations

Classic ML inference is typically microseconds per prediction and trivially parallelizable, making it suitable for real-time, high-volume decision paths that GenAI inference cannot match.

20. Cost considerations

Training cost scales with data size and model complexity but is typically far cheaper than deep learning/GenAI training; inference cost per prediction is negligible at scale compared to LLM API calls.

21. Debugging/troubleshooting

  • High training accuracy, low test accuracy: overfitting — add regularization, simplify the model, or get more data.
  • Both train and test accuracy low: underfitting — increase model capacity or improve features.
  • Good offline metrics, poor production results: check for train/serve feature skew or data drift.

27. Interview Questions — Beginner

Q1. What's the difference between classification and regression?
A. Classification predicts a discrete category/label; regression predicts a continuous numeric value.
Q2. What's the difference between supervised and unsupervised learning?
A. Supervised learning uses labeled data to learn a mapping to known outputs; unsupervised learning finds structure/patterns in unlabeled data.
Q3. What is precision?
A. Of all items predicted positive, the fraction that are actually positive.
Q4. What is recall?
A. Of all actually positive items, the fraction correctly predicted positive.
Q5. What is the F1 score?
A. The harmonic mean of precision and recall, balancing both into a single metric.
Q6. Why is accuracy a poor metric for imbalanced datasets?
A. A model that always predicts the majority class can achieve very high accuracy while being useless at detecting the minority class of interest.
Q7. What is clustering?
A. An unsupervised technique for grouping similar data points together without predefined labels.
Q8. What's the difference between bias and variance?
A. Bias is error from overly simplistic assumptions (underfitting); variance is error from sensitivity to training data noise (overfitting).
Q9. What is feature engineering?
A. Transforming raw data into informative input variables that help a model learn the task better.
Q10. What does reinforcement learning learn from?
A. Reward signals obtained by interacting with an environment, rather than from fixed labeled examples.

28. Interview Questions — Intermediate

Q1. Why would you choose ROC-AUC over accuracy when comparing classifiers?
A. ROC-AUC measures a model's ability to rank positives above negatives across all thresholds, remaining meaningful under class imbalance, whereas accuracy can be misleadingly high by always predicting the majority class.
Q2. How would you handle a severely imbalanced classification problem (e.g., 0.1% positive rate)?
A. Use metrics beyond accuracy (precision/recall/F1/ROC-AUC/PR-AUC), consider resampling techniques (oversampling minority, undersampling majority) or class weighting, and tune the decision threshold against the actual business cost of false positives vs false negatives rather than using a default 0.5 cutoff.
Q3. What is data leakage and how might it inflate offline evaluation results?
A. When information not actually available at prediction time (e.g., a future outcome, or a feature derived using test-set statistics) leaks into training features, the model appears to perform well offline but fails in production where that leaked information isn't available.
Q4. Why might semi-supervised learning be attractive in a real enterprise setting?
A. Labeling data is often expensive/slow while unlabeled data is abundant; semi-supervised techniques let you leverage the larger unlabeled pool to improve a model trained on a smaller labeled set.
Q5. How does reinforcement learning relate to how LLMs are aligned (RLHF)?
A. RLHF uses reinforcement-learning-style optimization (or related preference-optimization techniques) where the "reward" comes from human (or AI) preference judgments on model outputs, nudging the model's policy (its token-generation behavior) toward preferred responses.
Q6. Why might a simple logistic regression baseline sometimes outperform a more complex model in production?
A. Simpler models are less prone to overfitting with limited/noisy data, are easier to debug and monitor for drift, and complex models' theoretical capacity advantage doesn't always translate to better generalization on the actual production distribution.
Q7. What's the difference between PR-AUC and ROC-AUC, and when would you prefer PR-AUC?
A. ROC-AUC considers true/false positive rates relative to all negatives; PR-AUC focuses on precision and recall, which is more informative when the positive class is rare, since ROC-AUC can look deceptively good even with poor precision under heavy imbalance.
Q8. How would you detect that a deployed classifier's features are suffering from train/serve skew?
A. Compare the distributions of each feature computed in the live serving pipeline against the distributions seen during training/offline evaluation; systematic differences indicate the feature is computed differently in the two paths.
Q9. Why is stratified splitting important for imbalanced classification datasets?
A. A random (non-stratified) split can produce a test set with very few or zero minority-class examples, making evaluation metrics unstable or meaningless; stratification preserves the class ratio across train/val/test splits.
Q10. What's an example of unsupervised learning being used to improve a supervised pipeline?
A. Using clustering or embedding-based unsupervised representation learning to engineer features (e.g., a customer's cluster assignment) that are then fed into a supervised model as additional predictive signal.

29. Interview Questions — Advanced

Q1. How would you choose a decision threshold for a fraud classifier given asymmetric costs of false positives (customer friction) vs false negatives (fraud loss)?
A. Define an explicit cost function (e.g., $X per false positive, $Y per false negative) using the model's predicted probabilities, and select the threshold minimizing expected total cost on a validation set — not the default 0.5 or even F1-optimal threshold, which ignores the actual asymmetric business costs.
Q2. Why might a model with excellent validation metrics still fail when the real-world class balance shifts significantly after deployment (e.g., fraud rate changes from 0.1% to 1%)?
A. Precision at a fixed threshold is sensitive to the base rate (prior probability) of the positive class — a shift in base rate changes the actual precision/recall trade-off at any fixed threshold even if the model's underlying discriminative ability (e.g., ROC-AUC) is unchanged, requiring threshold recalibration, not necessarily retraining.

30. Interview Questions — Senior/Architect

Q1. Design a production fraud-detection system end to end, covering model choice, evaluation, and monitoring.
A. Use a gradient-boosted or similar classic ML model for real-time scoring (low latency, interpretable feature importances for audit); evaluate with precision/recall/PR-AUC tuned against an explicit cost function; deploy with a champion-challenger promotion gate; monitor live feature distributions and prediction rate for drift; maintain a human review queue for borderline-score cases; retrain on a defined cadence incorporating confirmed fraud/non-fraud outcomes as new labels.

31. Scenario-Based Questions

Scenario 1. Your classifier reports 99.5% accuracy on a fraud dataset, but the fraud team says it's useless in practice. What's likely wrong and how do you fix it?
A. Likely severe class imbalance making accuracy meaningless (predicting "no fraud" always could already hit ~99.5%); re-evaluate using precision/recall/PR-AUC and tune the decision threshold against actual business costs instead of optimizing/reporting accuracy.
Scenario 2. A model's offline test accuracy was 92% but production accuracy is only 78%. How do you investigate?
A. Check for train/serve feature skew (features computed differently in production vs. the offline training pipeline) and data drift (has the real-world input distribution shifted since the training data was collected) — both are more likely culprits than the model itself being flawed.

32. Quick revision notes

  • Supervised = labeled data; Unsupervised = no labels; RL = reward-driven.
  • Classification = category; Regression = number; Clustering = grouping.
  • Accuracy is misleading under class imbalance — use precision/recall/F1/ROC-AUC.
  • Always start with a simple baseline.

33. Cheat sheet

Supervised (labels) vs unsupervised (no labels) vs RL (rewards). Classification vs regression vs clustering. Never use accuracy alone on imbalanced data — use precision/recall/F1/ROC-AUC, and tune thresholds against actual business cost.
