Phase 7 · Recursion & Backtracking

Recursion & Backtracking

Recursion — function khud ko chhoti problem par call karta hai. Backtracking — recursion jisme hum choice explore karke, dead-end pe use undo kar dete hain. Ye dono milkar Trees, Graphs, DP, aur combinatorial problems ki foundation hain.

Concept — Recursion

1. What is it?

Recursion matlab ek function khud ko call karta hai, ek chhoti version of the same problem solve karne ke liye — jab tak ek itni chhoti problem na aa jaye jiska answer directly pata ho (base case).

2. Why do we need it?

Kai problems naturally "smaller version of themselves" mein todi ja sakti hain — jaise Trees, Backtracking, Divide & Conquer. Recursion se code chhota aur samajhne mein aasaan ban jata hai un cases mein.

3. Real-Life Analogy

📝 Russian Nesting Dolls (Matryoshka)
Har doll ke andar ek chhoti doll hai. Tum tab tak kholte jaate ho jab tak sabse chhoti, solid doll (base case) na mil jaye — jisme aur kuch kholne ko nahi hai. Phir tum wapas bahar aate ho, doll ko band karte hue.

4. Base Case, Recursive Case, Call Stack

  • Base Case — wo simplest condition jaha function bina khud ko call kiye directly answer return kar deta hai. Iske bina recursion kabhi rukega nahi.
  • Recursive Case — jaha function khud ko ek chhoti/simpler input ke saath call karta hai.
  • Call Stack — computer memory ka wo hissa jo track karta hai kaunse function calls "pending" hain. Har recursive call ek nayi "frame" stack par daalta hai.
  • Stack Overflow — agar recursion kabhi rukta nahi (missing/galat base case), call stack full ho jata hai aur program crash ho jata hai.

5. Visual Diagram — Call Stack for factorial(4)

6. Code Examples

Factorial
function factorial(n) {
  if (n === 0) return 1;          // base case
  return n * factorial(n - 1);    // recursive case
}
Fibonacci
function fib(n) {
  if (n <= 1) return n;                 // base case
  return fib(n - 1) + fib(n - 2);       // recursive case
}
⚠️ Naive Fibonacci is O(2ⁿ)!
Har call 2 further calls banata hai, aur bahut sare subproblems baar-baar solve hote hain (overlapping subproblems). Isse fix karne ka tarika — Memoization — Dynamic Programming phase mein cover karte hain.
Reverse an Array using Recursion
function reverseArray(arr, left = 0, right = arr.length - 1) {
  if (left >= right) return arr;               // base case
  [arr[left], arr[right]] = [arr[right], arr[left]];
  return reverseArray(arr, left + 1, right - 1); // recursive case
}
Power Calculation (Fast Exponentiation)
// Brute: O(n) — multiply n times
function powerBrute(base, exp) {
  if (exp === 0) return 1;
  return base * powerBrute(base, exp - 1);
}

// Optimal: O(log n) — halve the exponent each time
function powerOptimal(base, exp) {
  if (exp === 0) return 1;
  const half = powerOptimal(base, Math.floor(exp / 2));
  if (exp % 2 === 0) return half * half;
  return half * half * base;
}

Why faster: Instead of multiplying n times, hum base^(exp/2) ek baar calculate karte hain aur usse square kar dete hain — jaise Binary Search, har step exponent ko aadha kar deta hai → O(log n).

7. Dry Run — factorial(3)

📝 Step by step
factorial(3) needs factorial(2) → needs factorial(1) → needs factorial(0) = 1 (base case)
factorial(1) = 1 * 1 = 1 (returns to factorial(2))
factorial(2) = 2 * 1 = 2 (returns to factorial(3))
factorial(3) = 3 * 2 = 6

8. Complexity

Factorial: Time O(n), Space O(n) (call stack depth). Fibonacci (naive): Time O(2ⁿ), Space O(n) (max stack depth, even though there are exponentially many calls, only n are "in progress" at once).

How to THINK Recursively

💡 The 3-Step Framework
  1. Trust the recursion. Assume function(n-1) already correctly solves the smaller problem — don't trace through it mentally.
  2. Figure out what to do with that trusted smaller answer to build the answer for n.
  3. Define the base case — the smallest input where you know the answer without recursing.
Beginners often try to "trace the whole tree in their head" — instead, trust that the recursive call works, and just focus on combining its result.

Concept — Backtracking

1. What is it?

Backtracking ek recursive technique hai jisme hum ek choice karte hain, use explore karte hain, aur agar wo dead-end nikle to use undo karke koi doosri choice try karte hain.

2. Choose → Explore → Undo

function backtrack(path, choices) {
  if (isComplete(path)) {
    record(path);
    return;
  }
  for (choice of choices) {
    path.push(choice);       // CHOOSE
    backtrack(path, ...);    // EXPLORE
    path.pop();               // UNDO (backtrack!)
  }
}

3. Real-Life Analogy

📝 Maze Solving
Ek maze mein tum ek raasta choose karte ho, aage badhte ho. Agar dead-end mile, tum wapas (backtrack) aakar doosra raasta try karte ho. Jitna aage gaye the utna "undo" karke.

Example: Generate All Subsets

function subsets(arr) {
  const result = [];
  function backtrack(start, path) {
    result.push([...path]); // every path is a valid subset
    for (let i = start; i < arr.length; i++) {
      path.push(arr[i]);        // CHOOSE
      backtrack(i + 1, path);   // EXPLORE
      path.pop();                // UNDO
    }
  }
  backtrack(0, []);
  return result;
}

Example: Generate All Permutations

function permute(arr) {
  const result = [];
  const used = new Array(arr.length).fill(false);
  function backtrack(path) {
    if (path.length === arr.length) {
      result.push([...path]);
      return;
    }
    for (let i = 0; i < arr.length; i++) {
      if (used[i]) continue;
      used[i] = true;      path.push(arr[i]);   // CHOOSE
      backtrack(path);                            // EXPLORE
      used[i] = false;     path.pop();            // UNDO
    }
  }
  backtrack([]);
  return result;
}

Example: N-Queens (the classic backtracking problem)

Problem: N queens ko N×N board par is tarah rakho ki koi bhi do queens ek doosre ko attack na karein (same row, column, ya diagonal nahi).

function solveNQueens(n) {
  const results = [];
  const cols = new Set(), diag1 = new Set(), diag2 = new Set();
  const board = [];

  function backtrack(row) {
    if (row === n) {
      results.push([...board]);
      return;
    }
    for (let col = 0; col < n; col++) {
      if (cols.has(col) || diag1.has(row - col) || diag2.has(row + col)) {
        continue; // this column is under attack, skip
      }
      // CHOOSE
      cols.add(col); diag1.add(row - col); diag2.add(row + col);
      board.push(col);

      backtrack(row + 1); // EXPLORE

      // UNDO
      cols.delete(col); diag1.delete(row - col); diag2.delete(row + col);
      board.pop();
    }
  }
  backtrack(0);
  return results;
}

Line-by-line: Har row ke liye, har column try karte hain. Agar wo column ya diagonal already kisi queen se attacked hai, skip. Warna queen rakho, agli row explore karo. Jab N rows fill ho jaye, ek valid solution mil gaya. Undo karna zaroori hai taaki agli column try ho sake.

Recursion Tree for Subsets of [1,2]

                  []
              /        \
           choose 1    skip 1
            /              \
          [1]               []
        /    \             /   \
   choose 2  skip 2   choose 2  skip 2
      /         \        /        \
   [1,2]        [1]     [2]        []

4 leaves = 2² subsets: [1,2], [1], [2], []

Common Mistakes

  • Undo step bhool jaana — agar path.pop() ya used[i]=false nahi kiya, purani choices "stuck" reh jaati hain aur galat results aate hain.
  • Base case (missing ya galat) → infinite recursion → stack overflow.
  • result.push(path) likhna instead of result.push([...path]) — reference push karoge to baad mein path change hone par result bhi change ho jayega!

When to Use — Checklist

🎯 Ask yourself
  • Problem "sab possible combinations/arrangements find karo" jaisa dikhta hai?
  • Kya tum choices ko step-by-step build karte ho, aur invalid path detect hone par "undo" kar sakte ho?
  • Kya brute-force exponential (2ⁿ ya n!) solutions expected hain, with maybe some pruning?
Agar haan — Backtracking.

Interview Tips

Backtracking problems mein hamesha bolo: "Main har position par sabhi valid choices try karunga, aur agar koi choice dead-end de, use undo karke next try karunga." Complexity generally exponential hoti hai (O(2ⁿ) ya O(n!)) — ye bolna zaroori hai taaki interviewer ko pata chale tumhe pata hai ye brute-force-with-pruning hai, na ki koi polynomial solution.

Interview Questions

Easy Easy

Q1. Factorial of a NumberEasy

Compute n! recursively.

Example: n = 5 → Output: 120

Hint: Base case n===0 returns 1; else n * factorial(n-1).
Q2. Sum of Digits (recursive)Easy

Given a non-negative integer, return the sum of its digits recursively.

Example: n = 1234 → Output: 10

Hint: Base case n < 10 returns n; else n%10 + sumOfDigits(floor(n/10)).
Q3. Reverse a String RecursivelyEasy

Reverse a string using recursion (no loops).

Example: "hello" → Output: "olleh"

Hint: Base case empty string returns empty; else reverse(str.slice(1)) + str[0].
Q4. Check if a String is a Palindrome (recursive)Easy

Check palindrome using recursion.

Example: "racecar" → Output: true

Hint: Base case left >= right returns true; else check str[left]===str[right] and recurse inward.
Q5. Print All Subsequences of a StringEasy

Print/return all subsequences of a given string.

Example: "ab" → Output: ["", "a", "b", "ab"]

Hint: Classic include/exclude recursion — at each character, branch into "take it" and "skip it".

Medium Medium

Q6. Subsets (Power Set)Medium

Return all possible subsets of a set of unique integers.

Example: [1,2] → Output: [[],[1],[1,2],[2]]

Hint: Backtrack with a start index, adding the current path at every recursive call.
Q7. PermutationsMedium

Return all permutations of a list of distinct integers.

Example: [1,2,3] → Output: 6 permutations

Hint: Backtrack with a "used" boolean array to avoid reusing an element in the same permutation.
Q8. Combination SumMedium

Given candidates and a target, find all combinations that sum to target (elements can repeat).

Example: candidates = [2,3,6,7], target = 7 → Output: [[7],[2,2,3]]

Hint: Allow reusing the same element by not advancing the start index; prune when running sum exceeds target.
Q9. Generate ParenthesesMedium

Generate all combinations of n pairs of well-formed parentheses.

Example: n = 3 → Output: ["((()))","(()())","(())()","()(())","()()()"]

Hint: Backtrack tracking open and close counts; only add "(" if open < n, only add ")" if close < open.
Q10. Letter Combinations of a Phone NumberMedium

Given digits 2-9, return all letter combinations the number could represent (like a phone keypad).

Example: "23" → Output: ["ad","ae","af","bd","be","bf","cd","ce","cf"]

Hint: Backtrack digit by digit, appending each possible letter for the current digit to the path.

Hard Hard

Q11. N-QueensHard

Place N queens on an N×N board so that no two queens attack each other. Return all solutions.

Example: n = 4 → Output: 2 solutions

Hint: Track attacked columns and both diagonals using sets for O(1) conflict checks while backtracking row by row.
Q12. Sudoku SolverHard

Fill a 9x9 Sudoku board so every row, column, and 3x3 box contains 1-9 without repetition.

Example: Partially filled board → Output: fully solved board

Hint: Backtrack cell by cell, trying digits 1-9, checking row/col/box validity before placing, undo on dead end.
Q13. Word Search (grid backtracking)Hard

Given a 2D grid of letters and a word, check if the word exists by moving to adjacent cells (no reuse).

Example: grid with "ABCE/SFCS/ADEE", word = "ABCCED" → Output: true

Hint: DFS/backtrack from each matching starting cell, marking visited cells temporarily and exploring 4 directions.
