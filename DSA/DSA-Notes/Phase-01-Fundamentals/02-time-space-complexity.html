Time & Space Complexity Core Topic

Big O notation, growth rates, aur complexity analyze karne ka tarika — Hinglish mein.

← Prev: What is DSA? Next: Arrays Basics →

1. What is it?

Time Complexity batata hai algorithm ko chalane mein kitna "kaam" (operations) lagega jab input size badhta hai. Space Complexity batata hai kitni extra memory lagegi.

Hum inhe seconds ya bytes mein nahi, balki Big O notation mein measure karte hain — kyunki hume ye jaanna hai ki input badhne par algorithm kitna "scale" karta hai, actual machine speed se independent.

2. Why do we need it?

Do alag codes same output de sakte hain, lekin ek 1 second mein chale aur dusra 1 ghanta le. Interviews mein aur real systems mein sirf correct hona kaafi nahi hai — fast bhi hona zaroori hai. Complexity analysis se hum bina code run kiye hi bata sakte hain ki kaunsa approach better hai.

3. Real-Life Analogy

📝 Phonebook Analogy
Agar tumhe ek naam dhundhna hai unsorted 1000 logo ki list mein, tumhe pura list check karna padega (slow). Lekin agar list sorted hai (jaise phonebook), tum beech se start kar sakte ho aur half-half elimination kar sakte ho (Binary Search — bahut fast). Yehi "complexity" ka farak hai.

4. How Does It Work? — Big O Notation

Big O sirf ye batata hai ki worst case mein operations input size (n) ke saath kaise badhte hain. Constants aur chhote terms ignore kiye jate hain — sirf growth rate matter karta hai.

NotationNameExample
O(1)ConstantArray index access arr[5]
O(log n)LogarithmicBinary Search
O(n)LinearSingle loop through array
O(n log n)LinearithmicMerge Sort, Quick Sort
O(n²)QuadraticNested loops (brute force pairs)
O(2ⁿ)ExponentialGenerating all subsets
O(n!)FactorialGenerating all permutations

Best, Average, and Worst Case

  • Best Case — sabse favorable input (jaise element pehli hi jagah mil jaye).
  • Average Case — typical/random input ke liye.
  • Worst Case — sabse unfavorable input (jo hum usually Big O mein report karte hain, kyunki ye guarantee deta hai).
📝 Example: Linear Search for value 7
[7, 2, 3, 4] → Best Case: O(1) (mil gaya pehle hi)
[2, 3, 4, 7] → Worst Case: O(n) (last mein mila)
[2, 3, 4, 5] (7 nahi hai) → Worst Case bhi O(n) (pura array check karna pada)

5. Visual Diagram — Growth Rate Comparison

Operations needed as n grows (approx, for intuition):

n = 10:
O(log n)  ≈ 3
O(n)      ≈ 10
O(n log n)≈ 33
O(n²)     ≈ 100
O(2ⁿ)     ≈ 1,024

n = 20:
O(log n)  ≈ 4
O(n)      ≈ 20
O(n log n)≈ 86
O(n²)     ≈ 400
O(2ⁿ)     ≈ 1,048,576   ← already exploding!

Growth order (slowest to fastest growing):
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)

6. Code Examples with Explanation

O(1) — Constant Time
function getFirst(arr) {
  return arr[0]; // no matter how big arr is, this is ONE operation
}

Chahe array mein 10 elements ho ya 10 crore, arr[0] hamesha same time lega — index se direct access.

O(log n) — Logarithmic Time
function binarySearch(arr, target) {
  let low = 0, high = arr.length - 1;
  while (low <= high) {
    const mid = Math.floor((low + high) / 2);
    if (arr[mid] === target) return mid;
    else if (arr[mid] < target) low = mid + 1;
    else high = mid - 1;
  }
  return -1;
}

Har step par hum search space ko aadha kar dete hain. 1000 elements → 500 → 250 → ... → sirf ~10 steps mein khatam. Isiliye O(log n).

O(n) — Linear Time
function sumArray(arr) {
  let sum = 0;
  for (let i = 0; i < arr.length; i++) {
    sum += arr[i]; // runs n times
  }
  return sum;
}
O(n log n) — Linearithmic Time
function mergeSort(arr) {
  if (arr.length <= 1) return arr;
  const mid = Math.floor(arr.length / 2);
  const left = mergeSort(arr.slice(0, mid));   // splitting: log n levels
  const right = mergeSort(arr.slice(mid));
  return merge(left, right);                   // merging: n work per level
}
function merge(a, b) {
  const res = [];
  let i = 0, j = 0;
  while (i < a.length && j < b.length) {
    res.push(a[i] <= b[j] ? a[i++] : b[j++]);
  }
  return [...res, ...a.slice(i), ...b.slice(j)];
}

Array ko baar-baar aadha karte hain (log n levels), aur har level par pure n elements merge karte hain → n × log n.

O(n²) — Quadratic Time
function hasDuplicateBrute(arr) {
  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      if (arr[i] === arr[j]) return true; // n * n comparisons
    }
  }
  return false;
}
O(2ⁿ) — Exponential Time
function generateSubsets(arr, index = 0, current = []) {
  if (index === arr.length) {
    console.log(current);
    return;
  }
  generateSubsets(arr, index + 1, current);                 // exclude
  generateSubsets(arr, index + 1, [...current, arr[index]]); // include
}

Har element ke liye 2 choices hain (include / exclude), aur n elements hain → 2 × 2 × ... (n times) = 2ⁿ total subsets.

O(n!) — Factorial Time
function permute(arr, current = [], used = []) {
  if (current.length === arr.length) {
    console.log(current);
    return;
  }
  for (let i = 0; i < arr.length; i++) {
    if (used[i]) continue;
    used[i] = true;
    permute(arr, [...current, arr[i]], used);
    used[i] = false; // backtrack
  }
}

Pehli position ke liye n choices, dusri ke liye n-1, teesri ke liye n-2 ... = n × (n-1) × (n-2) × ... × 1 = n!

How to Calculate Complexity — Quick Rules

💡 Rules of Thumb
  • Single loop over n elements → O(n)
  • Nested loop (both over n) → O(n²)
  • Loop that halves each time → O(log n)
  • Two separate loops (not nested) → O(n) + O(n) = O(2n) → simplify to O(n) (drop constants)
  • Recursion that splits into 2 + does O(n) work (like merge sort) → O(n log n)
  • Recursion that branches into 2 without reducing much (like naive Fibonacci) → O(2ⁿ)
  • Drop constants and lower-order terms: O(2n + 100) → O(n). O(n² + n) → O(n²).

7. Space Complexity — Explained

Space complexity mein hum count karte hain extra memory jo algorithm apne input ke alawa use karta hai:

  • Extra arrays/objects banaye gaye
  • Recursion ka call stack (har recursive call thoda stack memory leti hai — ye bhi count hota hai!)
📝 Recursion Space Example
factorial(5) function 5 baar khud ko call karega before returning — matlab call stack mein ek waqt par 5 frames honge → O(n) space, chahe koi extra array na bhi banayi ho.

8. When Should I Use Which? — Checklist

🎯 Interviewer's Expectation
  • Hamesha apna approach batane ke baad, uski Time & Space Complexity boldo — bina poochhe bhi.
  • Agar tumhara solution O(n²) hai aur constraints n = 10^5 hai, turant bolo "ye TLE (Time Limit Exceeded) dega, mujhe optimize karna hoga."
  • Space-Time tradeoff samjho: HashMap se O(n) time milta hai lekin O(n) extra space lagta hai. Ye tradeoff bolna interview mein achha impression deta hai.

9. Common Mistakes

⚠️ Beginners Often Do This
  • Constants ko bhi count karna: O(2n) ko simplify na karna — ye bas O(n) hi hai.
  • String concatenation ko O(1) samajhna — actually strings immutable hoti hain (JS mein), so building a string in a loop can be O(n²) in the worst case for naive approaches.
  • Recursive functions ki space complexity bhool jaana (call stack ko ignore karna).
  • "Average case" aur "worst case" ko confuse karna — interviews mein hamesha worst case poocha jata hai jab tak specify na ho.

10. Interview Tips

🎯 What Interviewers Actually Want
Interviewer sirf ye nahi dekhta ki code kaam kar raha hai. Wo dekhta hai ki tum apne approach ki complexity samajhte ho ya nahi. Har solution ke baad khud se bolo: "Iska time complexity O(...) hai kyunki..." — ye habit banao abhi se.

Interview Questions

Easy Section

Q1. Find the complexity of a single loopEasy
for (let i = 0; i < n; i++) {
  console.log(i);
}
Hint: Loop kitni baar chal raha hai n ke reference mein?
Q2. Nested loop complexityEasy
for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) {
    console.log(i, j);
  }
}
Hint: Har i ke liye poora j loop chal raha hai — total operations socho.
Q3. Two separate (non-nested) loopsEasy
for (let i = 0; i < n; i++) { console.log(i); }
for (let j = 0; j < n; j++) { console.log(j); }
Hint: Ye nested nahi hain, back to back chal rahe hain — Big-O mein constants drop hote hain.
Q4. Space complexity of a copy functionEasy
function copyArray(arr) {
  const newArr = [];
  for (let i = 0; i < arr.length; i++) newArr.push(arr[i]);
  return newArr;
}
Hint: Ek naya array bana rahe ho jitna bada input hai — extra space kitna laga?
Q5. Halving loop complexityEasy
let i = n;
while (i > 1) {
  i = Math.floor(i / 2);
  console.log(i);
}
Hint: Har iteration mein i aadha ho raha hai — jaise binary search.

Medium Section

Q6. Triangular nested loopMedium
for (let i = 0; i < n; i++) {
  for (let j = i; j < n; j++) {
    console.log(i, j);
  }
}
Hint: Andar wala loop har baar chhota ho raha hai — total operations count karke socho (n + (n-1) + (n-2) + ...).
Q7. Recursive Fibonacci complexityMedium
function fib(n) {
  if (n <= 1) return n;
  return fib(n - 1) + fib(n - 2);
}
Hint: Har call 2 further calls banati hai — recursion tree draw karo aur socho time aur space alag alag kaise nikalte hain.
Q8. Hidden complexity in string buildingMedium
let result = "";
for (let i = 0; i < n; i++) {
  result += "a";
}
Hint: Strings JavaScript mein immutable hain — har += ek naya string bana sakta hai. Iska worst-case time socho.
Q9. Amortized complexityMedium

JavaScript array ka push() ko amortized O(1) kyu bola jata hai jabki kabhi kabhi resize bhi hota hai?

Example: Array capacity 4 hai aur 5th element push ho raha hai — resize trigger hota hai.
Hint: Resize rarely hota hai (doubling strategy) — cost ko sab calls mein average karo.
Q10. Compare two algorithms given constraintsMedium

n = 10^6 hai, ek approach O(n²) hai, dusra O(n log n). 1-second time limit mein kaunsa chalega?

Input: n = 10^6, time limit = 1s
Hint: Rough operation counts nikaalo dono approaches ke liye aur compare karo modern CPU speed (~10^8-10^9 ops/sec) se.

Hard Section

Q11. Merge Sort space complexity deep-diveHard

Merge Sort ki space complexity O(n) kyun hoti hai, jab ki wo sirf array ko halves mein split karta hai (jo O(log n) depth hai)?

Input: arr of size n, recursion depth = log n
Hint: Call stack depth O(log n) hai, lekin merge step mein temporary arrays har level par milakar O(n) space lete hain.
Q12. Analyze complexity of a recursive divide-and-conquer with unequal splitsHard

Ek recursion har call mein problem ko n/3 aur 2n/3 mein split karta hai, aur O(n) work karta hai combine karne mein. Overall time complexity kya hogi?

Example: T(n) = T(n/3) + T(2n/3) + O(n)
Hint: Recursion tree draw karo — har level total work O(n) hota hai; depth kitni hai socho (unbalanced but still O(log n)).
Q13. Memoization impact on exponential recursionHard

Naive Fibonacci O(2ⁿ) hai. Agar memoization add kar do (results cache karo), naya time aur space complexity kya hoga?

Input: fib(40) with and without memoization.
Hint: Har unique subproblem (0 to n) sirf ek baar solve hota hai — socho ye time ko O(n) tak kaise le aata hai, but extra space bhi lagta hai cache ke liye.
