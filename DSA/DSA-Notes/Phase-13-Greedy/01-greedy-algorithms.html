Phase 13 · Greedy Algorithms

Greedy Algorithms 🎯

Greedy choice property, activity selection, greedy vs DP — aur interview mein sabse zyada poochhe jaane wale greedy problems.

1. Greedy Algorithms — Concept

1. What is it?

Greedy Algorithm har step par wo choice choose karta hai jo abhi ke liye sabse best lage (locally optimal), is umeed mein ki ye choices milkar overall best (globally optimal) solution denge — bina kabhi apni choice ko wapas dekhe (no backtracking).

2. Why Needed?

Bahut saari optimization problems (jinme "maximum/minimum" chahiye) DP se solve ho sakti hain, lekin DP mein saari possibilities explore karni padti hain — slow. Agar problem mein Greedy Choice Property ho, to ek simple sort + single pass se hi optimal answer mil jata hai — much faster aur code karne mein simpler.

3. Greedy Choice Property

Greedy sirf tab kaam karta hai jab problem mein "Greedy Choice Property" ho — matlab ek locally optimal choice hamesha ek globally optimal solution ka hissa ban sakti hai. Har problem ye property nahi rakhti!

4. Real-Life Analogy

📝 Making Change with Coins
Agar tumhe 67 rupaye dene hain minimum coins mein (available: 50, 10, 5, 1), tum greedily sabse bade coin se start karte ho: 50 (remaining 17), 10 (remaining 7), 5 (remaining 2), 1+1 (remaining 0). Total 5 coins. Is standard currency system mein greedy hamesha optimal deta hai — lekin har coin system mein aisa nahi hota (see mistake below)!

5. When Does Greedy Work?

💡 Two Conditions Needed
  1. Greedy Choice Property — Local best choice leads toward global best.
  2. Optimal Substructure — Problem ka optimal solution, uske subproblems ke optimal solutions se bana ho sakta hai.
Agar in dono mein se koi bhi missing hai, Greedy galat answer de sakta hai — tab Dynamic Programming chahiye hoti hai (jo saari possibilities explore karta hai).

6. Greedy vs DP — Visual

Coin problem with coins [1, 3, 4], target = 6

Greedy approach: pick 4 first (biggest <= 6) → remaining 2 → pick 1,1 → Total: 4+1+1 = 3 coins
Optimal answer:  3 + 3 = 2 coins!  ← Greedy FAILED here!

Ye batata hai: coin denominations jo "canonical" nahi hain (jaise 1,3,4),
unme Greedy kaam nahi karta — DP chahiye hoti hai.
💡 Greedy vs DP — Kaise decide karein?
Greedy tab use karo jab tumhe pakka pata ho (ya prove kar sako) ki local optimal choice kabhi globally galat nahi hoga (e.g. exchange argument se). Agar tum ek counter-example dhundh sakte ho jaha greedy fail hota hai, to DP use karo — jo har possibility explore karke guaranteed optimal deta hai, bas thoda slower.

7. Code Examples

Activity Selection (Maximum Non-Overlapping Intervals)
function maxActivities(activities) {
  // activities: [[start, end], ...]
  activities.sort((a, b) => a[1] - b[1]); // sort by END time - the greedy choice!
  let count = 1;
  let lastEnd = activities[0][1];

  for (let i = 1; i < activities.length; i++) {
    if (activities[i][0] >= lastEnd) { // starts after (or when) last one ended
      count++;
      lastEnd = activities[i][1];
    }
  }
  return count;
}

Why sort by END time (the greedy insight): Jitni jaldi ek activity khatam ho, utni jaldi agli activity ke liye "room" bach jata hai. Isliye hamesha sabse jaldi khatam hone wali valid activity choose karna optimal hota hai — ye ek classic proven Greedy Choice Property hai.

Fractional Knapsack
function fractionalKnapsack(items, capacity) {
  // items: [[value, weight], ...]
  items.sort((a, b) => (b[0] / b[1]) - (a[0] / a[1])); // sort by value/weight ratio, descending
  let totalValue = 0;

  for (const [value, weight] of items) {
    if (capacity >= weight) {
      totalValue += value;      // take the whole item
      capacity -= weight;
    } else {
      totalValue += value * (capacity / weight); // take a FRACTION of it
      break; // knapsack is full
    }
  }
  return totalValue;
}

Why value/weight ratio: Har unit weight ke liye "sabse zyada value dene wala" item pehle lena hamesha optimal hai — kyunki hum items ko todke (fraction mein) le sakte hain, isliye greedy yahan perfectly kaam karta hai (0/1 Knapsack mein aisa nahi hota — wahan DP chahiye).

8. Dry Run — Activity Selection

📝 Activities: [1,3], [2,5], [4,6], [6,7]
Sorted by end: [1,3], [2,5], [4,6], [6,7] (already sorted here)
Pick [1,3]. lastEnd=3, count=1
[2,5]: start=2 < 3 → skip
[4,6]: start=4 ≥ 3 → pick! lastEnd=6, count=2
[6,7]: start=6 ≥ 6 → pick! lastEnd=7, count=3
Answer: 3 activities

9. Time / Space Complexity

Both examples: Time O(n log n) — dominated by the sort. Space: O(1) extra (or O(n) if the sort isn't in-place).

10. How to Identify Greedy Problems? — Checklist

🎯 Checklist
  • Problem asks for "maximum/minimum number of..." with some scheduling/selection flavor
  • Sorting by some criterion (end time, ratio, size) seems to reveal an obvious "always pick this" rule
  • Try to find a counter-example to your greedy rule with a small hand-made input — if you can't break it after a few tries, greedy likely works
  • If greedy clearly fails on some input (like the coin example above), switch to DP

11. Common Mistakes

  • Assuming greedy always works without proving/testing the Greedy Choice Property — it's easy to be wrong (see coin change counter-example above).
  • Sorting by the wrong criterion — e.g. sorting Activity Selection by start time instead of end time gives a wrong answer.
  • Forgetting greedy gives NO way to "undo" a choice — if the property doesn't hold, wrong early choices can't be fixed later.

12. Interview Tips

Jab tum greedy approach propose karo, interviewer ko ek chhota sa "proof sketch" do: "Main claim kar raha hoon ki [X criterion] se sort karke greedily choose karna optimal hai, kyunki [reasoning]." Agar tum counter-example khud test kar chuke ho, wo bhi mention karo — ye dikhata hai tumne approach ko validate kiya hai, sirf guess nahi kiya.

Interview Questions — Greedy

Easy

Q1. Activity Selection / Non-overlapping IntervalsEasy
Pattern: Sort by end time

Given a set of intervals, find the minimum number of intervals to remove so the rest are non-overlapping (equivalently, find the max number you can keep).

Example: intervals=[[1,2],[2,3],[3,4],[1,3]] → remove 1 ([1,3])

Hint: Sort by end time, greedily keep an interval if its start ≥ the last kept interval's end. See maxActivities code above.
Q2. Assign CookiesEasy
Pattern: Sort both arrays, two pointers

Given children's greed factors and cookie sizes, maximize the number of content children (a child is content if their cookie size ≥ their greed factor).

Example: g=[1,2,3], s=[1,1] → 1

Hint: Sort both arrays. Use two pointers — greedily assign the smallest sufficient cookie to each child.
Q3. Lemonade ChangeEasy
Pattern: Greedy cash-register logic

Customers pay with $5, $10, or $20 bills for a $5 lemonade; determine if you can provide correct change to every customer in order.

Example: bills=[5,5,5,10,20] → true

Hint: Track counts of $5 and $10 bills. For a $20 payment, prefer giving one $10+one $5 over three $5s (keeps flexible $5 bills in reserve).
Q4. Best Time to Buy and Sell StockEasy
Pattern: Greedy min-tracking

Given an array of stock prices by day, find the maximum profit from a single buy-sell transaction (buy before sell).

Example: prices=[7,1,5,3,6,4] → 5 (buy at 1, sell at 6)

Hint: Track the minimum price seen so far while scanning; at each day compute profit if sold today, keep the max.
Q5. Minimum Number of Coins (canonical system)Easy
Pattern: Greedy (works for standard currency)

Given a target amount and standard currency denominations, find the minimum number of coins/notes needed.

Example: amount=67, coins=[50,10,5,1] → 5 coins (50+10+5+1+1)

Hint: Repeatedly take the largest denomination ≤ remaining amount. Note: only works for "canonical" coin systems (see the [1,3,4] counter-example above for when it fails).

Medium

Q6. Jump GameMedium
Pattern: Greedy reachability tracking

Given an array where each element is your max jump length from that position, determine if you can reach the last index starting from index 0.

Example: nums=[2,3,1,1,4] → true

Hint: Track the farthest index reachable so far as you scan left to right. If current index ever exceeds farthest reachable, return false.
Q7. Gas StationMedium
Pattern: Greedy with running total reset

Given gas and cost arrays for a circular route, find the starting gas station index from which you can complete the circuit, or -1 if impossible.

Example: gas=[1,2,3,4,5], cost=[3,4,5,1,2] → 3

Hint: Track a running total (gas - cost); if it drops below 0, that station can't be the start — reset and try the next station as the new candidate.
Q8. Partition LabelsMedium
Pattern: Greedy with last-occurrence tracking

Given a string, partition it into as many parts as possible so each letter appears in at most one part; return the sizes of these parts.

Example: s="ababcbacadefegdehijhklij" → [9,7,8]

Hint: Precompute the last occurrence index of each character. Scan and extend the current partition's end to the max last-occurrence of characters seen; close the partition when you reach that end.
Q9. Minimum Number of PlatformsMedium
Pattern: Sort arrivals/departures, sweep

Given arrival and departure times of trains at a station, find the minimum number of platforms needed so no train waits.

Example: arr=[900,940,950,1100,1500,1800], dep=[910,1200,1120,1130,1900,2000] → 3

Hint: Sort arrivals and departures separately. Sweep through with two pointers, incrementing a platform counter on each arrival and decrementing on each departure that happened before it; track the max.
Q10. Job Sequencing with DeadlinesMedium
Pattern: Sort by profit, greedy slot assignment

Given jobs each with a deadline and profit (each job takes 1 unit of time, only one job per time slot), find the maximum profit achievable by scheduling a subset of jobs within their deadlines.

Example: jobs=[(d=2,p=100),(d=1,p=19),(d=2,p=27),(d=1,p=25),(d=3,p=15)] → schedule yielding profit 142

Hint: Sort jobs by profit descending. For each job, greedily place it in the latest available free time slot ≤ its deadline (using a simple array or disjoint-set for slot tracking).

Hard

Q11. Candy DistributionHard
Pattern: Two-pass greedy

Given ratings of children in a line, distribute candies so each child gets at least 1, and any child with a higher rating than a neighbor gets more candies than that neighbor. Find the minimum total candies needed.

Example: ratings=[1,0,2] → 5 (candies: 2,1,2)

Hint: One left-to-right pass giving +1 over left neighbor when rating is higher, then one right-to-left pass doing the same against the right neighbor, taking the max of both passes at each position.
Q12. Merge IntervalsMedium
Pattern: Sort by start, greedily merge

Given a collection of intervals, merge all overlapping intervals and return the resulting non-overlapping intervals.

Example: intervals=[[1,3],[2,6],[8,10],[15,18]] → [[1,6],[8,10],[15,18]]

Hint: Sort intervals by start time. Iterate, merging the current interval into the last result interval if they overlap, otherwise start a new one.
Q13. Fractional KnapsackMedium
Pattern: Sort by value/weight ratio

Given item values, weights, and a knapsack capacity, maximize total value where items can be taken fractionally.

Example: items=[(60,10),(100,20),(120,30)], capacity=50 → 240.0

Hint: See fractionalKnapsack code above — sort by value/weight ratio descending, take whole items greedily, fraction the last one that doesn't fully fit.
Q14. Minimum Number of Arrows to Burst BalloonsHard
Pattern: Sort by end, greedy interval grouping

Given balloons as intervals on the x-axis, find the minimum number of arrows (vertical shots) needed to burst all balloons (an arrow bursts every balloon whose interval it passes through).

Example: points=[[10,16],[2,8],[1,6],[7,12]] → 2

Hint: Sort intervals by end coordinate. Greedily shoot an arrow at the end of the first unburst balloon, and skip all balloons whose start is ≤ that arrow position (already burst).
