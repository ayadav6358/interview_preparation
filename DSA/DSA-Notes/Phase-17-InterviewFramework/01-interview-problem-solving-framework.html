Phase 17 · Interview Preparation

The Interview Problem-Solving Framework 🎯

Ab tak humne kya seekha hai (patterns, data structures, algorithms). Ab dekhte hain interview mein kaise use karna hai — ek repeatable 9-step process jo har naye problem par apply hota hai, chahe wo koi bhi topic ho.

1. What is it?

Ye ek structured, repeatable process hai jo tumhe kisi bhi naye — chahe pehle kabhi na dekha ho — DSA problem ko systematically approach karne mein madad karta hai. Ye sirf "code likhna" nahi, balki poori soch ka process hai jo interviewer ko dikhta hai.

2. Why do we need it?

Interviewer sirf sahi answer nahi dekhta, wo dekhta hai process. Bina framework ke candidates directly code likhna shuru kar dete hain, edge cases miss kar dete hain, ya silent ho jaate hain — jo bad impression deta hai chahe final code sahi ho.

3. Real-Life Analogy

📝 Doctor's Diagnosis Process
Ek acha doctor seedha treatment nahi deta — pehle symptoms poochta hai, tests karta hai, phir diagnosis batata hai, phir treatment plan explain karta hai. Interview bhi waise hi hai — seedha code mat likho, pehle samjho, poochho, phir explain karke likho.

4. How it works — The 9 Steps

💡 The 9 Steps
  1. Understand the problem — Question do baar padho. Input/output types clear karo.
  2. Ask clarifying questions — Edge cases, constraints, assumptions confirm karo.
  3. Understand constraints — Input size (n) dekh kar decide karo kaunsi complexity chahiye.
  4. Think of brute force — Chahe slow ho, pehle koi working approach nikaalo.
  5. Optimize — Poocho "kya repeat ho raha hai?" ya "kaunsa pattern fit baithta hai?"
  6. Explain your approach — Code likhne se pehle apna plan loudly bolo.
  7. Write code — Clean, readable code likho.
  8. Dry run — Apne code ko ek example par haath se chalao.
  9. Analyze complexity — Time aur space dono boldo, bina poochhe.

5. Diagram — The Flow

Understand → Clarify → Constraints → Brute Force
     → Optimize → Explain → Code → Dry Run → Complexity

Each arrow = "don't skip this step, even under time pressure."

Worked Example 1: "Find two numbers that sum to a target" (Two Sum)

📝 Step 1 & 2: Understand + Ask Questions
Interviewer: "Given an array of integers and a target, return indices of two numbers that add up to target."
You ask: "Kya exactly ek solution guaranteed hai? Same element do baar use kar sakte hain? Array sorted hai?" (Interviewer: "Exactly one solution, no reuse, unsorted.")
📝 Step 3: Constraints
"n ≤ 10⁴" bataya gaya. Iska matlab O(n²) (10⁸) bhi chal sakta hai technically, lekin O(n) clearly better hoga aur asaani se achievable hai.
📝 Step 4: Brute Force
"Main har pair check kar sakta hoon nested loops se — O(n²)."
📝 Step 5: Optimize
"Main soch raha hoon — har element ke liye, mujhe bas ye jaanna hai ki 'complement' (target - current) pehle dekha hai ya nahi. Ye ek HashMap se O(1) mein pata chal sakta hai. Isse main poore array ko ek hi pass mein solve kar sakta hoon."
📝 Step 6: Explain Before Coding
"Main ek HashMap banaunga jo value → index store karega. Array traverse karte waqt, har number ke liye check karunga ki uska complement map mein hai ya nahi. Agar hai, wahi answer hai. Nahi to current number ko map mein daal dunga."
Step 7: Code
function twoSumOptimal(nums, target) {
  const seen = new Map(); // value -> index
  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];
    if (seen.has(complement)) {
      return [seen.get(complement), i];
    }
    seen.set(nums[i], i);
  }
  return [];
}
📝 Step 8: Dry Run — [2,7,11,15], target=9
i=0, nums[0]=2, complement=7, not in map → add 2:0
i=1, nums[1]=7, complement=2, 2 is in map! → return [0, 1] ✅
📝 Step 9: Complexity
"Time O(n) — single pass. Space O(n) — HashMap worst case mein saare elements store kar sakta hai."

Worked Example 2: "Longest Substring Without Repeating Characters"

📝 Steps 1-2: Understand + Ask
"Given a string, find the length of the longest substring without repeating characters."
You ask: "Case-sensitive? Empty string allowed? What character set (ASCII only, or Unicode)?" (Interviewer: "Case-sensitive, empty string returns 0, ASCII.")
📝 Step 3: Constraints
"String length up to 10⁵." → O(n²) (10¹⁰) too slow. Need O(n) or O(n log n).
📝 Step 4: Brute Force
"Main har possible substring generate kar sakta hoon aur check kar sakta hoon uniqueness — O(n³) (O(n²) substrings, O(n) to check each). Bahut slow hai."
📝 Step 5: Optimize
"Ye 'contiguous substring' problem hai jisme condition hai (no repeats) — ye Sliding Window ka classic signal hai. Main ek Set maintain karunga current window ke characters ka, aur jab duplicate mile, left se shrink karunga."
Steps 6-7: Explain + Code
function lengthOfLongestSubstring(s) {
  const seen = new Set();
  let left = 0, maxLen = 0;
  for (let right = 0; right < s.length; right++) {
    while (seen.has(s[right])) {
      seen.delete(s[left]);
      left++;
    }
    seen.add(s[right]);
    maxLen = Math.max(maxLen, right - left + 1);
  }
  return maxLen;
}
📝 Steps 8-9: Dry Run + Complexity
Dry run on "abcabcbb" → window expands abc, hits duplicate 'a', shrinks from left, keeps tracking max length = 3.
"Time O(n) because each character is visited at most twice (once by right, once by left). Space O(min(n, charset size))."

How to Handle "I Don't Know This Problem"

🎯 It's OK to not immediately know the answer
  • Say your thinking out loud, even if incomplete: "Ye mujhe [X pattern] jaisa lag raha hai kyunki [reason]."
  • Start with brute force ALWAYS — even a wrong-but-working solution shows you can code and reason.
  • If truly stuck, ask a guiding question: "Kya array sorted hai? Kya wo mujhe help karega?"
  • Never go silent for a long time — narrate your thought process constantly.

6. When to Use This Framework — Checklist

🎯 Apply this framework whenever...
  • You're given a new problem in an interview, contest, or practice session you haven't seen before.
  • You feel the urge to jump straight to coding — that's exactly when you should pause and go through steps 1-6 first.
  • You're stuck — re-reading the constraints (step 3) or re-stating brute force (step 4) often unblocks you.

Common Mistakes in Interviews

  • Directly optimal code likhne ki koshish karna bina brute force discuss kiye — interviewer ko lagta hai tumne pehle se ye question dekha hai, wo dekhna chahte hain tumhara reasoning process.
  • Complexity boliye bina — hamesha khud se bolo, mat wait karo poochhe jaane ka.
  • Edge cases ignore karna — empty input, single element, all same elements, negative numbers.
  • Code likhte waqt silent ho jaana — narrate karte raho.

Interview Tips — Meta Advice

🎯 What separates strong candidates
Interviewer sirf "sahi answer" nahi dekhta — wo dekhta hai kaise tum us answer tak pahunche. Ek candidate jo brute force se optimal tak clearly reason karta hai, aur apni complexity explain karta hai, ek candidate se better perform karta hai jo directly (bina explanation) optimal code likh deta hai — chahe dono ka final code same ho.

Interview Questions — Practice Applying the Framework

In problems ko is 9-step framework se khud solve karo — statement padho, apne aap clarifying questions poochho, brute force socho, phir optimize karo. Hint sirf ye batayega ki kaunse framework step ya topic par focus karna hai.

Easy

Q1. Two SumEasy
Array aur target diya hai — do indices dhundo jinke values sum karke target banate hain.

Example: Input: nums=[2,7,11,15], target=9 → Output: [0,1]

Hint: Focus on Step 5 (Optimize) — think about what data structure gives O(1) lookup for "have I seen the complement?"

Q2. Valid ParenthesesEasy
Ek string of brackets di hai — check karo ki wo valid balanced hai ya nahi.

Example: Input: "()[]{}" → Output: true

Hint: Focus on Step 2 (clarify) — ask which bracket types count, then Step 4 brute force with a Stack.

Q3. Group AnagramsEasy
Strings ka array diya hai — anagrams ko groups mein organize karo.

Example: Input: ["eat","tea","tan","ate","nat","bat"] → Output: [["eat","tea","ate"],["tan","nat"],["bat"]]

Hint: Focus on Step 5 — think what canonical "key" two anagrams share, then group by it with a hashmap.

Q4. Best Time to Buy and Sell Stock (single transaction)Easy
Stock prices ka array diya hai — maximum profit nikalo ek buy aur ek sell se.

Example: Input: [7,1,5,3,6,4] → Output: 5

Hint: Focus on Step 4 vs Step 5 — brute force is O(n²) checking all pairs; optimize by tracking the minimum seen so far in one pass.

Q5. Contains DuplicateEasy
Array mein koi duplicate element hai ya nahi, check karo.

Example: Input: [1,2,3,1] → Output: true

Hint: Focus on Step 3 (constraints) — decide between sorting O(n log n) vs a Set for O(n) based on space trade-offs you'd state out loud.

Medium

Q6. Longest Substring Without Repeating CharactersMedium
String di gayi hai — longest substring ki length nikalo jisme koi character repeat na ho.

Example: Input: "abcabcbb" → Output: 3

Hint: Focus on Step 5 — recognize the sliding window signal from the "contiguous + no repeats" phrasing.

Q7. Merge IntervalsMedium
Intervals ka array diya hai — overlapping intervals ko merge karo.

Example: Input: [[1,3],[2,6],[8,10],[15,18]] → Output: [[1,6],[8,10],[15,18]]

Hint: Focus on Step 4 — a good brute force insight here is "sort by start time first," which almost gives you the optimal approach directly.

Q8. Course Schedule (Can Finish All Courses?)Medium
Courses aur unke prerequisites diye hain — check karo ki saare courses complete kiye ja sakte hain ya nahi.

Example: Input: numCourses=2, prerequisites=[[1,0]] → Output: true

Hint: Focus on Step 1-2 — recognize this as a graph problem in disguise, then ask "can the prerequisite graph have a cycle?"

Q9. Kth Largest Element in an ArrayMedium
Array aur k diya hai — kth largest element nikalo.

Example: Input: [3,2,1,5,6,4], k=2 → Output: 5

Hint: Focus on Step 3 and 5 — compare sorting O(n log n) against a heap-based O(n log k) approach and justify your pick out loud.

Q10. Product of Array Except SelfMedium
Array diya hai — ek output array banao jisme har index par saare elements ka product ho except khud wo index (bina division use kiye).

Example: Input: [1,2,3,4] → Output: [24,12,8,6]

Hint: Focus on Step 4 to Step 5 transition — brute force with division is easy but disallowed; think prefix and suffix products instead.

Hard

Q11. LRU Cache DesignHard
Ek Least Recently Used (LRU) cache design karo jisme get aur put dono O(1) time mein ho.

Example: Input: capacity=2, operations put(1,1), put(2,2), get(1), put(3,3) evicts key 2 → Output: get(2) returns -1

Hint: Focus on Step 2 and 5 — clarify eviction rules first, then combine a HashMap (O(1) lookup) with a Doubly Linked List (O(1) reorder) rather than one structure alone.

Q12. Word Break II (return all sentences)Hard
String aur dictionary diya hai — saare possible ways return karo string ko dictionary words se space-separated segment karne ke.

Example: Input: s="catsanddog", wordDict=["cat","cats","and","sand","dog"] → Output: ["cats and dog","cat sand dog"]

Hint: Focus on Step 4 to Step 5 — brute force backtracking works but is exponential; add memoization on substring start index to prune repeated work.

Q13. Serialize and Deserialize a Binary TreeHard
Ek binary tree ko string mein convert karo aur wapas tree mein reconstruct karo.

Example: Input: tree [1,2,3,null,null,4,5] → Output: serialized string that deserializes back to the same tree

Hint: Focus on Step 2 — clarify what null markers look like in your format, then use a simple traversal order (e.g., preorder with null markers) consistently for both directions.
