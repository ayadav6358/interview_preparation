Phase 8 · Linked List

Linked List

Ek data structure jahan elements memory mein bikhre hote hain, bas ek doosre ko "pointer" ke through jodte hain. Array ke opposite trade-offs — slow random access, but fast insert/delete.

Concept

1. What is it?

Linked List ek data structure hai jisme elements ("nodes") memory mein kahin bhi ho sakte hain (contiguous nahi, array ki tarah) — har node apne data ke saath agle node ka address (pointer) bhi store karta hai.

2. Why do we need it (vs Array)?

Array mein beech mein insert/delete karna O(n) hai (sabko shift karna padta hai). Linked List mein, agar tumhare paas position ka pointer hai, insert/delete sirf O(1) mein ho sakta hai — bas pointers rewire karne hain, kuch shift nahi karna.

3. Real-Life Analogy

📝 Treasure Hunt
Ek treasure hunt mein, har clue tumhe batata hai agla clue kahan hai — clues khud ek order mein "physically" nahi rakhe hote, bas ek doosre ko point karte hain. Waise hi linked list ke nodes memory mein bikhre ho sakte hain, bas ek doosre ko "point" karte hain.

JavaScript — Node & Basic Linked List
class Node {
  constructor(value) {
    this.value = value;
    this.next = null;
  }
}

class LinkedList {
  constructor() {
    this.head = null;
  }

  // Insert at end - O(n) without tail pointer, O(1) with tail pointer
  append(value) {
    const newNode = new Node(value);
    if (!this.head) { this.head = newNode; return; }
    let curr = this.head;
    while (curr.next) curr = curr.next;
    curr.next = newNode;
  }

  // Insert at beginning - O(1)
  prepend(value) {
    const newNode = new Node(value);
    newNode.next = this.head;
    this.head = newNode;
  }

  // Search - O(n)
  find(value) {
    let curr = this.head;
    while (curr) {
      if (curr.value === value) return curr;
      curr = curr.next;
    }
    return null;
  }

  // Delete a value - O(n)
  delete(value) {
    if (!this.head) return;
    if (this.head.value === value) { this.head = this.head.next; return; }
    let curr = this.head;
    while (curr.next && curr.next.value !== value) curr = curr.next;
    if (curr.next) curr.next = curr.next.next; // skip over the node
  }
}

Key Problem 1: Reverse a Linked List

Idea: Har node ke next pointer ki direction palat do — teen pointers use karke: prev, curr, next.

function reverseList(head) {
  let prev = null, curr = head;
  while (curr) {
    const nextTemp = curr.next; // save next before we overwrite it
    curr.next = prev;            // reverse the pointer
    prev = curr;                 // move prev forward
    curr = nextTemp;             // move curr forward
  }
  return prev; // prev is now the new head
}

Time: O(n), Space: O(1) — iterative approach, no extra data structure.

Key Problem 2: Detect a Cycle (Floyd's Algorithm)

Idea: Do pointers use karo — ek "slow" (1 step) aur ek "fast" (2 steps). Agar list mein cycle hai, fast pointer eventually slow ko "lap" kar lega (mil jayenge). Agar cycle nahi hai, fast pointer null tak pahunch jayega.

function hasCycle(head) {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow === fast) return true; // they met - cycle exists
  }
  return false; // fast reached the end - no cycle
}
📝 Analogy: Two Runners on a Circular Track
Agar ek runner doosre se tez daudta hai ek circular track par, wo eventually use "lap" kar lega — matlab mil jayenge. Agar track circular nahi hai (straight line), tez runner bas finish line (null) tak pahunch jayega bina mile.

Time: O(n), Space: O(1) — bahut better than using a HashSet to track visited nodes (which would be O(n) space).

Key Problem 3: Find the Middle of a Linked List

Idea: Same slow/fast pointer trick! Jab fast pointer end tak pahunchta hai, slow exactly beech mein hota hai (kyunki wo aadhi speed se chal raha tha).

function findMiddle(head) {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
  }
  return slow; // middle node
}

Brute force would be: count total length first (one pass), then walk to length/2 (second pass) — O(n) but two passes. Slow/fast pointer does it in a single pass.

Key Problem 4: Merge Two Sorted Linked Lists

function mergeTwoLists(l1, l2) {
  const dummy = new Node(0); // dummy node simplifies edge cases
  let tail = dummy;
  while (l1 && l2) {
    if (l1.value <= l2.value) { tail.next = l1; l1 = l1.next; }
    else { tail.next = l2; l2 = l2.next; }
    tail = tail.next;
  }
  tail.next = l1 || l2; // attach whichever list has leftovers
  return dummy.next;
}
🎯 Dummy Node Trick
Linked list problems mein ek "dummy" (placeholder) node banake shuru karna bahut common trick hai — isse edge cases (jaise "head khud change ho raha hai") handle karna aasan ho jata hai, bina special-case code likhe.

When Should I Use Linked List?

🎯 Checklist
  • Bahut saari insertions/deletions honi hain, especially beech mein ya start mein
  • Random index access ki zaroorat nahi hai
  • Size dynamically change hoti rahegi bina resize cost ke

Common Mistakes

  • Reverse karte waqt next save karna bhool jaana — isse list "toot" jati hai aur aage ka access kho jata hai.
  • Empty list (head === null) ka edge case handle na karna.
  • Slow/fast pointer mein fast.next null check bhool jaana — null.next access karne se crash hoga.

Interview Tips

Linked List problems mein hamesha pehle poochho: "Singly ya doubly? Circular ho sakti hai?" Aur jab bhi "cycle detect karo" ya "middle dhundo" jaisa kuch dikhe, turant Floyd's Slow/Fast pointer technique bolo — ye ek signature pattern hai jo interviewer turant recognize karega.

Interview Questions

Easy Easy

Q1. Reverse a Linked ListEasy

Reverse a singly linked list in-place.

Example: 1→2→3→null → Output: 3→2→1→null

Hint: Use three pointers — prev, curr, next — and flip each node's next pointer as you go.
Q2. Find Middle of Linked ListEasy

Return the middle node of a linked list in one pass.

Example: 1→2→3→4→5 → Output: 3

Hint: Slow and fast pointers — slow moves 1 step, fast moves 2 steps.
Q3. Delete a Node (given only that node, not head)Easy

Delete a given node from a singly linked list, where you don't have access to the head.

Example: list 4→5→1→9, node = 5 → Output: 4→1→9

Hint: Copy the next node's value into the current node, then skip over the next node.
Q4. Convert Array to Linked ListEasy

Build a linked list from an array of values.

Example: [1,2,3] → Output: 1→2→3→null

Hint: Loop through the array appending each value, or build backwards while prepending.
Q5. Palindrome Linked ListEasy

Check whether a singly linked list reads the same forward and backward.

Example: 1→2→2→1 → Output: true

Hint: Find the middle, reverse the second half, then compare both halves node by node.

Medium Medium

Q6. Detect Cycle in a Linked ListMedium

Determine if a linked list has a cycle.

Example: 3→2→0→-4→(back to 2) → Output: true

Hint: Use fast and slow pointers — Floyd's Cycle Detection.
Q7. Merge Two Sorted ListsMedium

Merge two sorted linked lists into one sorted list.

Example: 1→2→4 and 1→3→4 → Output: 1→1→2→3→4→4

Hint: Use a dummy node and a tail pointer, always attaching the smaller of the two current nodes.
Q8. Remove Nth Node From EndMedium

Remove the n-th node from the end of the list in one pass.

Example: 1→2→3→4→5, n=2 → Output: 1→2→3→5

Hint: Move a "fast" pointer n steps ahead first, then move both pointers together until fast reaches the end.
Q9. Reorder ListMedium

Reorder list L0→L1→…→Ln-1→Ln into L0→Ln→L1→Ln-1→…

Example: 1→2→3→4 → Output: 1→4→2→3

Hint: Find the middle, reverse the second half, then merge the two halves alternately.

Hard Hard

Q10. Merge K Sorted ListsHard

Merge k sorted linked lists into one sorted list.

Example: [[1,4,5],[1,3,4],[2,6]] → Output: 1→1→2→3→4→4→5→6

Hint: Merge lists pairwise divide-and-conquer style, or use a min-heap holding the current head of each list.
Q11. Copy List with Random PointerHard

Deep-copy a linked list where each node also has a random pointer to any node (or null).

Example: list with random pointers → Output: fully independent deep copy

Hint: Use a hashmap from original node to cloned node, or interleave cloned nodes into the original list to avoid extra space.
Q12. LRU CacheHard

Design a Least Recently Used cache with O(1) get and put operations.

Example: capacity=2; put(1,1); put(2,2); get(1)→1; put(3,3) evicts key 2

Hint: Combine a doubly linked list (for O(1) reordering/eviction) with a hashmap (for O(1) key lookup).
