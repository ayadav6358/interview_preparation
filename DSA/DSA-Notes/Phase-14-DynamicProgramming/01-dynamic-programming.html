Phase 14 · Dynamic Programming

Dynamic Programming — Zero se Interview Tak 🧠

Recursion ko fast banane ka tareeka — jab same subproblems baar-baar solve ho rahe hon, unhe cache karke exponential time se polynomial time tak le aana.

1. What is it?

Dynamic Programming (DP) ek technique hai jo Recursion ko fast banati hai, un problems ke liye jisme same subproblems baar-baar solve ho rahe hote hain — hum unko ek baar solve karke store (cache) kar lete hain, taaki dobara calculate na karna pade.

2. Why do we need it?

Naive Fibonacci recursion O(2ⁿ) leta hai — kyunki fib(3) jaisi values baar-baar recompute hoti hain. DP isse O(n) mein le aata hai — bas ek chhota sa change: "agar answer pehle se pata hai, dobara mat nikalo."

3. Real-Life Analogy

📝 Homework Answers Notebook
Socho tumhe wahi sawaal baar-baar solve karna pad raha hai. Agar tum apna answer ek notebook mein likh lo pehli baar, agli baar bas notebook dekh lo — dobara poora solve karne ki zaroorat nahi. Yehi Memoization hai.

4. The Journey: Recursion → Memoization → Tabulation

Recursion (Brute Force)
   ↓  "same subproblems repeat — let's cache them"
Memoization (Top-Down DP)
   ↓  "let's build the answer from the bottom instead of recursing"
Tabulation (Bottom-Up DP)

Notice: fib(3) computed TWICE, fib(2) computed THREE times!
As n grows, this repetition explodes → O(2ⁿ)

6. Code — All Three Stages for Fibonacci

Stage 1: Plain Recursion — O(2ⁿ)
function fibRecursive(n) {
  if (n <= 1) return n;
  return fibRecursive(n - 1) + fibRecursive(n - 2);
}
Stage 2: Memoization (Top-Down) — O(n)
function fibMemo(n, memo = {}) {
  if (n <= 1) return n;
  if (n in memo) return memo[n];       // already solved? return cached answer
  memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo); // solve & cache
  return memo[n];
}

Line-by-line: Bilkul same recursion hai, bas ek memo object add kiya hai. Agar n ka answer already memo mein hai, seedha return kar do — koi dobara call nahi. Warna solve karo aur memo mein store kar do future ke liye.

Stage 3: Tabulation (Bottom-Up) — O(n)
function fibTabulation(n) {
  if (n <= 1) return n;
  const dp = new Array(n + 1);
  dp[0] = 0; dp[1] = 1;               // base cases
  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];    // build up from smaller answers
  }
  return dp[n];
}

Difference from Memoization: Yahan koi recursion hi nahi hai — hum chhote se bade (bottom-up) values calculate karte jaate hain ek loop mein. Same O(n) time, but no call-stack overhead.

Bonus: Space-Optimized Tabulation — O(1) space
function fibOptimal(n) {
  if (n <= 1) return n;
  let prev2 = 0, prev1 = 1;
  for (let i = 2; i <= n; i++) {
    const curr = prev1 + prev2;
    prev2 = prev1;
    prev1 = curr;
  }
  return prev1;
}

Kyunki hume sirf pichle 2 values chahiye hoti hain kisi bhi point par, poora array store karne ki zaroorat nahi — bas 2 variables kaafi hain.

7. Dry Run — fibMemo(5)

📝 Step by step (showing cache hits)
fib(5) → needs fib(4) + fib(3)
fib(4) → needs fib(3) + fib(2) → computes and caches fib(3), fib(2), fib(1), fib(0)
Back to fib(5): fib(3) is already in memo! → instant return, no recomputation
Total unique computations: fib(0) through fib(5) = only 6 calls (vs 15 in plain recursion)

Important DP Problem 1: Climbing Stairs

Problem: n stairs hain, tum 1 ya 2 steps ek baar mein chad sakte ho. Kitne distinct ways hain top tak pahunchne ke?

💡 Spotting the Recurrence
Step n tak pahunchne ke ways = (step n-1 se 1 step lekar) + (step n-2 se 2 steps lekar) = ways(n-1) + ways(n-2). Ye bilkul Fibonacci jaisa hi recurrence hai! 
function climbStairs(n) {
  if (n <= 2) return n;
  let prev2 = 1, prev1 = 2;
  for (let i = 3; i <= n; i++) {
    const curr = prev1 + prev2;
    prev2 = prev1;
    prev1 = curr;
  }
  return prev1;
}

Important DP Problem 2: 0/1 Knapsack

Problem: N items hain, har ek ka weight aur value hai. Ek bag hai capacity W ki. Maximum value kya hai jo tum utha sakte ho (har item pura lo ya bilkul mat lo)?

💡 Why NOT Greedy here?
Fractional Knapsack mein greedy (value/weight ratio) kaam karta tha kyunki items todh sakte the. 0/1 Knapsack mein items todh nahi sakte — isliye saari possibilities try karni padti hain — DP chahiye. 
function knapsack(weights, values, capacity) {
  const n = weights.length;
  // dp[i][w] = max value using first i items with capacity w
  const dp = Array.from({ length: n + 1 }, () => new Array(capacity + 1).fill(0));

  for (let i = 1; i <= n; i++) {
    for (let w = 0; w <= capacity; w++) {
      dp[i][w] = dp[i - 1][w]; // option 1: don't take item i-1
      if (weights[i - 1] <= w) {
        dp[i][w] = Math.max(dp[i][w], dp[i - 1][w - weights[i - 1]] + values[i - 1]); // option 2: take it
      }
    }
  }
  return dp[n][capacity];
}

Line-by-line: dp[i][w] stores the best value using the first i items with capacity w. Har item ke liye decide karo: lo ya mat lo — jo bhi bada value de. Ye "include/exclude" pattern backtracking jaisa hi hai, bas ab results cache ho rahe hain.

Important DP Problem 3: Longest Common Subsequence (LCS)

Problem: Do strings di gayi hain — unka longest common subsequence (order same, contiguous nahi) length kya hai?

function longestCommonSubsequence(text1, text2) {
  const m = text1.length, n = text2.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (text1[i - 1] === text2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1] + 1; // characters match, extend the LCS
      } else {
        dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]); // best of skipping either char
      }
    }
  }
  return dp[m][n];
}
📝 Dry Run: text1="ace", text2="abcde"
'a'='a' → match, extend. 'c' and 'e' also match at right positions. Final LCS = "ace", length = 3.

How to Identify DP Problems — Checklist

🎯 Look for these signs
  1. Overlapping Subproblems — a naive recursive solution recomputes the same smaller inputs repeatedly.
  2. Optimal Substructure — the optimal answer for the full problem can be built from optimal answers to subproblems.
  3. Keywords: "maximum/minimum ways", "count the number of ways", "longest/shortest subsequence", "can you reach/partition", "minimum cost to..."
  4. You find yourself writing a brute-force recursion with choices at each step (include/exclude) — strong hint DP applies.
Process: Write the brute-force recursion first → identify repeated subproblems → add memoization → (optionally) convert to tabulation.

Common Mistakes

  • Jumping straight to a DP table without first writing the recursive relation.
  • Off-by-one errors in the DP table dimensions (length vs length+1).
  • Forgetting base cases in the DP table.
  • Using DP where Greedy would suffice, or Greedy where DP was needed — always check the Greedy Choice Property first.

Interview Tips

DP problems mein interviewer sabse zyada ye dekhna chahta hai ki tum recursion se DP tak ka safar dikha sako: "Pehle brute force recursion, phir dikhaunga kaunse subproblems repeat ho rahe hain, phir memoize karunga." Ye process bolna, sirf final table code likhne se zyada valuable hai.

Interview Questions — Dynamic Programming

Easy

Q1. Climbing StairsEasy
n stairs, 1 ya 2 steps ek baar mein. Kitne distinct ways top tak pahunchne ke?

Example: Input: n = 3 → Output: 3 (ways: 1+1+1, 1+2, 2+1)

Hint: Recurrence is exactly Fibonacci — ways(n) = ways(n-1) + ways(n-2).

Q2. House RobberEasy
Array of house values di gayi hai — adjacent houses rob nahi kar sakte. Maximum money?

Example: Input: [1,2,3,1] → Output: 4 (rob house 0 and 2)

Hint: At each house decide skip vs rob — dp[i] = max(dp[i-1], dp[i-2] + arr[i]).

Q3. Min Cost Climbing StairsEasy
Har step par ek cost hai. Minimum cost floor tak pahunchne ka (0 ya 1 index se start, 1 ya 2 step jump).

Example: Input: cost = [10,15,20] → Output: 15

Hint: dp[i] = cost[i] + min(dp[i-1], dp[i-2]).

Q4. Maximum Subarray (Kadane's Algorithm)Easy
Contiguous subarray ka maximum sum nikalo.

Example: Input: [-2,1,-3,4,-1,2,1,-5,4] → Output: 6 (subarray [4,-1,2,1])

Hint: At each position, decide: extend the previous subarray, or start fresh here.

Q5. Fibonacci NumberEasy
Nth Fibonacci number nikalo efficiently.

Example: Input: n = 6 → Output: 8

Hint: Practice all three stages — recursion, memoization, tabulation, and O(1)-space version.

Medium

Q6. Coin Change (Minimum Coins)Medium
Coins ka array aur ek amount di gayi hai. Minimum coins chahiye amount banane ke liye.

Example: Input: coins=[1,2,5], amount=11 → Output: 3 (5+5+1)

Hint: dp[amount] over 1..target; for each coin try dp[amount-coin]+1.

Q7. Longest Increasing SubsequenceMedium
Array mein sabse lambi strictly increasing subsequence ki length nikalo.

Example: Input: [10,9,2,5,3,7,101,18] → Output: 4 ([2,3,7,101])

Hint: dp[i] = length of LIS ending at i = 1 + max(dp[j]) for j<i where arr[j]<arr[i].

Q8. Longest Palindromic Substring (DP version)Medium
String mein sabse lambi palindromic substring dhundo.

Example: Input: "babad" → Output: "bab" (ya "aba")

Hint: dp[i][j] = true if s[i..j] is palindrome, using dp[i+1][j-1] and s[i]==s[j].

Q9. Partition Equal Subset SumMedium
Array ko do subsets mein divide kar sakte ho jinka sum equal ho?

Example: Input: [1,5,11,5] → Output: true ([1,5,5] and [11])

Hint: This is a 0/1 knapsack variant — target = sum/2, check if that subset sum is achievable.

Q10. Unique PathsMedium
m x n grid mein top-left se bottom-right tak (only right/down moves) kitne unique paths hain?

Example: Input: m=3, n=7 → Output: 28

Hint: dp[i][j] = dp[i-1][j] + dp[i][j-1], base case first row/col = 1.

Q11. Longest Common SubsequenceMedium
Do strings ka longest common subsequence ka length nikalo.

Example: Input: text1="abcde", text2="ace" → Output: 3

Hint: 2D dp[i][j] — match extends diagonal, mismatch takes max of left/up.

Hard

Q12. Edit DistanceHard
Do strings ke beech minimum operations (insert/delete/replace) nikalo ek ko dusre mein convert karne ke liye.

Example: Input: word1="horse", word2="ros" → Output: 3

Hint: dp[i][j] = dp[i-1][j-1] if chars match, else 1 + min(insert, delete, replace) options.

Q13. Word BreakHard
String ko dictionary words se break kar sakte ho ya nahi, check karo.

Example: Input: s="leetcode", wordDict=["leet","code"] → Output: true

Hint: dp[i] = true if s[0..i] can be segmented; check every j<i where dp[j] is true and s[j..i] is in dict.

Q14. Best Time to Buy and Sell Stock with CooldownHard
Stock prices ka array di gayi hai. Maximum profit nikalo, lekin sell ke baad ek din cooldown hai (agle din buy nahi kar sakte).

Example: Input: [1,2,3,0,2] → Output: 3

Hint: Maintain three states per day — held, sold (cooldown next), rest — and transition between them.

Q15. 0/1 Knapsack (Full Reconstruction)Hard
Knapsack ke max value ke saath-saath, kaunse items select huye wo bhi batao.

Example: Input: weights=[1,3,4,5], values=[1,4,5,7], W=7 → Output: max value 9, items indices [1,2]

Hint: Build the full dp table, then backtrack from dp[n][W] checking whether dp[i][w] equals dp[i-1][w] (not taken) or not (taken).
