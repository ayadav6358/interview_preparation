1. Time Complexity — "Code kitna time lega?"

Simple meaning: Time Complexity ka matlab actual seconds measure karna nahi hai. Hum dekhte hain ki input size N badhne par operations kitni speed se badhte hain.

Step 1: Iterations count karo

PDF page 2 ka rule:

  1. Input size N ke terms mein iterations find karo.
  2. Constants hatao.
  3. Lower contribution terms hatao.

O(N) — one loop

for (i = 1; i <= N; i++) {
    // work
}

Loop roughly N times chalega → O(N).

Reverse loop bhi O(N)

for (i = N; i >= 1; i--) {
    // work
}

N se 1 tak ja raha hai, total roughly N iterations → O(N).

i ko 2 se multiply karna

for (i = 1; i <= N; i = i * 2) {
    // work
}

Values: 1, 2, 4, 8, 16, 32... Jab tak N. Ye roughly log₂N steps leta hai → O(log N).

Nested loops

for (i = 1; i <= N; i++) {
    for (j = 1; j <= i; j++) {
        // work
    }
}

Iterations: 1 + 2 + 3 + ... + N = N(N+1)/2.

N(N+1)/2 = N²/2 + N/2 → O(N²)

Constant 1/2 aur lower term N/2 ignore karne par O(N²).

4. Space Complexity — "Extra memory kitni chahiye?"

Time = kitna work/time. Space = algorithm ko extra memory kitni chahiye.

Example: one array

int A[N];

for (int i = 0; i < N; i++) {
    // work
}

Array itself N memory leta hai → O(N) space. Loop ka counter sirf constant extra memory hai.

Important: nested loop ≠ automatically O(N²) space

for (int i = 0; i < N; i++) {
    for (int j = 0; j < M; j++) {
        // work
    }
}

Time can be O(N×M), but agar koi N×M size ka extra data store nahi ho raha, extra space O(1) ho sakta hai. PDF page 8 isi distinction ko highlight karta hai.

Shortcut: Har variable ko memory mein count karne ki zarurat nahi. Usually complexity ke liye growing data structures/arrays ko track karo.

5. Range Sum Query — Problem kya hai?

Suppose:

A = [7, 1, 5, -9, 2, 10, 5, 8]
     0  1  2   3  4   5  6  7

Question ho sakta hai: L se R tak ka sum batao.

For L=1, R=3:

A[1] + A[2] + A[3] = 1 + 5 - 9 = -3

Agar sirf ek query hai, simple loop se sum nikal sakte ho.

sum = 0;
for (i = L; i <= R; i++) {
    sum += A[i];
}

One query ka cost range length ke proportional hai. PDF page 11 mein multiple queries ke case mein TLE concern dikhaya gaya hai.

6. Multiple Range Queries — Problem kyun hoti hai?

Maan lo N array elements hain aur Q queries hain.

Har query ke liye L se R tak loop karoge to worst case roughly:

O(Q × N)

Agar N aur Q dono large hain, ye bahut expensive ho sakta hai.

Idea: Same work baar-baar karne ke bajay pehle kuch useful information calculate kar lo, phir har query ko quickly answer karo.

7. Prefix Sum — Main Technique

Prefix sum ka matlab: start se current index tak ka sum store karna.

A = [7, 1, 5, -9, 2, 10, 5, 8]

P = [7, 8, 13, 4, 6, 16, 21, 29]

Formula:

P[i] = A[0] + A[1] + ... + A[i]

Ya recursive form:

P[i] = P[i-1] + A[i]

For example:

  • P[0] = 7
  • P[1] = 7 + 1 = 8
  • P[2] = 8 + 5 = 13
  • P[3] = 13 - 9 = 4

8. Prefix Sum se L..R Sum

Ye sabse important formula hai.

If L = 0 → sum(L,R) = P[R]
If L > 0 → sum(L,R) = P[R] - P[L-1]

Example

A = [7, 1, 5, -9, 2, 10, 5, 8]
P = [7, 8, 13, 4, 6, 16, 21, 29]

Find sum from L=2 to R=6:

P[6] - P[1] = 21 - 8 = 13

Actual values: 5 + (-9) + 2 + 10 + 5 = 13.

Why works? P[R] contains everything from 0..R. P[L-1] contains everything from 0..L-1. Subtract karne par left wala part cancel ho jata hai, aur L..R bach jata hai.

9. Prefix Sum with Many Queries

Approach:

  1. Array read karo → O(N)
  2. Prefix array build karo → O(N)
  3. Har query ko prefix se answer karo → O(1) each

Total roughly:

O(N + Q)

Space agar prefix array store kar rahe ho → O(N).

Big idea: Thoda extra memory/time upfront spend karo, taaki later queries fast ho jayein. Isko preprocessing idea samjho.

A = [7, 1, 5, -9, 2, 10, 5, 8]

11. Subarray kya hota hai?

Subarray = array ke continuous elements ka group.

For:

A = [1, 7, 5, 9]

Examples:

  • [1]
  • [1, 7]
  • [1, 7, 5]
  • [7]
  • [7, 5]
  • [5, 9]
  • [1, 7, 5, 9]

Important: Elements continuous hone chahiye. [1, 5] is array ka subarray nahi hai because 7 ko skip kiya.

12. Number of Subarrays

Array length N hai. Total subarrays:

N(N+1) / 2

Why?

Index 0 se start hone wale subarrays = N.

Index 1 se = N-1.

Index 2 se = N-2.

...

Last index se = 1.

N + (N-1) + ... + 2 + 1 = N(N+1)/2

For N=4:

4×5/2 = 10 subarrays

13. All Subarrays Print Karna

PDF page 24 mein L aur R se subarrays generate karne ka basic idea hai:

for (L = 0; L < N; L++) {
    for (R = L; R < N; R++) {
        // subarray [L, R]
    }
}

Har [L,R] choose karne ke baad uske elements print karne ke liye ek aur loop lag sakta hai.

Isliye agar actual elements bhi print kar rahe ho, total work O(N³) tak ho sakta hai. PDF page 24 mein subarray generation ke code ka TC O(N³) aur SC O(1) shown hai.

14. Sum of All Subarrays — Brute Force

PDF pages 25–26 mein pehla approach hai: har subarray ka sum nikalo aur total answer mein add karo.

ans = 0;

for (L = 0; L < N; L++) {
    for (R = L; R < N; R++) {
        sum = 0;

        for (i = L; i <= R; i++) {
            sum += A[i];
        }

        ans += sum;
    }
}

Isme repeated summation ho rahi hai, so ye inefficient hai. PDF page 26 is brute-force version ko O(N³) time, O(N) space ke context mein show karta hai.

15. Prefix Sum se All Subarray Sums

Same problem ko prefix sum se improve kar sakte ho.

for (L = 0; L < N; L++) {
    for (R = L; R < N; R++) {

        if (L == 0)
            sum = P[R];
        else
            sum = P[R] - P[L-1];

        ans += sum;
    }
}

Ab har subarray ka sum O(1) mein milta hai. L,R ke pairs O(N²) hain.

Time ≈ O(N²)

PDF page 26 isi improvement ko highlight karta hai.

16. Contribution Technique — Smart Way

PDF pages 27–30 ka most important idea: Har subarray ko individually generate karne ki jagah, har element kitni subarrays mein contribute karta hai, ye count karo.

Example

A = [1, 7, 5, 9]
     [0, 1, 2, 3]

Element A[i] ke liye:

  • Uske left mein kitne choices hain? i + 1
  • Uske right mein kitne choices hain? N - i
Contribution of A[i] = A[i] × (i+1) × (N-i)

Why?

Subarray mein A[i] ko include karne ke liye:

  • Start index 0..i mein se koi bhi choose kar sakte ho → i+1 choices.
  • End index i..N-1 mein se koi bhi choose kar sakte ho → N-i choices.

Har left choice × har right choice ek subarray banata hai jisme A[i] included hai.

18. Contribution Technique ka Code

long long ans = 0;

for (int i = 0; i < N; i++) {
    ans += 1LL * (i + 1) * (N - i) * A[i];
}

cout << ans;

PDF page 30 mein isi formula ka O(N) time aur O(1) space approach diya gaya hai.

Big win: Brute force mein bahut saare subarrays process karne pad sakte hain. Contribution approach mein har element ko sirf ek baar process karte hain → O(N).

21. Interview mein kaise sochna hai?

  1. Constraint dekho: N kitna bada hai?
  2. Brute force imagine karo: sab kuch directly karne par kitna time lagega?
  3. Repeated work identify karo: kya same sum baar-baar calculate ho raha hai?
  4. Prefix sum socho: kya range sum repeatedly chahiye?
  5. Contribution socho: kya har element ka contribution independently count ho sakta hai?
  6. Space check karo: extra array banana allowed/needed hai?
